# Source Evaluation Checklist

Accept a source only when it can support a useful user-facing learning plan.

Check:

- User goal: Does it clearly map to interview sprint, long-term learning, topic breakthrough, mistake review, or ability diagnosis?
- Structure: Does it provide ordering, topic/pattern groups, difficulty, phases, or enough metadata to build phases?
- Local matching: Can problems be matched by LeetCode slug or frontend ID?
- Coverage: Does it cover a coherent route instead of a random resource list?
- Personalization: Can duration, weekly hours, level, language, and weak topics reasonably adjust the draft?
- Attribution: Can source name, URL, commit/version, source path, curation notes, and license notice be recorded?
- Safety: Does the planned seed avoid copying solution code, articles, diagrams, or problem statements?
- Limitations: Are premium/missing/unmatched problems auditable without entering generated draft recommendations?

If the source fails structure, matching, or attribution, keep it as a research note instead of generating a committed seed.
