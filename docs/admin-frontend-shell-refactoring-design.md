# 管理员前端工作区重构设计

> 本设计对应当前管理端实现。改造范围仅限 `/admin/*`，普通学习端继续使用现有 `AppShell`、顶部导航和页面交互。
> 管理端采用与学习端一致的中性、克制视觉语言，但为表格、筛选、详情和连续操作提供更高的信息密度。

## 1. 已定决策

1. 管理员只有进入 `/admin/*` 后才使用独立 `AdminShell`；管理员访问 `/`、`/learning-plans` 等学习端路由时仍使用普通 `AppShell`。
2. 管理后台采用“左侧多级导航 + 顶部全局动作 + 页面工作区”结构，不再使用顶部业务菜单或内容区业务页签。
3. 侧栏同时承担业务域、页面和 AI 子视图导航。页面数量多的业务域可展开，只有一个页面的业务域点击后直接跳转。
4. 导航配置按照 `AuthPermission` 过滤。前端隐藏只控制可达性和界面呈现，不能替代后端 `/api/admin/**` 权限校验。
5. 保持现有 URL、查询参数、浏览器前进后退和深链接行为。AI 平台的四个视图继续复用 `/admin/ai`，通过 `tab` 查询参数区分。
6. 不引入新的 UI 框架，不改写管理页面的数据请求语义，不补造缺少后端支持的管理能力。
7. 桌面侧栏由用户手动折叠，不在 `760px - 1199px` 区间强制折叠，避免折叠后多级页面无法到达。
8. 管理页面使用紧凑标题、工具栏、表格、主从视图和对话框，不使用营销式大标题、装饰性卡片或无业务含义的视觉元素。

## 2. 背景与目标

管理功能持续增加后，将管理员概览、用户、准入、会话、AI、反馈、题库和调试工具平铺在学习端顶栏会产生以下问题：

- 顶部空间不足，导航依赖横向滚动；
- 身份、AI、内容、运营和开发工具缺少稳定分组；
- AI 页面内部页签与全局导航形成重复层级；
- 管理页面沿用学习端较宽松的留白，表格和操作区可用空间不足；
- 页面切换时缺少明确的业务域和页面位置提示；
- 页面状态容易进入 Shell，使布局组件和业务组件职责混杂。

本次改造目标：

- 建立可扩展、按权限过滤的多级管理导航；
- 提高表格、筛选、详情和批量操作的首屏信息密度；
- 统一管理页面标题、工具栏、数据区、空状态和分页的视觉边界；
- 保持所有现有业务行为、路由和查询参数不变；
- 在桌面、紧凑桌面和平板上保留完整导航，在移动端使用可访问抽屉；
- 与重构后的学习端共享成熟、克制的中性视觉基调。

非目标：

- 不重构普通用户首页、学习计划、复习中心、学习画像和设置页；
- 不新增后端权限、角色、动态菜单 API 或服务端布局配置；
- 不建设组织树、全局搜索或可关闭的多窗口标签；
- 不强制所有业务页面使用同一种数据呈现形式。

### 3.3 导航行为

- 无可访问页面的业务域不渲染。
- 只有一个可访问页面的业务域点击后直接导航，不显示无意义的展开层级。
- 包含多个页面的业务域点击后展开或收起；当前路由所属业务域在路由变化后自动展开。
- 同一时间保留一个手动展开的业务域，降低长菜单的纵向占用。
- 当前业务域和当前页面均通过 `aria-current="page"` 标记，不能只用颜色表达状态。
- AI 查询参数参与 active 匹配；缺少 `tab` 时默认匹配“用量与成本”，以兼容原 `/admin/ai` 地址。
- 反馈未读数显示在“运营与支持”和“反馈与支持”对应入口，最大显示 `99+`；折叠态使用提示点。

## 4. 整体布局

### 4.1 桌面结构

```text
┌───────────────┬──────────────────────────────────────────────────────┐
│ AM Algo Mentor│ 身份与访问 / 用户管理     返回学习端 主题 语言 账号 │ 56
│ 管理后台      ├──────────────────────────────────────────────────────┤
│               │ 用户管理                    搜索 状态 刷新           │
│ 运营概览      │                                                      │
│ 身份与访问    │ 表格 / 主从视图 / 页面工作区                         │
│   用户管理    │                                                      │
│   用户组管理  │                                                      │
│   ...         │                                                      │
│ AI 平台       │                                                      │
│ 内容管理      │                                                      │
│ 运营与支持    │                                                      │
│ 开发工具      │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
      236px                         minmax(0, 1fr)
```

核心尺寸：

```text
--admin-header-height: 56px
--admin-sidebar-width: 236px
--admin-sidebar-collapsed-width: 68px
```

- `AdminShell` 使用 `100dvh` 和两列网格，页面滚动只发生在 `.admin-workspace`。
- 内容列使用 `minmax(0, 1fr)` 和 `min-width: 0`，避免表格撑破整个文档。
- 管理内容不受学习端 `1200px` 最大宽度限制。
- 桌面折叠后保留业务域图标和未读提示；用户点击业务域时先展开侧栏，再展示子页面。

### 4.2 顶部栏

顶部栏只承载全局动作和位置提示：

- 中部：当前业务域和当前页面，例如“身份与访问 / 用户管理”；
- 右侧：返回学习端、主题切换、语言切换和账户菜单；
- 移动端左侧：打开管理导航和简化品牌；
- 不放业务页签、筛选、反馈列表或 AI 调试连接状态；
- 不增加没有真实能力支撑的全局搜索框。

### 4.3 左侧导航

- 使用中性浅灰背景、轻边框和白色 active 面，深色主题使用独立深色 token。
- 业务域使用 Lucide 图标；子页面使用固定圆点轨道；AI 子分组使用紧凑文字标签。
- 菜单项维持稳定高度和列宽，文本过长时省略，徽标不得改变布局尺寸。
- 展开、收起和 active 使用背景、字重与形状共同表达，不依赖高饱和品牌色。
- 侧栏自身可纵向滚动，不带动顶部栏或页面主体。

### 4.4 页面工作区

- 页面标题使用 `20px` 左右的紧凑层级，面板标题使用 `16px` 左右。
- 工具栏使用“标题与命令 + 搜索与筛选”结构；内容不足时保持单行，空间不足时允许换行。
- 数据表格和详情面板使用一像素边框、`4px - 8px` 圆角和极少阴影。
- 搜索、筛选、刷新和主操作维持稳定尺寸，工具按钮使用 Lucide 图标和可访问名称。
- 状态、空数据和错误信息在对应工作区内呈现，不改变整体导航位置。

## 5. 数据工作区规范

### 5.1 表格页

- 表头保持单行，字号 `12px - 13px`；正文使用 `13px - 14px`。
- 常规行高不低于 `40px`，操作控件维持可点击面积。
- 文字列可省略，但必须保留访问完整值的方式；状态、时间和操作列使用稳定宽度。
- 空状态、加载状态和错误状态占据数据主体，不造成标题和工具栏跳动。
- 宽度不足时仅表格容器横向滚动，文档根节点不得产生横向溢出。

### 5.2 主从工作区

反馈处理等连续工作流使用列表和详情并列结构：

- 列表与详情属于同一个连续工作区，不嵌套装饰性卡片；
- 详情宽度保持稳定，列表使用 `minmax(0, 1fr)`；
- 选中对象继续写入 `threadId`、`userId` 等查询参数；
- 移动端切换为列表和详情两个状态，保留明确返回动作。

### 5.3 抽屉与对话框

- 用户详情继续使用右侧抽屉，创建、编辑和危险操作确认使用对话框；
- 打开后限制焦点并支持 `Escape`，关闭后将焦点归还触发控件；
- 移动端复杂对话框使用全屏布局，紧凑确认框可保留留边；
- 删除、停用、重置密码等高影响动作必须明确目标并二次确认。

## 6. 页面落位

- **运营概览**：使用紧凑指标、状态和待办分区，链接到对应管理页面，不使用展示型仪表盘装饰。
- **身份与访问**：用户、用户组、准入、会话监控和会话策略共享同一业务域；每个页面保留原有数据请求和 URL 状态。
- **AI 平台**：移除页面内部重复页签，由侧栏直接切换 Provider、路由、用量和定价视图；全局止损开关、筛选、编辑对话框和用户跳转语义不变。
- **内容管理**：题库搜索、筛选和操作使用全宽工作区，并补齐标准页面标题。
- **运营与支持**：运行状态和反馈处理归入同一业务域；反馈继续使用未读数、主从视图和 `threadId` 深链接。
- **开发工具**：AI 调试状态留在调试页面，控制台使用剩余视口高度，并补齐标准页面标题。

## 7. 视觉规范

### 7.1 色彩与层级

- 浅色主题使用中性灰工作区、白色内容面和深色文字；深色主题使用独立的中性黑灰 token。
- 主按钮使用高对比中性色，暖黄色保留给学习端品牌语义和必要强调，不让后台被单一色相主导。
- 成功、警告和危险继续使用现有语义色。
- 表格、面板和侧栏主要通过背景差异与细边框建立层级，避免大面积阴影。

管理端 token 集中在 `styles.css` 的 `.admin-shell` 区块：

```text
--admin-sidebar-bg
--admin-sidebar-text
--admin-sidebar-text-muted
--admin-sidebar-active-bg
--admin-workspace-bg
--admin-row-hover-bg
--admin-row-selected-bg
```

### 7.2 圆角、字体与图标

- 卡片和工作区圆角不超过 `8px`，表格容器通常使用 `4px`。
- 页面标题 `20px` 左右，表格正文 `13px - 14px`，辅助文字不低于 `10px`。
- 字号不随视口宽度缩放，字距保持 `0`。
- 图标统一使用现有 Lucide；icon-only 控件必须同时具有 `aria-label` 和 tooltip。

## 8. 响应式设计

### 8.1 桌面与平板，`>= 760px`

- 默认展示 `236px` 完整侧栏，允许用户手动折叠为 `68px`。
- 不根据桌面宽度自动隐藏多级子页面，确保所有有权限页面始终可达。
- 页面工具栏按可用宽度换行；表格和主从视图在自己的容器中处理溢出。

### 8.2 移动端，`< 760px`

- 侧栏变为顶栏菜单按钮打开的模态抽屉，宽度为 `min(304px, 88vw)`。
- 抽屉始终展示完整业务域和子页面，不继承桌面折叠态。
- 打开时锁定背景滚动并限制焦点；支持关闭按钮、遮罩、页面选择和 `Escape` 关闭。
- 关闭后将焦点归还菜单按钮；路由变化自动关闭抽屉。
- 工具栏和筛选按单列布局，输入控件使用可用宽度。
- 页面根节点不得横向溢出，表格横向滚动仅发生在数据容器。

## 9. 可访问性

- 当前业务域和当前页面设置 `aria-current="page"`。
- 可展开业务域设置 `aria-expanded`，折叠按钮同步暴露展开状态。
- 移动端抽屉打开后聚焦关闭按钮，`Tab` 和 `Shift+Tab` 在抽屉内循环。
- 所有 icon-only 控件提供可访问名称，tooltip 不替代 `aria-label`。
- 键盘焦点使用高对比 focus ring，不能被侧栏、表头或滚动容器裁切。
- 主题、语言和账户菜单继续复用全局状态源，避免两个 Shell 行为分叉。

## 10. 前端结构

```text
frontend/src/admin/shell/AdminShell.tsx
frontend/src/admin/shell/AdminSidebar.tsx
frontend/src/admin/shell/adminNavigation.ts
```

职责边界：

- `AppShell`：普通学习端布局，并在账户菜单按权限提供管理后台入口。
- `AdminShell`：管理端网格、顶部栏、工作区、桌面折叠、移动抽屉和焦点管理。
- `AdminSidebar`：渲染权限过滤后的业务域、子分组、页面和反馈徽标。
- `adminNavigation.ts`：维护模块、页面、查询参数、权限、图标、顺序和 active 匹配。
- 具体管理页面：持有搜索、筛选、加载、错误、对话框和数据请求状态；Shell 不复制业务状态。

导航模型支持页面和页面分组：

```ts
interface AdminModuleDefinition {
  id: AdminModuleId;
  labelKey: AdminNavigationLabelKey;
  icon: LucideIcon;
  items: AdminNavigationEntry[];
}

interface AdminPageDefinition {
  id: AdminPageId;
  labelKey: AdminNavigationLabelKey;
  path: string;
  permission: AuthPermission;
  query?: Readonly<Record<string, string>>;
  defaultForPath?: boolean;
}
```

## 11. 路由与状态

- `App.tsx` 先规范化路径并校验当前页面权限，再为 `/admin` 和 `/admin/*` 选择 `AdminShell`。
- 已知但无权限的深链接不得渲染受保护页面；导航模块也按同一权限集合过滤。
- 页面筛选、AI 视图和选中对象继续保存在 URL 查询参数中，Shell 只读取定位所需参数。
- 浏览器前进、后退和刷新必须恢复当前业务域、页面和 AI 子视图。
- 普通学习端账户菜单对 `session:manage` 和 `policy:manage` 等管理权限同样展示管理入口，避免拥有局部管理权限的用户无法进入后台。

## 12. 测试与验收

### 12.1 自动化测试

- 普通用户继续使用原有学习端导航；管理员访问学习端时也不切换 Shell。
- 管理模块、页面和 AI 子分组按权限过滤。
- `/admin/user-groups/{groupId}` 和 `/admin/ai?tab=...` 匹配正确 active 页面。
- 桌面侧栏可手动折叠和恢复；折叠时业务域仍可操作。
- 移动端抽屉锁定背景滚动，支持遮罩、关闭按钮、`Escape` 和焦点循环。
- 反馈徽标超过 `99` 显示 `99+`。
- 所有管理深链接、数据请求、筛选和对话框行为无回归。

### 12.2 视觉检查

- `1440x900`：`236px` 侧栏、`56px` 顶栏和页面工作区完整，无文档横向溢出。
- `1024x768`：完整多级侧栏仍可到达所有页面，工具栏和表格不与导航重叠。
- `390x844`：抽屉关闭与打开状态均无横向溢出；背景滚动锁定有效。
- 浅色和深色主题均有清晰的 active、hover、selected、danger 和 focus 状态。
- 中英文最长导航、筛选项和按钮文本不溢出容器。

### 12.3 验收标准

- 管理业务不再平铺在学习端顶栏，也不再使用内容区重复页签。
- 所有管理页面均可从按权限过滤的侧栏到达，当前位置清晰。
- AI Provider、路由、用量和定价可直接从三级侧栏导航，并保留原查询参数深链接。
- 页面形成一致的紧凑标题、工具栏、数据工作区和分页结构。
- 桌面、平板和移动端均可完成导航、筛选、查看详情和关键管理操作。
- 普通学习端行为、管理端数据语义、URL 和深链接没有回归。

## 13. 风险与约束

- 项目使用轻量手写路由，新增管理页面时必须同步更新路由识别、权限校验和 `adminNavigation.ts`。
- 同一路径承载多个 AI 视图时，active 匹配必须同时检查查询参数和默认视图。
- 桌面折叠态隐藏页面叶子，因此折叠后点击多页面业务域必须先恢复展开态。
- 固定视口布局容易产生双滚动条，Shell、页面和表格必须分别维持明确的唯一滚动边界。
- `styles.css` 体量较大，后续管理端样式应继续限定在 `.admin-shell` 或 `.admin-workspace` 命名空间内。
- 管理页面提高密度后仍需保留可读字号、稳定点击面积和完整键盘操作。
