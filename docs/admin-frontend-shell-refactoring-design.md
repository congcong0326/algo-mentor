# 管理员前端工作区重构设计

> 实施顺序：本设计先于 `docs/user-group-management-design.md` 执行。
> 本次只改造管理员访问的 `/admin/*` 界面。普通用户现有顶栏导航、页面布局和交互风格保持不变。
> 视觉参考：仓库根目录 `友商管理界面.png`。本设计借鉴其管理台信息层级和高密度工作区，不复制品牌、配色、组织树或多窗口标签体系。

## 0. 已定决策

1. 普通用户继续使用现有 `AppShell` 和顶部一级导航；管理员只有进入 `/admin/*` 后才切换到独立 `AdminShell`。
2. 管理后台采用“全局顶栏 + 左侧业务域导航 + 内容区局部导航 + 页面工作区”四层结构。
3. 左侧栏只放稳定的业务域，不把每个页面都平铺成同级菜单；同一业务域内的页面通过内容区页签切换。
4. “用户与访问”业务域包含用户管理、用户组管理和内测准入；用户组功能未实现前不展示对应页签。
5. 管理员页面以扫描、筛选、批量处理和查看详情为核心，使用紧凑工具栏、表格、主从视图和抽屉，不使用营销式大标题或装饰性卡片。
6. 保持现有管理员 URL、查询参数和深链接可用；旧 `/debug` 规范化到 `/admin/debug`。
7. 导航和路由继续按照现有 `AuthPermission` 过滤；前端隐藏不替代后端 `/api/admin/**` 权限校验。
8. 不引入新的 UI 框架，不改造管理员页面的数据请求语义，不为参考图中不存在于本项目的能力补造后端接口。
9. 管理台沿用 Algo Mentor 现有暖黄色品牌强调色和明暗主题，不照搬参考图的高饱和蓝色体系。

## 1. 背景与问题

当前 `AppShell` 会识别管理员权限，把管理员概览、内测准入、用户管理、AI 治理、反馈、题库和 AI 调试平铺在顶部导航。管理员功能继续增加后存在以下问题：

- 顶部空间不足，导航依赖横向滚动，页面越多越难定位；
- 用户、AI、内容、运营和开发工具混排，缺少稳定的业务域；
- 管理页面仍沿用学习端较宽松的页面留白，表格和操作区可用空间不足；
- 各页面自行组织标题、筛选、刷新和操作按钮，密度与交互顺序不一致；
- 页面切换时只有顶栏 active 状态，缺少“当前处于哪个管理域、哪个子页面”的位置感；
- `debugStatus` 等页面局部状态进入全局顶栏，导致 Shell 和业务页面职责交叉。

普通用户侧导航数量有限，并且符合学习工具的高频路径，不存在同样的问题。因此本次只建立管理员工作区，不做全站导航重构。

## 2. 参考图分析

### 2.1 借鉴内容

参考图中值得转译到 Algo Mentor 的设计方法：

1. **全局与业务导航分层**：全局顶栏只承载品牌、工作区和账户动作，业务模块固定在左侧。
2. **当前业务域高识别度**：深色侧栏、明确 active 区域和稳定宽度让管理员始终知道当前位置。
3. **局部页面切换靠近内容**：同一业务域内的子页面在内容区顶部切换，而不是继续挤占全局导航。
4. **命令与筛选成行排列**：常用操作在左，搜索、筛选和高级条件在右，减少纵向占用。
5. **高密度数据工作区**：表格、树、详情和分页形成连续操作面，避免每段内容都包成悬浮卡片。
6. **主从结构**：列表与详情同时可见，适合反馈处理、用户详情等高频连续操作。

### 2.2 不直接借鉴内容

- 不引入组织机构树。当前项目只有用户组，没有组织层级、父子节点或目录授权语义。
- 不引入可关闭的多窗口标签。现有页面规模不需要 MDI，多标签还会带来状态恢复、脏数据确认和移动端适配成本。
- 不增加没有后端支持的全局搜索、导入、导出、组授权或批量绑定入口。
- 不照搬蓝色主色和大面积深蓝背景；项目继续使用现有品牌色与主题 token。
- 不把桌面端截图按比例缩小到移动端；移动端采用抽屉、页面选择器和单列详情。

## 3. 目标与非目标

### 3.1 目标

- 让管理员在全局工作区、业务域、子页面和当前对象之间快速定位。
- 让现有和后续管理员功能可以按业务职责扩展，不再依赖顶部横向空间。
- 提高表格、筛选、详情和批量操作的首屏信息密度。
- 统一管理员页面标题、命令栏、筛选区、数据区、空状态和分页结构。
- 为用户组管理提供稳定入口和布局基座，但不提前展示空功能。
- 保持现有业务行为、URL 查询参数和可复制深链接。
- 在桌面、平板和移动端保持完整的导航与操作能力。

### 3.2 非目标

- 不改变普通用户首页、学习计划、复习中心、学习画像和设置页。
- 不在本阶段重写用户管理、AI 治理、反馈管理等页面的数据状态逻辑。
- 不新增后端权限、管理员角色、动态菜单 API 或服务端布局配置。
- 不实现用户组、成员管理、组织树或访问策略。
- 不建设可拖动、可关闭、可恢复的多窗口标签系统。
- 不为所有业务页面强制使用同一种表格或详情形态；只统一页面骨架和通用交互约束。

## 4. 信息架构

### 4.1 路由范围

`AdminShell` 负责以下地址：

```text
/admin                       运营概览
/admin/users                 用户与访问 / 用户管理
/admin/user-groups           用户与访问 / 用户组管理，功能完成后启用
/admin/beta-access           用户与访问 / 内测准入
/admin/monitoring            系统监控 / 运行状态
/admin/ai                    系统监控 / AI 治理
/admin/problems              内容管理 / 题库管理
/admin/feedback              反馈与支持
/admin/debug                 开发工具 / AI 调试
```

现有 `/debug` 作为兼容入口保留，认证和权限校验后使用 replace 方式规范化到 `/admin/debug`。其他现有 `/admin/*` 地址和查询参数保持不变。

### 4.2 左侧业务域

左侧栏只展示稳定业务域：

```text
运营概览
用户与访问
系统监控
内容管理
反馈与支持
开发工具
```

映射规则：

| 业务域 | 默认地址 | 子页面 | 可见条件 |
| --- | --- | --- | --- |
| 运营概览 | `/admin` | 无 | `admin-overview:read` |
| 用户与访问 | 第一个有权限的子页面 | 用户、用户组、内测准入 | 任一子页面权限可用 |
| 系统监控 | 第一个有权限的子页面 | 运行状态、AI 治理 | `admin-overview:read` 或 `ai-governance:manage` |
| 内容管理 | `/admin/problems` | 题库管理 | `problem:read` |
| 反馈与支持 | `/admin/feedback` | 反馈处理 | `feedback:manage` |
| 开发工具 | `/admin/debug` | AI 调试 | `debug:access` |

“用户与访问”点击后进入当前用户有权限的第一个子页面，优先级固定为用户管理、用户组管理、内测准入。业务域没有任何可访问子页面时不渲染。

### 4.3 内容区局部导航

只有一个业务域包含多个独立页面时才显示局部页签。第一版至少包含：

```text
用户与访问
  用户管理       /admin/users
  用户组管理     /admin/user-groups
  内测准入       /admin/beta-access

系统监控
  运行状态       /admin/monitoring
  AI 治理         /admin/ai
```

- 页签按权限过滤，用户组页面完成前不加入可见配置。
- 当前页签使用 `aria-current="page"`，不能只用颜色表达 active 状态。
- AI 治理现有 `?tab=` 视图仍属于页面内部视图，不与系统监控的 Shell 页签混用。
- 只有一个可见子页面时不显示局部页签，减少无效层级。

## 5. 整体布局

### 5.1 桌面结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Algo Mentor │ 管理后台                    返回学习端  主题  语言  账号 │ 56
├──────────────┬───────────────────────────────────────────────────────┤
│ 管理后台     │ 用户管理  用户组管理  内测准入                         │ 44
│              ├───────────────────────────────────────────────────────┤
│ 运营概览     │ 用户管理                          搜索  状态  刷新       │ 52
│ 用户与访问 ◀ ├───────────────────────────────────────────────────────┤
│ 系统监控     │                                                       │
│ 内容管理     │ 数据表格 / 主从工作区 / 页面主体                       │
│ 反馈与支持   │                                                       │
│ 开发工具     ├───────────────────────────────────────────────────────┤
│              │ 共 48 项                              分页与每页数量    │
└──────────────┴───────────────────────────────────────────────────────┘
      216                              minmax(0, 1fr)
```

布局尺寸使用管理员专属 CSS 变量集中管理：

```text
--admin-header-height: 56px
--admin-sidebar-width: 216px
--admin-sidebar-collapsed-width: 64px
--admin-context-nav-height: 44px
--admin-toolbar-min-height: 52px
```

- `AdminShell` 使用 `100dvh` 高度，桌面端页面滚动发生在内容工作区，不让顶栏和侧栏随长表格消失。
- 主内容列必须使用 `minmax(0, 1fr)` 和 `min-width: 0`，避免表格撑破布局。
- 内容区不设置学习端使用的 `1200px` 最大宽度，管理页面可以使用完整可用宽度。
- 页面外层使用浅色工作区背景；表格、详情面板通过一像素边框分区，不包裹装饰性外层卡片。

### 5.2 全局顶栏

顶栏只承载全局动作：

- 左侧：Algo Mentor 品牌、分隔线、“管理后台”工作区名称；
- 右侧：返回学习端、主题切换、语言选择、账户菜单；
- 移动端额外显示打开侧栏的菜单按钮；
- 不放业务页面菜单、筛选条件、反馈未读列表或 AI 调试连接状态；
- 不增加无真实能力支撑的全局搜索框。

“返回学习端”是明确命令，使用图标加文字；主题等熟悉动作使用图标按钮和 tooltip。管理员从学习端进入后台的入口仍放在账户菜单，普通用户不显示该入口。

### 5.3 左侧业务域导航

- 桌面展开宽度为 `216px`，顶部显示“管理后台”或当前环境标识，下面排列业务域。
- 图标、文本和 active 指示保持固定轨道，动态徽标不能改变菜单项尺寸。
- active 状态使用“背景变化 + 左侧 3px 品牌色指示条 + 高对比文字”，不使用整块高饱和黄色。
- 反馈未读数显示在“反馈与支持”右侧，最大显示 `99+`。
- 分组之间使用留白或细分隔线，不使用多个大标题占据纵向空间。
- 折叠状态只显示图标，并为每项提供 tooltip 和可访问名称。

### 5.4 局部导航与页面头

内容区顶部由两个可选层组成：

1. `AdminContextNav`：同一业务域的子页面页签，高度 `44px`；没有兄弟页面时不渲染。
2. `AdminPageToolbar`：页面标题、主命令、搜索和筛选，高度最小 `52px`，内容多时允许换行。

页面标题使用紧凑的 `18px` 至 `20px` 字号，不使用学习端 `32px` 的展示型标题。默认不添加解释功能的副标题；确有错误、风险或运行状态时，以状态条或内联提示展示。

命令栏排序固定为：

```text
左侧：页面标题 -> 主操作 -> 次操作
右侧：快速筛选 -> 搜索 -> 高级筛选 -> 刷新
```

- 搜索框宽度稳定，建议 `240px` 至 `320px`，不得挤压主命令。
- 刷新使用图标按钮和 tooltip；“新建用户组”等明确命令使用图标加文字。
- 二元状态使用开关或复选框，有限选项使用 select/menu，不把所有筛选做成文字按钮。
- 工具栏只展示页面真实支持的操作，不因参考图而添加导入、导出或批量绑定。

## 6. 数据工作区规范

### 6.1 表格页

表格页采用连续结构：

```text
局部导航（可选）
页面命令栏
状态提示（可选）
表格滚动区
分页栏
```

- 表头保持单行，字号建议 `12px` 至 `13px`；数据行正文保持 `14px`。
- 常规行高不低于 `40px`，操作按钮有稳定点击区域，不能为了密度缩小到难以使用。
- 文本列允许省略并提供完整值访问方式；状态、时间和操作列保持稳定宽度。
- 行内操作不超过两个时直接显示；更多操作收进 `MoreHorizontal` 菜单。
- 只有批量操作存在时才显示首列复选框；选中后工具栏切换为批量操作状态。
- 空状态、加载状态和错误状态都占据表格主体，不改变表头和分页栏的位置。
- 表格横向空间不足时仅数据区横向滚动，侧栏和整个页面不得一起横向滚动。

### 6.2 主从工作区

反馈管理等需要连续处理对象的页面使用主从结构：

```text
┌────────────────────列表──────────────────┬────────详情────────┐
│ 筛选后的反馈行                            │ 时间线、状态、回复   │
└──────────────────────────────────────────┴────────────────────┘
```

- 列表和详情共用一个有边框的工作区，不把详情再包成卡片。
- 详情宽度使用 `clamp(320px, 36%, 520px)`，列表保持 `minmax(0, 1fr)`。
- 选中对象继续写入查询参数，例如 `threadId`、`userId`，刷新和复制链接后可恢复。
- 小屏幕切换为列表页和详情页两个状态，提供明确返回按钮，不强行并排压缩。

### 6.3 抽屉与对话框

- 用户详情继续使用右侧抽屉，桌面宽度建议 `440px` 至 `520px`，通过 `userId` 查询参数驱动。
- 创建、编辑和危险操作确认使用对话框；详情信息较多或包含成员表格时使用独立页面。
- 抽屉和对话框打开后管理焦点、支持 `Escape`、关闭后把焦点还给触发控件。
- 抽屉内部按信息区块使用分隔线，不堆叠多层卡片。

## 7. 页面落位

### 7.1 运营概览

- 左侧业务域选中“运营概览”，不显示局部页签。
- 顶部使用紧凑状态摘要，展示 AI 可用性、准入状态、Token/成本、额度风险和反馈待办。
- 摘要指标可以使用同级小型指标块，但不使用大面积插图、渐变背景或营销文案。
- 待办和风险项直接链接到带查询参数的目标页面。

### 7.2 用户管理

- “用户与访问”业务域 active，局部页签选中“用户管理”。
- 命令栏右侧依次放状态筛选、用户搜索和刷新。
- 主体使用全宽用户表格；点击用户或“查看”打开现有详情抽屉。
- 重置密码、停用、恢复、删除等危险动作维持明确确认，不进入拥挤的批量工具栏。
- 用户组功能完成后增加“用户组”列，但不在本 Shell 阶段实现。

### 7.3 用户组管理

- 功能完成后作为“用户与访问”的局部页签出现。
- 列表页使用搜索、状态筛选、新建用户组、表格和分页。
- 详情继续使用独立 `/admin/user-groups/{groupId}` 页面，不照搬参考图的组织树。
- 成员管理表格和用户详情抽屉遵循 `docs/user-group-management-design.md`。

### 7.4 内测准入

- “用户与访问”业务域 active，局部页签选中“内测准入”。
- 全局开关属于页面状态区；搜索、批量添加和刷新进入页面命令栏。
- 准入名单继续使用表格和分页，不新增目录树或授权面板。

### 7.5 系统监控

- 左侧业务域选中“系统监控”，局部页签包含“运行状态”和“AI 治理”。
- `/admin/monitoring` 使用现有 `/api/health` 显示 API 服务健康状态、最近检查时间与手动刷新入口，并每分钟自动检查一次。
- AI 治理保留原 `/admin/ai` 地址、全局止损开关和用量/价格页内标签；它作为系统监控的子页面展示，不改动 AI 治理的数据请求语义。
- 表格筛选、价格编辑对话框和用户跳转保留现有查询参数语义。

### 7.6 内容管理

- 第一版只有题库管理，左侧点击后直接进入 `/admin/problems`，不显示只有一个选项的局部页签。
- 题库搜索、筛选和操作迁入统一命令栏；题目列表使用完整内容宽度。

### 7.7 反馈与支持

- 左侧显示未读徽标，进入后使用列表与详情主从工作区。
- 状态、分类和“仅未读”位于页面命令栏或其下方的紧凑筛选行。
- 选择反馈后保持 `threadId` 深链接；移动端进入单独详情状态。

### 7.8 开发工具

- `/debug` 规范化到 `/admin/debug`，左侧选中“开发工具”。
- AI 调试连接状态移动到调试页面命令栏，不占用全局顶栏。
- 调试控制台可使用剩余视口高度，日志和输入区独立滚动。

## 8. 视觉规范

### 8.1 色彩

- 全局顶栏：使用 `--surface-elevated` 和底部分隔线。
- 页面工作区：使用 `--surface-page`、`--surface-muted` 和 `--border-subtle` 建立层级。
- 左侧栏：使用中性的深色表面；暖黄色只作为 active 指示、主命令和焦点强调。
- 成功、警告、危险继续使用现有语义色，不用品牌色代替状态色。
- 深色主题必须使用主题 token 重新计算背景和边框，不对浅色值做简单反相。

管理员专属 token 应集中在 `styles.css` 的管理台区块，优先复用现有全局 token：

```text
--admin-sidebar-bg
--admin-sidebar-text
--admin-sidebar-text-muted
--admin-sidebar-active-bg
--admin-workspace-bg
--admin-row-hover-bg
--admin-row-selected-bg
```

### 8.2 边框、圆角与阴影

- 管理台以边框和背景层级组织信息，减少阴影。
- 工作区、表格容器和局部导航圆角为 `0` 至 `6px`；不沿用学习端 `20px` 大卡片圆角。
- 对话框和抽屉可以保留较清晰的 elevation；表格和页面分区不使用悬浮阴影。
- 不使用渐变、装饰性光斑、水印或无业务含义的背景图。

### 8.3 字体与图标

- 全局品牌 `16px`，页面标题 `18px` 至 `20px`，表格正文 `14px`，辅助信息不低于 `12px`。
- 字号不随视口宽度缩放，字距保持 `0`。
- 图标统一使用现有 Lucide，尺寸建议 `16px` 至 `18px`。
- 熟悉的工具动作使用图标按钮；不熟悉的图标必须有 tooltip，危险操作不能只依赖颜色表达。

## 9. 响应式设计

### 9.1 宽屏，`>= 1200px`

- 左侧栏保持 `216px` 展开状态。
- 局部页签、页面标题和命令栏尽量单行。
- 表格和主从工作区占用剩余视口宽度与高度。

### 9.2 紧凑桌面与平板，`760px - 1199px`

- 左侧栏折叠为 `64px` 图标导航；通过 tooltip 显示名称。
- 页面命令栏允许分成两行，主命令与筛选不能重叠。
- 主从页面根据可用宽度决定并排或切换为单详情状态。
- 表格保持自己的横向滚动容器。

### 9.3 移动端，`< 760px`

- 左侧栏改为由顶栏菜单按钮打开的模态抽屉。
- 抽屉打开时锁定背景滚动、限制焦点，选择业务域或按 `Escape` 后关闭。
- 局部页签替换为紧凑的页面选择菜单，避免多个标签横向挤压。
- 命令栏按“标题与主操作、搜索、筛选”分行排列；搜索宽度为 `100%`。
- 表格优先保留关键列并允许数据区横向滚动；不把每行自动改造成高度失控的卡片。
- 详情抽屉变为全屏详情层，顶部保留返回和关闭动作。

## 10. 交互与可访问性

- 路由导航优先使用链接语义；SPA 拦截跳转时仍应保留可复制地址、刷新恢复和浏览器前进后退能力。
- 当前业务域和当前子页面均设置 `aria-current="page"`。
- 所有 icon-only 按钮提供 `aria-label` 和 tooltip，tooltip 不替代可访问名称。
- 键盘焦点使用高对比 focus ring，不被侧栏或 sticky 表头裁切。
- 加载期间保留页面骨架，避免工具栏、表头和分页跳动。
- 错误提示靠近对应工作区；全局错误不得覆盖页面操作或只用短暂 toast 表达。
- 删除、停用、重置密码、关闭反馈等高影响动作继续确认，并清楚说明目标对象。
- 主题切换、语言切换和账户菜单复用现有交互，不在两个 Shell 中形成两套状态源。

## 11. 前端结构调整

### 11.1 建议目录

```text
frontend/src/admin/shell/AdminShell.tsx
frontend/src/admin/shell/AdminHeader.tsx
frontend/src/admin/shell/AdminSidebar.tsx
frontend/src/admin/shell/AdminContextNav.tsx
frontend/src/admin/shell/AdminPageToolbar.tsx
frontend/src/admin/shell/adminNavigation.ts
```

职责边界：

- `AppShell`：只负责普通用户工作区，移除管理员菜单排序和过滤分支。
- `AdminShell`：负责管理台整体网格、响应式侧栏、内容出口和滚动边界。
- `AdminHeader`：负责品牌、工作区名称、返回学习端和通用账户动作。
- `AdminSidebar`：只渲染按权限过滤后的业务域与徽标。
- `AdminContextNav`：渲染当前业务域的可访问子页面。
- `AdminPageToolbar`：提供统一布局槽位，不持有业务搜索或筛选状态。
- `adminNavigation.ts`：集中维护业务域、子页面、路由、权限、图标、默认地址和显示顺序。

主题切换、语言选择和账户菜单可以在出现真实复用时从 `AppShell` 提取为窄职责组件。本次不建设通用布局框架，也不让 `AdminShell` 读取具体页面的筛选状态。

### 11.2 导航配置模型

建议使用配置驱动的稳定契约：

```ts
interface AdminModuleDefinition {
  id: AdminModuleId;
  labelKey: AdminNavigationLabelKey;
  icon: LucideIcon;
  defaultPath: string;
  items: AdminPageDefinition[];
}

interface AdminPageDefinition {
  id: AdminPageId;
  labelKey: AdminNavigationLabelKey;
  path: string;
  permission: AuthPermission;
  enabled: boolean;
}
```

- `AdminModuleId`、`AdminPageId`、路由和查询参数 key 使用已有或新建的常量/联合类型，不在 JSX 中散落字符串。
- 模块可见性由可见子页面计算，不单独维护容易失真的权限列表。
- 用户组功能上线时只修改路由映射和 `enabled` 状态，不添加 disabled 占位项。

### 11.3 Shell 选择

`App.tsx` 根据规范化后的当前路径选择 Shell：

```text
pathname matches /admin or /admin/*
  -> 校验当前页面权限
  -> AdminShell

其他已认证路由
  -> AppShell
```

管理员身份本身不强制普通用户路由进入 `AdminShell`。管理员访问 `/`、`/learning-plans` 等地址时，仍看到与普通用户一致的学习端布局。

## 12. 路由、权限与状态

- 新增 `isAdminPath(pathname)`、`adminModuleFromPath(pathname)` 和 `firstAccessibleAdminPath(user)`。
- `/admin/debug` 为规范地址，`/debug` 只保留兼容映射。
- 已知但无权限的管理员深链接不得渲染受保护页面；规范化到第一个可访问管理员页面，若不存在则回到学习端首页。
- 未知 `/admin/*` 地址进入管理台内的未找到状态，不静默显示其他业务页面。
- 页面筛选和选中对象继续保存在 URL 查询参数中；Shell 不复制这些状态。
- 反馈未读数等跨页面轻量状态可以由现有 App 层持有，再传给 `AdminSidebar`。
- 用户组页面未实现时 `/admin/user-groups` 不属于已知可访问路由，也不展示导航入口。

## 13. 实施步骤

### 阶段一：导航与 Shell 基座

1. 拆分普通用户导航和管理员导航配置。
2. 补充 `/admin/debug`、管理员路径识别和权限规范化。
3. 新增 `AdminShell`、`AdminHeader`、`AdminSidebar` 和 `AdminContextNav`。
4. 从 `AppShell` 移除管理员专属菜单排序、过滤和调试状态分支。
5. 保证普通用户和管理员访问学习端时的现有渲染结果不变。

### 阶段二：管理页骨架统一

1. 新增管理台布局 token 和 `AdminPageToolbar`。
2. 迁移用户管理、内测准入、反馈、AI 治理、题库和 AI 调试页面。
3. 将 AI 调试连接状态移回调试页面。
4. 统一表格滚动区、空状态、错误状态和分页栏的布局边界。
5. 保留每个页面现有数据请求、确认弹窗和 URL 查询参数语义。

### 阶段三：响应式与可访问性

1. 完成展开侧栏、折叠侧栏和移动端抽屉。
2. 完成局部页签到移动端页面选择器的切换。
3. 完成焦点管理、tooltip、`aria-current`、`Escape` 和背景滚动锁定。
4. 检查表格、主从视图、抽屉和对话框在各断点不重叠。

### 阶段四：用户组入口接入

该阶段属于 `docs/user-group-management-design.md`：

1. 用户组页面和路由完成后，在“用户与访问”局部导航显示“用户组管理”。
2. 页面未完成前不展示 disabled 页签或“开发中”占位页。

## 14. 测试范围

### 14.1 导航与权限测试

- 普通用户继续看到原有顶部导航项和顺序。
- 普通用户不看到“管理后台”入口。
- 管理员访问学习端路由时仍使用普通 `AppShell`。
- 管理员访问 `/admin/*` 时使用 `AdminShell`。
- 左侧业务域和局部页签按权限过滤，并选择正确 active 状态。
- “用户与访问”进入当前用户可访问的第一个子页面。
- “系统监控”按 `admin-overview:read` 和 `ai-governance:manage` 分别过滤运行状态和 AI 治理页签。
- 反馈未读数显示在左侧对应业务域，超过 `99` 显示 `99+`。
- 用户组功能未完成时不显示入口。

### 14.2 路由与状态测试

- 所有现有 `/admin/*` 深链接仍映射到原页面。
- `/debug` 使用 replace 方式规范化到 `/admin/debug`。
- 无权限管理员路由不会渲染受保护页面。
- 未知 `/admin/*` 显示管理台内未找到状态。
- 刷新用户详情和反馈详情深链接后，抽屉或详情选择可以恢复。
- 浏览器前进、后退可恢复业务域、局部页签和页面查询条件。

### 14.3 组件与交互测试

- 桌面侧栏展开、平板侧栏折叠、移动端抽屉可以正常导航。
- 移动端抽屉支持遮罩、选择、关闭按钮和 `Escape` 关闭。
- 抽屉和对话框正确限制并归还焦点。
- icon-only 控件具有可访问名称和 tooltip。
- 页面工具栏换行时搜索、筛选和主操作不重叠。
- 加载、空数据、错误和无权限状态不造成布局跳动。

### 14.4 视觉检查

- `1440x900`：侧栏、局部导航、工具栏、表格和分页首屏完整可见。
- `1024x768`：折叠侧栏不挤压表格操作区，工具栏允许两行。
- `390x844`：移动抽屉、页面选择器、搜索和详情层无重叠。
- 中英文最长导航、筛选项和按钮文本不溢出容器。
- 浅色和深色主题均具备清晰的 active、hover、selected、danger 和 focus 状态。
- 表格横向滚动只发生在数据工作区，不带动整个页面。

## 15. 验收标准

- 普通用户界面与改造前保持一致。
- 管理员顶栏不再平铺业务页面，业务域固定在左侧导航。
- 用户管理、用户组管理和内测准入在同一业务域的局部导航中组织。
- 页面形成统一的紧凑标题、命令栏、数据工作区和分页结构。
- 管理员页面不再受学习端 `1200px` 内容宽度和大面积留白限制。
- 所有管理员功能均可按权限到达，当前业务域和子页面位置清晰。
- 桌面、平板和移动端均可完成导航、筛选、查看详情和关键管理操作。
- 现有业务行为、查询参数和深链接没有回归。
- 用户组功能实现前不出现空入口，实现后可以直接接入“用户与访问”局部导航。

## 16. 风险与约束

- 当前 `App.tsx` 使用轻量手写路由。Shell 拆分时必须先集中路径识别，避免管理员路径判断继续散落在渲染分支中。
- `styles.css` 体量已经较大，管理台样式应按 `admin-shell`、`admin-page`、页面局部样式分区，避免继续添加不可追踪的单行组合规则。
- 固定视口布局容易产生双滚动条，实施时必须明确 Shell、页面和表格各自唯一的滚动容器。
- 管理页密度提高后仍要保留可点击面积和可读字号，不能把参考图的桌面密度机械压缩到所有设备。
- 现有管理员页面视觉差异较大，应先统一骨架，再逐页调整内部布局，避免一次性重写业务状态造成回归。
