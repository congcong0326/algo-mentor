# 学习记忆前端展示设计

## 1. 目标

在现有「学习画像」页面展示当前用户的学习记忆，让用户能够看到 AI 已保存的学习背景、长期观察和专项能力判断，同时保持能力雷达与自然语言画像的语义边界。

本次只实现当前 `ACTIVE` 内容的只读展示，不增加编辑、删除、历史版本和记忆开关。

## 2. 页面位置

学习记忆放在 `/me` 学习画像页的能力摘要与能力雷达之间，不新增一级导航。

页面信息顺序：

1. 能力摘要；
2. 学习记忆；
3. 能力雷达；
4. 标签能力热力图。

设置页暂不承载记忆正文。后续增加记忆开关、清空和隐私治理时，再放入设置页。

## 3. 展示分组

- `DECLARED_FACT`：展示为「我告诉 AI 的」；
- `GENERAL_OBSERVATION`：展示为「AI 观察到的」；
- `TAG_ASSESSMENT`：展示为「专项能力判断」。

三个分组使用标签页切换，每组默认显示 5 条，超过后提供展开和收起操作。标签评价使用规范化题目标签的中英文名称，能力分仍以现有能力雷达为准。

## 4. API 契约

新增 `GET /api/me/learner-profile`，用户身份只从当前认证上下文读取，不接受请求参数中的 `userId`。

响应只包含展示所需字段：

- 条目 ID、维度、版本号、正文、来源类型和更新时间；
- 标签评价对应的标签 ID、稳定值和中英文名称；
- 三类当前条目及整体最近更新时间。

接口只查询 `status = ACTIVE` 的条目，不返回历史正文、模型 provider、模型名、Prompt 版本或其他内部诊断字段。

## 5. 状态与降级

- 学习记忆与能力画像独立加载，一侧失败不阻塞另一侧；
- 提供加载、空数据、失败和重试状态；
- Markdown 正文通过项目现有安全渲染组件展示；
- 标签页具备 `tablist/tab/tabpanel` 语义，并在可访问名称中包含条目数量。

## 6. 测试范围

- Controller 验证当前用户隔离、未登录响应和安全字段；
- Service 验证三类分组、标签映射和最近更新时间；
- MyBatis XML 验证仅查询 `ACTIVE` 内容并关联规范化标签；
- 前端验证三类切换、默认 5 条预览、展开和 API 请求头。
