# 今日题包独立入口与计划激活模型设计

编写日期：2026-07-07

> 本文只回答一件事：**「今日该练什么」和「我的方案」这两件事，在产品的入口与导航结构上如何拆开。**
> 不涉及节奏参数、负载计算和题包实时算法，那些承接：
> - [`learning-plan-living-contract-design.md`](./learning-plan-living-contract-design.md)（活的契约：不丢题 / 不设墙 / 有回声）
> - [`learning-plan-rhythm-redesign.md`](./learning-plan-rhythm-redesign.md)（每日题数 / 每周天数 / 题包实时计算不持久化）

---

## 一句话结论

「计划」是战略层（低频、长期），「今天刷哪些题」是执行层（高频、每天来）。当前把两者揉在同一个方案页里，导致高频操作被埋在低频页面下。本设计把 **今日题包拆成独立主入口**，把 **「激活」这一概念做到最轻**——它唯一决定的，就是「今日题包按哪个计划生成」，除此之外什么都不管。

---

## 现状与问题

- 方案页可以创建多个方案；点进某个方案后，既能管理计划，又能自由选任意题目查看、对话。
- 「今天该练什么」（题包）目前挂在方案页内部，是低频页面下的一个二级操作。
- 结果：用户每天最高频的动作（看今天该刷什么、开始刷），路径被拉长，埋在战略层页面里。

核心矛盾：**战略层（选哪条路线）和执行层（今天刷什么）频率差一个数量级，却共用一个入口。**

---

## 为什么拆得动：两个前提消除了副作用

拆分之所以没有代价，依赖两个已成立的前提：

1. **两条路殊途同归**：无论从「今日题包」进，还是从「方案里自由选题」进，最终都落到同一个**聊天页**。入口不同，终点相同。
2. **题包实时计算**：题包状态由实时计算得出（见 rhythm-redesign），不持久化。因此**不存在两套进度**，从哪个入口进都不影响结果。

结论：既然浏览和对话都是无副作用的（实时计算 + 都进聊天页），**自由浏览/对话可以永远全局可用，不受任何激活状态限制。**

---

## 激活模型：越轻越好

**任意时刻只有一个激活计划。** 可以创建多个计划（类似草稿箱 + 当前采用），但同时只有一个被激活。

关键决策——**把「激活」的职责压到最小**：

> 激活唯一决定的事，是「**今日题包按哪个计划生成**」。除此之外，它不约束浏览、不约束对话、不约束进度归属。

激活越轻，切换成本越低，用户越敢用。一旦激活牵扯「进度归属」「断点丢失」这类东西，用户就不敢随便切了。

| 能力 | 是否受激活限制 |
| --- | --- |
| 今日题包按哪个计划生成 | **是（激活的唯一职责）** |
| 点进任意计划浏览题目 | 否，全局可用 |
| 对任意题目发起对话 | 否，全局可用 |
| 进度 / 完成状态 | 否，实时计算，与入口无关 |

---

## 三层结构

拆分后，产品是**三层**，而不是两个平级入口。系统推荐是主动脉，自由选择是旁路——不让用户在门口就被迫二选一。

| 层 | 界面 | 频率 | 职责 | 与激活的关系 |
| --- | --- | --- | --- | --- |
| 执行层 | **今日题包** | 高频（默认落点） | 打开即刷，展示激活计划算出的今日题目 | **绑定**激活计划 |
| 战略层 | **方案** | 低频 | 管理多计划、切换激活；点进任一计划可看全部题目、自由选题对话（全局入口） | 管理激活状态，但浏览/自由刷**不依赖**激活 |
| 共同终点 | **聊天** | — | 两条路的共同终点 | 无关 |

- **首页默认落点 = 今日题包**：用户打开即见今天该刷什么，不用多点一下。
- **方案页保留「全局入口」价值**：需要一个能纵览全局、自由挑题的地方；这个能力不受激活限制，哪怕是未激活的计划也能点进去看题、发起对话。

心智模型一句话：**想被安排 → 看今日题包；想自己逛 → 进方案。**

---

## 今日题包的「性格」

拆出来后，「今日题包」必须区别于「题库」——它是一个**有边界、有目标、有约束的每日任务**，不是换了皮的题库推荐。以下几条共同定义它的性格。

### 1. 刷完的收尾：有明确的「今天到此为止」

- 今日题目全部完成 → 给完成正反馈，主按钮是「**到此为止 / 收工**」。
- 学有余力者可继续「**再来一包**」，但：
  - **提前申请的题包必须标注它属于哪一天**（如「这是 7/8 的题包，提前解锁」），而不是含糊地「再来一组」。让用户始终知道自己在消耗未来的额度，而不是无限刷。
  - **不设硬上限**：允许用户按自己的节奏一直往前领（信任用户、不惩罚）。
  - 但连续提前时给一句**中性温和提示**（如「你已提前到 7/9 的题包，注意留出消化时间」），点到为止，不拦路。

> 边界感来自「每天有一个可达成的目标 + 提前是显式特权」，而不是来自「一堵墙」。无限刷会让人焦虑、没有成就感；「今天到此为止」的完成感，是今日题包的灵魂。

### 2. 没刷完：不变，且必须体现「顺延」

这是整套设计里最关键的一条。

- **今天没刷完 → 明天题包不变**，昨天没做的题滚到今天，**不丢**（承接契约文档的「不丢题」承诺）。
- 今日题包分两段呈现，顺序即直觉——**先还债，再干今天的活**：
  1. 上：**「顺延 / 待补」** 段，带**天数标记**（如「顺延 1 天」）。
  2. 下：**「今天的」** 段。
- **措辞必须中性，不要惩罚感**：用「顺延 / 待补」，**不要**用「逾期 / 欠账 / 未完成 ❌」。学习产品一旦让用户觉得「我失败了 / 我欠了一屁股债」，挫败感会直接赶走人。
- **止损阀（必须有）**：顺延长期堆积（如积压超过 X 天）时，不要无限往上垒，而是温和提示「要不要调整计划节奏 / 一键清账重新开始」。**允许用户体面地重来**，比让他盯着一座还不完的债山然后卸载要好得多。

## 其余已拍板的产品决策

- **切换激活计划 → 一道轻确认**：切换是唯一有全局副作用的操作，轻归轻，但误触代价是「明天的题全变了」。切换时给一句提示「今日题包将按新计划生成」，不拦路，只是让用户对「我改变了主线」有知觉。切换后**不呈现**「你今天在旧计划下已完成 X 题」——实时计算下断点不会丢，不必制造多余焦虑。
- **冷启动空态 = 可立即激活的推荐计划**：新用户第一次进来没有计划，今日页是留存第一屏。空态不能只写「暂无计划」，而应是一个**能立刻激活的推荐计划入口**，让用户 30 秒内就有「今天该刷的题」。
- **全局入口里标记「此题在今日题包中」**（优先级靠后）：用户在方案里自由逛时，若能看到「这题是你今天计划要做的」，能把两条路轻轻缝起来，避免两个入口像割裂的两个世界。一个小标签，一致性收益不小。

## 留给 v2 的信号（现在不做）

「顺延」如果长期堆积，本质是**计划难度与用户真实节奏不匹配**的信号。未来可以用它来做「自动帮用户调整计划强度」，这是一个很自然的智能 / 付费卖点。但那是 v2 的事，第一版只需保证顺延被中性、诚实地呈现即可。

## 交互修订 v2（2026-07-07）

第一版落地后，实际交互暴露出一个问题：**首页和方案详情页各自铺了一份题目列表，两套「点题目 → 进聊天」的入口并存**，导致首页被迫承担执行页的重量，而它本该是高频的轻入口。本次修订收敛这一点。

### 修订动机

- **首页不该铺题目**：首页是每天来的高频入口，应「打开即知今天要不要练、练多少」，而不是把题目行整片铺开。铺题让首页和方案详情页重复，也让首页变重。
- **题目列表能力只保留一处**：题目列表（点题进聊天）作为一种产品能力，全项目只应存在于**方案详情页**。首页和方案列表只提供**快捷入口**，不重新实现列表。
- **入口便捷，但不改变大的使用体验**：用户从首页/列表跳进去看到的，和他自己进方案页看题的心智完全一致——入口是捷径，终点是同一个方案详情页。
- **进度和节奏属于执行上下文**：路线进度、预计学完日、本周节奏、「正常推进 / 有风险」这类状态，以及「调整节奏」动作，用户最需要看到它们的时刻是准备开练、刷完一包或顺延堆积时。因此它们应放在**今日题包视图**，不放在方案全局题目视图里。

### 三层结构（修订后）

| 层 | 呈现 | 入口行为 |
| --- | --- | --- |
| 首页 `/` | **纯入口 + 概览**：概览卡展示「计划名 · 节奏(N题/天) · 今日状态一行摘要」+ 主按钮「开始今日训练」；**不铺题目行，不承载路线进度 / 本周节奏 / 调整节奏** | 主按钮 → 方案详情 `?pack=today` 视图 |
| 方案列表 | 计划列表 | 激活行：👁 眼睛 → 详情·全局视图；新增「今日题包」按钮 → 详情 `?pack=today`。非激活行只有眼睛 |
| 方案详情 | 按 URL 参数渲染：带 `?pack=today` → 今日题包视图；否则 → 全局题目视图。**页面本身不承载视图切换控件**；全局题目视图只承担阶段/题目浏览与自由练习，不展示路线进度、本周节奏和调整节奏 | 不新增页内入口 |

心智模型不变：**想被安排 → 从首页/列表的「今日题包」入口进；想自己逛 → 从眼睛进全局。** 差别只是「切视图」这个低频动作由**入口**决定，而不是在详情页内放分段控件。

### 关键决策与理由

1. **首页概览只给数字/状态，不铺题目**
   - 有激活计划：一行摘要，如「今天 3 题待做（含顺延 1 题）」或「今天已收工 ✅」，主按钮「开始今日训练」跳 `/learning-plans/{激活计划id}?pack=today`。
   - 题目行不出现在首页。

2. **去掉「一键生成并激活推荐计划」**
   - 面向付费用户的产品，开局塞一个通用套餐计划是鸡肋：用户没做任何选择却凭空多出一条计划，制造垃圾数据。移除自动生成。
   - **但空态不做成死路**：无激活计划时，首页空态 = 一句中性说明 + 一个**指向方案页的轻引导**（如「还没有采用中的计划，去方案页创建或采用一个 →」）。不替用户做决定，只告诉他下一步去哪。这也顺带覆盖「有计划但都未激活」的情况。
   - 这与被移除的「一键生成」本质不同：前者替用户凭空造计划，后者只做导航指引。

3. **入口只做在方案列表，详情页不加切换控件**
   - 详情页只是一个**被 URL 参数驱动的宿主**：`?pack=today` 渲染题包视图，否则渲染全局视图，UI 上不新增分段控件，保持简洁。
   - 「切视图」这个低频动作退回列表完成，代价仅是多一次返回，可接受。
   - 语义自洽：题包只绑定「当前采用」的计划，因此「今日题包」入口只在**激活行**出现；非激活行只有眼睛（全局视图）。

4. **路线进度、本周节奏和调整节奏只放在今日题包视图**
   - 今日题包页顶部在题目列表前展示执行状态：计划名、路线进度（如 `42 / 120`）、预计学完日、当前节奏（如 `3 题/天 · 每周 5 天`）、本周节奏状态（如「正常推进」「有风险」「已超前」）。
   - 「调整节奏」按钮归入这块执行状态区域。用户在看到顺延堆积、预计学完日变远或本周节奏偏紧时，可以就地调整每日题数 / 每周训练天数。
   - 方案详情的全局题目视图不展示这些状态，也不提供调整节奏。它只回答「这条路线里有什么题、我想自由刷哪题」，不承担「今天应该怎样推进」。
   - 首页只保留可扫一眼的摘要，不展示完整路线进度和节奏调整入口；需要处理节奏时，引导进入今日题包。

5. **今日题包视图不再展示「下一次训练包」预览**
   - `nextTrainingPackage` 是计划层的下一包预览，和按日期实时计算出的今日题包容易在当天指向同一批题；同时展示会让用户感觉重复。
   - 今日题包视图只展示真实计算出的「顺延 / 今天 / 未来」题包列表；如果用户提前领未来题包，用题包日期标签说明它属于哪一天，而不是再叠一块「下一次训练包」。

### 落地范围（前端为主，后端尽量复用）

- 将现有 `TodayPackPage` 主体抽为可复用的 `TodayPackPanel` 组件（路线进度、预计学完日、本周节奏、调整节奏、顺延/今天分段、到此为止/再来一包、清账重来、看未来题包），供方案详情页在 `?pack=today` 时渲染；不要在题包视图里复用展示 `nextTrainingPackage` 的计划预览块。
- 首页 `/` 从 `TodayPackPage` 换为轻量入口组件：调用首页专用的轻量概览接口，只取概览数字与激活计划信息；**移除冷启动的「一键生成并激活」卡**，空态改为指向方案页的引导。
- 方案详情页解析 `?pack=today` query，据此在题包视图 / 全局视图之间二选一渲染；页面本身不放切换控件；全局视图移除路线进度、本周节奏和调整节奏区域。
- 方案列表激活行新增「今日题包」入口按钮，跳详情 `?pack=today`；眼睛按钮维持跳全局视图。
- 后端优先复用现有计划详情中的进度 / 节奏计算；如果 `getTodayPack` 当前不返回路线进度、预计学完日、节奏状态和调整节奏所需字段，则只在今日题包响应上补充这些执行态字段，不把方案全局视图作为展示宿主。

### 接口分层（2026-08-20）

- `GET /api/today-pack?timezone=...&packOffset=...`：题包详情接口，仅供方案详情中的 `?pack=today` 视图使用。返回分段、题目元数据、顺延提示和未来题包日期，支持通过 `packOffset` 查看未来题包。
- `GET /api/today-pack/home-summary?timezone=...`：首页入口接口。仅返回本地日期、训练状态、待做题数、下一题包日期、激活计划的节奏摘要，以及无激活计划时的引导摘要；不返回题目分段、题目内容、标签、`packOffset`、激活时间或推荐模板标识。
- 两个接口使用相同的排程和完成状态判定规则。首页概览接口不构造题目分段或题目响应对象，避免首页加载时传输和序列化完整题包。
