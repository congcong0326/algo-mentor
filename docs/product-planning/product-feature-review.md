# Algo Mentor 产品功能盘点与价值评估

> 视角：产品经理复盘
> **定位前提（已校准）**：`algo-mentor` 是一款**面向公开市场、以商业化变现为目标的 AI 算法学习产品**——目标是推广给真实用户使用，并让他们产生**付费意愿**。
> 因此本文档的价值标尺是：**这个功能是否能帮助获客、留存、转化付费，或是否是支撑规模化运营/控制成本的必要基建。** 而非「单人自用够不够」。
> 结论为主观评估，供迭代优先级与商业化排期参考。

---

## 一、当前已完成功能盘点

项目已交付一条**相当完整的端到端学习闭环**，并且已经具备不少「多用户规模化运营」所需的平台能力。主要模块如下。

### 1. 学习计划（核心闭环起点）
- AI 流式生成学习计划草案：目标 / 时长 / 难度 / 主题偏好，多轮澄清后生成分阶段计划。
- 计划确认、列表、详情、删除。
- 分阶段（phase）推荐题目，每题附「为什么推荐」的个性化理由。
- 计划扩展：基于当前进度 AI 生成扩展阶段，支持多轮修订、应用、放弃。

### 2. 题目训练工作台（核心闭环主场）
- 训练会话创建 / 复用 / 消息历史。
- 流式 AI 讲解对话（SSE），题面 seed 注入、上下文动态拼装。
- 进度状态管理（NOT_STARTED / IN_PROGRESS / COMPLETED / SKIPPED）。
- LeetCode 外链、题面本地化。

### 3. 代码 Review（核心差异化能力）
- `submit_practice_code_review` 触发结构化评分：正确性 / 复杂度 / 边界 / 代码质量 / 问题贴切度。
- Review 历史版本、详情、改进建议。
- 完成门槛（completion gate）：Review 评分达标才算完成。

### 4. 题库
- 搜索 / 筛选（关键词、难度、标签、分类）/ 分页。
- 题目详情（题面、样例、模板、多语言 i18n）。
- Agent 查题工具：`search_problems` / `get_problem_statement` / `list_problem_filters`。

### 5. 能力画像
- 基于做题进度与 Review 评分计算多维能力分，雷达图展示。

### 6. Agent 运行时（支撑性基础设施）
- Agent loop、工具调用、结构化输出、SSE 流式。
- 多轮上下文召回与压缩、大结果 blob 化。
- 会话/run 全链路持久化。
- 人在回路工具权限门禁。

### 7. AI 治理 / 平台能力
- 准入控制（功能开关、登录态、权限、请求大小、**日配额**、**并发锁**）。
- run 生命周期审计（ADMITTED / RUNNING / COMPLETED / FAILED …）。
- 幂等键 + Task 级互斥锁防重复/并发。

### 8. 账号与偏好
- 密码注册 / 登录 / 当前用户 / 登出，基于权限的路由守卫。
- 管理员用户管理（列表、禁用、恢复、删除、权限）。
- AI 教练风格偏好、主题切换、中英文 i18n。

### 9. 开发者工具
- AI Debug 控制台。

## 二、高价值功能（构成付费理由，应持续加码）

在商业化语境下，「用户为什么愿意付费」的答案必须集中在**别处替代不了的学习效果**上。以下功能是产品的核心价值主张与差异化护城河。

| 功能 | 价值 | 商业化理由 |
|---|---|---|
| **AI 学习计划生成 + 分阶段推荐** | ⭐⭐⭐⭐⭐ | 首要获客钩子。「一句话生成个性化刷题路径」是最直观的 aha moment，也是投放/落地页的主卖点。适合作为免费额度入口引流。 |
| **题目训练工作台 + 流式讲解** | ⭐⭐⭐⭐⭐ | 主使用场景、时长最长。做题即时问答的体验决定次日/次周留存，是订阅续费的根基。 |
| **结构化代码 Review + 完成门槛** | ⭐⭐⭐⭐⭐ | **最强付费理由**。多维评分 + 达标闭环是「有人盯着你、给你改进意见」的付费家教替代品，最容易让用户感知「值这个钱」。建议做成核心卖点并与付费额度绑定。 |
| **能力画像** | ⭐⭐⭐⭐ | 把成长可视化，是驱动续费与「舍不得走」的关键。可延伸为周报/月报，强化订阅粘性。 |
| **题库（内容资产）** | ⭐⭐⭐⭐ | 内容规模与质量是长期护城河。题库越大越精，AI 推荐/讲解才越有底气，直接影响可付费的天花板。 |
| **Agent 上下文压缩 / 持久化** | ⭐⭐⭐⭐ | 决定多轮讲解「记得住、接得上」，同时**直接压降每次对话的 token 成本**——对付费产品的毛利至关重要。 |

## 三、被重新评估为「战略资产」的平台能力（商业化下升值）

以下能力若按「单人自用」标尺看会显得过重，但在**多用户付费产品**语境下，它们是**规模化运营与守住毛利的必需基建**，应视为已提前完成的战略投入，而非鸡肋。

| 功能 | 重新评估 | 商业化价值 |
|---|---|---|
| **AI 治理层：配额 / 并发锁 / 准入 / 审计** | 🟢 战略资产 | LLM 是变动成本，**配额直接决定单用户成本上限，也天然映射到「免费 vs 付费」的分层权益**。审计支撑用量计费与滥用防护。这是付费产品的「水电表」，务必打磨好并**尽快对接到定价档位**。 |
| **幂等键 + Task 级互斥锁** | 🟢 战略资产 | 真实并发下防止重复扣费/重复 LLM 调用，是计费正确性与成本控制的底线，商业化下价值显著上升。 |
| **管理员用户管理** | 🟢 必需 | 运营真实用户必备：客服处理、封禁滥用、问题排查。建议补齐「用量/订阅状态」视角。 |
| **人在回路工具权限门禁** | 🟡 基建可留，UX 需收敛 | 面向未来「有副作用的工具」（写文件、调外部 API、消耗额度的高成本操作）是合理的安全/信任机制，也是付费用户对「AI 别乱花我的额度」的诉求。但**当前唯一受管的「代码评审」是用户主动发起的动作，每次弹窗确认反而制造摩擦**。建议：对用户显式发起的工具默认放行，把门禁保留给真正有副作用/高成本的工具。 |
| **中英文 i18n** | 🟡 升值 | 一旦考虑出海或覆盖非中文用户，i18n 是市场扩张的前置能力，从「边际」升为「增长期资产」。当前维持即可，规模化前不必扩语种。 |
| **AI 教练风格偏好** | 🟡 可产品化 | 可包装为**付费用户专属的个性化**（如更强的苏格拉底式引导、面试模拟人格），从「设置项」升级为「差异化权益」。但需先收敛为少数几种真正有感知差异的风格，否则仍是鸡肋。 |
| **学习计划扩展的多轮修订** | 🟡 复杂度对齐价值 | 「与 AI 反复打磨计划」可作为付费高级能力，但工程复杂度偏高、使用频率待验证。建议先用埋点验证真实使用率，再决定是否继续投入；免费档可只保留「一键扩展」。 |
| **AI Debug 控制台** | 🟢 内部工具 | 非面向用户的运营/调试资产，权限隔离保留即可，不算产品功能。 |

## 四、面向付费的关键缺口（当前最该补的）

要从「能用的 demo」走到「有人付费的产品」，以下缺口比继续堆功能更关键，按优先级排序。

### P0 — 变现基础设施（目前完全空白，是商业化的最大阻塞）
- **订阅 / 付费 / 计费体系**：没有支付、订阅套餐、权益（entitlement）分层、免费额度门槛、用量计量的用户侧展示。**没有这一层，「付费意愿」无法落地为收入。** 好在治理层的配额/审计已能作为计量底座，需补的是「定价档位 ↔ 权益 ↔ 支付」的打通。
- **免费/付费权益边界**：明确免费能用多少（如每日计划生成/Review 次数），付费解锁什么，并在 UI 中做好「触达上限 → 引导升级」的转化路径。

### P1 — 留存与效果（决定 LTV，直接影响续费）
- **错题本 / 间隔重复复习**（缺失）：AGENTS.md 将「错题复盘」列为核心，但目前只有 Review 历史，没有「错题沉淀 + 到期提醒 + 再练」闭环。这是学习类产品**留存与续费的核心机制**，付费用户尤其看重。
- **统一学习进度看板 / 每日任务**：缺一个「今天练什么、整体进度、连续天数、待复习」的回访入口，直接影响 DAU 与订阅粘性。
- **真实判题 / 代码运行**（缺失）：当前「正确性」维度依赖 LLM 判断。接入真实测试用例执行，能把 Review 可信度从「AI 觉得对」升级为「真的跑通」，**显著增强付费说服力**。

### P2 — 获客与增长
- **Onboarding 引导 / Aha 时刻前置**：新用户首访能否在 1–2 分钟内体验到「生成计划 + 一次讲解/Review」的爽点，决定注册转化。
- **分享 / 裂变**：学习报告、能力提升、连续打卡的可分享物料，是低成本获客渠道，目前缺失。
- **内容护城河**：持续扩充与打磨题库/题解质量，是可付费天花板的根本来源。

### P3 — 运营可观测
- **业务指标看板**：注册→激活→付费漏斗、留存曲线、单用户 LLM 成本/毛利。技术侧 Micrometer 已有基础，需补「商业指标」维度以支撑运营决策。

## 五、结论与优先级建议

**一句话总结**：项目在「学习闭环」和「平台基建」两条线上都已相当扎实——尤其治理/配额/审计这些平台能力，在商业化语境下从「过度设计」升级为「提前铺好的变现底座」。但产品目前**卡在从「好用」到「可收费」之间**，缺的不是更多功能，而是把已有价值**变现和留存**的那几块拼图。

- **继续加码（付费理由）**：学习计划、训练讲解、代码 Review、能力画像、题库内容。
- **立即补齐（变现阻塞，P0/P1）**：订阅计费 + 权益分层、错题复盘/间隔重复、进度看板、真实判题。
- **对齐商业化（把已有资产接上收入）**：将配额/审计接入定价档位；把教练风格/多轮修订包装为付费权益（先用埋点验证）；权限弹窗对用户主动动作默认放行。
- **维持不加码**：i18n（出海前不扩语种）、Debug 控制台。

> 核心判断：**技术底座已经为一个付费产品准备好了（治理、配额、审计、持久化都在），但商业化最后一公里——「计费/权益/转化」与「留存机制（错题复盘、进度看板）」——尚未动工。这才是决定「有没有人愿意付费」的关键，应作为下一阶段的绝对重点。**
