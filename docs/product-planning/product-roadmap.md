# Algo Mentor 产品形态设计与优先级路线图

> 视角：产品经理规划
> **阶段前提**：项目处于起步阶段，**暂不投入支付/计费基础设施**。本阶段目标是先把「对用户真的有帮助、用了就离不开」做实，为未来变现积累价值与口碑。
> **判断标尺**：一个功能是否让用户「学得更有效果 / 更愿意每天回来 / 更相信这里的反馈」。凡不服务这三点的，一律降优先级。
>
> 本文是路线图大纲，逐项给出「现状问题 → 目标 → 关键动作 → 成功信号」，按优先级排列。详细方案在各功能立项时再补设计文档。

---

## 一、产品定位与核心价值主张（北极星）

**一句话定位**：一个**懂你的 AI 算法教练**——为你规划路径、陪你做题讲解、审阅你的代码、并让你清楚看到自己在变强。

**差异化护城河（=未来付费理由）**：
1. **个性化路径**：不是一张通用题单，而是随你的能力动态调整的训练计划。
2. **对你代码的真实反馈**：不是标准题解，而是针对你这次提交的、可信的、可改进的点评。
3. **可度量的成长**：让「我变强了」这件事看得见、可回顾、能被自己和别人感知。

> 一切排期都服务于把这三点做到「别处替代不了」。

**核心用户旅程（目标形态）**：

```
首访 → 60 秒内生成一份属于我的计划（Aha）
  → 每天打开就知道「今天练什么 / 该复习什么」
    → 做题时随手问，AI 即时讲解（不是给答案，是带我想通）
      → 提交代码 → 真实判题 + 结构化点评 → 达标才算过
        → 错题自动进错题本，到期提醒我再练
          → 每周收到成长报告：哪些强了、哪些还弱、下周练什么
            → 「我在这里确实变强了」→ 留存 → 口碑 →（未来）付费
```

当前项目已经打通了这条链路的**中段**（计划→做题→讲解→Review），但**首尾两端（Aha 前置 / 复习闭环 / 成长可视化）**和**中段的可信度（真实判题）**是薄弱环节。路线图即围绕补强这些环节展开。

## 二、优先级路线图

### 阶段一（P0）：补齐留存闭环 + 打磨核心体验

> 目标：让产品从「能走一遍流程」变成「用户愿意每天回来」。这是当前**最该做**的一批，直接决定次日/次周留存。

#### P0-1　错题本 + 间隔重复复习（缺失，最高优先）
- **现状问题**：只有 Review 历史列表，没有「错题沉淀 → 到期复习 → 再练」的闭环。学习类产品的留存核心机制缺位。
- **目标**：做错/评分不达标/主动标记的题自动进错题本，按遗忘曲线（如 1/3/7/15 天）安排复习，首页每日提醒「今天有 N 道待复习」。
- **关键动作**：
  - 错题来源：Review 未达标、用户主动收藏、AI 判定薄弱。
  - 复习调度：间隔重复算法（SM-2 简化版即可），记录每题掌握度。
  - 复习形态：不是重看题解，而是「再做一遍 / 讲讲思路让 AI 判断你是否真懂」。
- **成功信号**：复习任务打开率、复习后同类题正确率提升、次周留存。

#### P0-2　学习进度看板 / 每日任务首页（偏薄）
- **现状问题**：有能力雷达和单计划详情，但缺一个统一的「回访入口」，用户打开不知道该干嘛。
- **目标**：登录首页即是「今日学习台」——今天练什么、待复习几道、整体进度、连续打卡天数、最近成长。
- **关键动作**：聚合当前计划的下一步 + 待复习错题 + streak；把「继续学习」做成一键入口。
- **成功信号**：DAU / 打开到开始做题的转化、连续打卡天数分布。

#### P0-3　Onboarding：把 Aha 前置到首访 60 秒
- **现状问题**：新用户首访缺少引导，价值感知延迟。
- **目标**：注册后（甚至注册前）用最短路径体验一次「生成计划 + 一次讲解或 Review」，让用户第一次就「哇」。
- **关键动作**：极简目标输入 → 秒出计划预览 → 引导做第一道题并触发一次 AI 讲解/点评；首个成功体验前不设过多门槛。
- **成功信号**：注册→激活（完成首个 Review/讲解）转化率、首访时长。

#### P0-4　工具权限交互瘦身（不足优化）
- **现状问题**：唯一受管的「提交代码 Review」是用户**主动发起**的动作，却每次弹窗确认，制造摩擦、打断心流。
- **目标**：用户显式发起的工具默认放行，「提交 Review」做成一键、无弹窗；权限门禁机制保留给未来真正有副作用/高成本的工具。
- **关键动作**：区分「用户主动动作」与「Agent 自主副作用动作」，仅后者走确认链路。
- **成功信号**：Review 提交完成率、单次做题的操作步数下降。

### 阶段二（P1）：强化「效果可信」与「个性化」——把付费理由做硬

> 目标：让用户**相信**这里的反馈、**感觉**到它真的懂自己。这是从「有用」到「值得付费」的关键跃迁。

#### P1-1　真实判题 / 代码运行（缺失，可信度关键）
- **现状问题**：「正确性」维度依赖 LLM 判断，说服力有限（用户会怀疑「AI 真的看懂了吗」）。
- **目标**：接入沙箱执行 + 测试用例，把「正确性」从「AI 觉得对」升级为「真的跑通 N/M 用例」。Review 里同时给出「客观通过率 + AI 定性点评」。
- **关键动作**：
  - 沙箱执行环境（安全隔离、超时、资源限制），先支持 1–2 种主流语言（如 Python/Java）。
  - 用例数据接入题库；结果反哺 Review 评分与完成门槛。
- **成功信号**：用户对 Review 结果的信任度（可调研）、达标判定争议率下降。
- **备注**：这是投入较大的一项，但对「付费说服力」不可替代，值得中期重点投入。

#### P1-2　计划随能力动态调整（个性化闭环）
- **现状问题**：计划生成后基本静态，调整靠用户手动扩展；「个性化」停留在生成时刻，之后不再进化。
- **目标**：基于能力画像与做题/复习表现，主动提示「这块薄弱，建议补练」/「该升难度了」/「这段可以跳过」，让计划活起来。
- **关键动作**：把能力画像与错题信号接入计划推荐；用「建议卡片」形式让用户一键采纳，而非强制改计划。
- **成功信号**：建议采纳率、采纳后薄弱项能力分提升。

#### P1-3　从「题目维度」深化到「知识点/技能维度」（内容深度）
- **现状问题**：当前主要是「计划→题目」，缺少概念层。算法学习真正的掌握是**知识点掌握**（如二分、DP、图论），而非刷够题数。
- **目标**：引入知识点体系，能力画像与讲解都挂到知识点上——「你在『区间 DP』上还弱，这是讲解卡 + 3 道针对题」。
- **关键动作**：为题库打知识点标签；沉淀轻量知识点卡片（可 AI 生成 + 人工校）；能力画像按知识点聚合。
- **成功信号**：知识点掌握度覆盖、按知识点补练的使用率。呼应 AGENTS.md 的「知识沉淀」目标。

#### P1-4　AI 教练风格收敛并做出真实差异（不足优化）
- **现状问题**：5 种风格感知差异小，接近摆设。
- **目标**：收敛为少数**真正影响教学方式**的模式，如「引导式（苏格拉底，不直接给答案）」vs「直给式（快速讲透）」，并可按场景自动切换（卡住太久自动多给提示）。
- **关键动作**：把风格落到 prompt 策略与提示节奏上，而非只是措辞；默认智能自适应。
- **成功信号**：讲解满意度、「被带着想通」而非「直接抄答案」的比例。

### 阶段三（P2）：增长、护城河与运营可观测

> 目标：在核心价值做实后，放大触达、加厚内容壁垒，并为未来商业化决策准备数据。

#### P2-1　成长报告 + 可分享物料（增长 + 留存）
- **目标**：每周自动生成成长报告（练了多少、强了哪些、连续打卡、下周计划），并做成可分享卡片。既强化「我在变强」的粘性，又是低成本获客渠道。
- **成功信号**：报告打开率、分享率、分享带来的新注册。

#### P2-2　面试模拟 / 场景化训练（高价值差异功能）
- **目标**：基于已有对话与 Review 能力，做「限时模拟面试」——出题、追问、复盘表现，直击目标用户（求职/跳槽）最强付费动机。
- **成功信号**：模拟面试使用率、完成后继续训练的转化。
- **备注**：天然适合作为未来**付费高级能力**，本阶段先验证需求。

#### P2-3　内容护城河：题库规模与题解质量
- **目标**：持续扩充题库、补充高质量题解/知识点卡片。内容质量是 AI 推荐与讲解的上限，也是长期壁垒。
- **成功信号**：题库覆盖度、讲解/推荐命中满意度。

#### P2-4　业务指标可观测（为未来变现决策铺路）
- **目标**：在已有 Micrometer 技术指标之上，补「商业维度」：注册→激活→留存漏斗、连续打卡分布、**单用户 LLM 成本**。虽不做支付，但要能回答「哪些用户最活跃、成本几何、谁最可能付费」。
- **成功信号**：能用数据回答「产品是否真的在帮到用户、单位成本是否可持续」。

## 三、现有平台能力：保持，但对齐未来（不加码、不浪费）

以下能力已完成且在商业化语境下是资产，**本阶段不投入新功能，仅维持并顺手对齐未来**：

- **AI 治理（配额 / 并发锁 / 准入 / 审计）**：保留。它是未来「免费/付费分层」和成本控制的现成底座；本阶段仅用作**成本护栏 + 用量计量**，先跑通「每用户用了多少」的数据。
- **幂等键 + 互斥锁**：保留，保障并发正确性。
- **Admin 用户管理**：保留，运营真实用户所需；顺手补「用量/活跃」视角即可。
- **i18n**：维持中英文，出海前不扩语种。
- **AI Debug 控制台**：内部工具，权限隔离保留。
- **学习计划扩展的多轮修订**：先埋点验证真实使用率再决定去留；免费路径可只保留「一键扩展」，避免复杂交互拖慢主线。

## 四、优先级一览（速览）

| 优先级 | 事项 | 类型 | 解决的核心问题 |
|---|---|---|---|
| **P0** | 错题本 + 间隔重复复习 | 补缺失 | 留存机制缺位 |
| **P0** | 每日学习台 / 进度看板 | 补缺失 | 缺回访入口 |
| **P0** | Onboarding，Aha 前置 | 补缺失 | 价值感知太慢 |
| **P0** | 工具权限交互瘦身 | 优化不足 | 主动动作被弹窗打断 |
| **P1** | 真实判题 / 代码运行 | 补缺失 | 反馈可信度不足 |
| **P1** | 计划随能力动态调整 | 优化不足 | 个性化只在生成时刻 |
| **P1** | 知识点/技能维度深化 | 补缺失 | 只有题目层，缺掌握度 |
| **P1** | 教练风格收敛做出真差异 | 优化不足 | 风格接近摆设 |
| **P2** | 成长报告 + 可分享 | 补缺失 | 增长 + 粘性 |
| **P2** | 面试模拟 | 新增差异功能 | 强付费动机场景 |
| **P2** | 题库/题解内容建设 | 加厚护城河 | 价值天花板 |
| **P2** | 业务指标可观测 | 补缺失 | 无商业数据支撑决策 |

## 五、北极星指标与阶段里程碑

- **北极星指标建议**：**「周活跃学习者中，完成 ≥3 次达标 Review 或复习的人数」**——它同时衡量「有没有人用」「用得深不深」「是否真的在练」，比单纯 DAU 更贴近价值。
- **阶段里程碑**：
  - 阶段一验收：新用户激活率、次周留存、每日复习任务打开率达到内部基线。
  - 阶段二验收：真实判题上线、用户对 Review 信任度提升、计划建议采纳率可观测。
  - 阶段三验收：具备成长报告与商业指标漏斗，能用数据判断「是否具备开启付费的时机」。

> 核心原则：**先把「让人变强、离不开、且相信」做到位，付费是水到渠成的结果，而不是起点。** 本阶段不碰支付，但每一步都在为「有人愿意付费」积累筹码。
