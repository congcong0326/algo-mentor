> - `docs/product-feature-review.md`（功能价值评估）

## 0. 定位锚点（一切排期的标尺）

- **产品定位**：面向公开市场、目标付费的 **AI 算法教练**；起步期不做支付，先把「有效果、有粘性、可信」做实。
- **核心价值主张**：一个懂你、盯着你、能证明你在变强的教练 —— **个性化路径 + 对你代码的教练式反馈 + 可度量的成长**。
- **与 LeetCode 的分工（重要，替代真实判题的定位）**：
  > **LeetCode 判「对不对」（AC），Algo Mentor 判「好不好 + 懂没懂」（思路/复杂度/边界/代码质量/是否真理解）。**
  我们不做判题，而是做 LeetCode 不做的教练部分。这既省掉自建测试集的重活，又是清晰的差异化。
- **最优先人群**：① 校招求职（大基数、强付费）+ ② 社招跳槽（高 ARPU）。③ 转码次之。④⑤⑥ 不作付费主攻。
- **一票否决原则**：**防「抄答案幻觉」**。凡是让用户「看似学会、实则不会」的设计一律不做——这是产品能否「真有帮助」进而值得付费的底线。

## 1. 目标产品形态：双入口，而非单一长计划

当前产品过度 plan-centric，只服务「有时间上多周计划」的人，漏掉了付费意愿最强的社招/冲刺群体。目标形态是**两种入口并存**，共用底层题库 / 推荐 / 讲解 / Review / 能力画像：

- **系统学习模式（已有，长计划）**：面向时间充裕的新手/学生，AI 生成分阶段计划、按路径推进。
- **冲刺模式（新增）**：面向社招②与临面试的求职①，跳过长计划配置，直接「高频考点题单 / 按主题速练 / 我哪弱补哪」，几分钟内开练。

> 长计划是给新手的入口，不该是所有人的必经之路。

## 3. P0 —— 校准核心体验 + 补留存闭环（立即启动）

> 建议按下列顺序推进：先低成本高杠杆的体验校准（3.1、3.2、3.6），再补留存重头（3.3、3.4），最后 3.5。

### 3.1 引导式教练默认（防抄答案）— 最先做，改动集中、价值最高
- **目标**：AI 讲解默认「苏格拉底式」——先问思路、给分层提示，卡太久才逐步加提示，不直接甩答案；「直给」仅作为用户显式选择或长时间卡死后的兜底。
- **关键动作**：改造题目训练场景的 prompt 策略与提示节奏（非仅措辞）；把「教练风格」从摆设升级为真正影响教学方式的开关（先内置「引导/直给」两档，默认引导）。
- **涉及代码**：`mentor-application/.../practice/PracticeChatPromptSectionProvider.java`、practice system prompt 组装、`user_ai_preference`。
- **成功信号**：讲解满意度；「被带着想通」而非「直接抄」的比例（可通过是否在讲解后独立提交代码衡量）。

### 3.2 代码 Review 定位重构（替代真实判题，保住完成门槛的意义）
- **目标**：明确 Review = 「教练式质量点评」而非「对错裁判」。完成门槛 = **用户回填「已在 LeetCode 通过」**（诚信自报 + 一键跳转外链核对）**＋ 我们的质量 Review 达标**。
- **关键动作**：
  - Review 结果页/工作台增加「我已在 LeetCode 通过」回填（配合已有 LeetCode 外链）。
  - 完成门槛（completion gate）取「AC 已回填 AND 质量 Review 达标」；文案上诚实说明「正确性以 LeetCode 为准，这里帮你把代码写得更好」。
  - Review 评分维度弱化「正确性权威」，强化思路/复杂度/边界/可读性等教练维度。
- **涉及代码**：`PracticeCompletionGateService`、`PracticeCodeReviewService`、`practice_code_review` schema、`PracticeChatWorkbench.tsx`、`ReviewDetailPanel.tsx`。
- **成功信号**：Review 完成率、用户对「反馈有用」的认可度、达标判定争议下降。

### 3.3 每日学习台 / 进度看板首页（回访入口）
- **目标**：登录首页即「今日学习台」——今天练什么、待复习几道、整体进度、连续打卡（streak）、最近成长。
- **关键动作**：聚合「当前计划下一步 + 待复习错题 + streak」，做一键「继续学习」。
- **涉及代码**：新增首页聚合 API（复用 learning plan / progress / ability）、前端 `HomeDashboard.tsx` 升级为认证后的学习台。
- **成功信号**：DAU、打开→开始做题转化、连续打卡天数分布。

### 3.4 错题本 + 间隔重复复习（留存核心，当前完全缺失）
- **目标**：做错/Review 不达标/主动标记的题自动进错题本，按遗忘曲线（如 1/3/7/15 天）安排复习，首页提醒「今天有 N 道待复习」。
- **关键动作**：
  - 错题来源：Review 未达标、用户收藏、AI 判定薄弱。
  - 调度：SM-2 简化版，记录每题掌握度。
  - 复习形态：**再做/讲思路让 AI 判断是否真懂**，而非重看题解（呼应防抄答案）。
- **涉及代码**：新增 `mistake_note` / `review_schedule` 迁移与 practice 模块服务、前端错题本页 + 首页复习入口。
- **成功信号**：复习任务打开率、复习后同类题表现提升、次周留存。

### 3.5 Onboarding：把 Aha 前置到首访 60 秒
- **目标**：注册后用最短路径体验一次「生成计划或选一个冲刺题单 + 一次讲解/Review」，第一次就「哇」。
- **关键动作**：极简目标输入 → 秒出预览 → 引导做第一道题并触发一次讲解/点评；首个成功体验前不设多余门槛。
- **涉及代码**：`LearningPlanCreatePage`/首页新用户引导、前端 onboarding 流。
- **成功信号**：注册→激活（完成首个讲解/Review）转化率、首访时长。

### 3.6 工具权限交互瘦身（顺手小改）
- **目标**：用户显式发起的「提交 Review」一键无弹窗；权限门禁保留给未来真正有副作用/高成本的工具。
- **关键动作**：区分「用户主动动作」与「Agent 自主副作用动作」，仅后者走确认链路。
- **涉及代码**：`PracticeCodeReviewPermissionHook`、`AgentToolPermissionController`/hook chain、`PracticeChatWorkbench.tsx` 权限弹窗逻辑。
- **成功信号**：Review 提交完成率、单次做题操作步数下降。

## 4. P1 —— 深化个性化 + 上冲刺模式（抓最高付费群体）

### 4.0 知识聚合层 / 内容中台（事实底座，先于冲刺模式与模拟面试）

这是让「冲刺模式、模拟面试、计划推荐」都更**有事实依据**的底层内容资产。落到 AGENTS.md 既定的独立 worker（`题目导入` / `向量索引` / `内容同步`）。分两块，按价值/成本排序：

**A. 公司维度题目元数据（高价值、低成本，先做）**
- **目标**：导入公开的「公司 × 题目 × 频率（近 30/60/90 天 + 历史）」元数据，作为**内部选题/排序信号**，不对外分发题面。支撑：冲刺模式题单（「字节高频」「大厂高频 100」）、模拟面试按目标公司加权出题、计划推荐同等条件下优先高频题。
- **数据来源（参考）**：`liquidslr/leetcode-company-wise-problems`（更新至 2025-06，较新）、`hxu296/leetcode-company-wise-problems-2022` 等公开仓库的 CSV/元数据。
- **关键动作**：
  - 新增 `题目导入` worker，定期拉取并归一化到题库：题目 slug 对齐现有 `problem`，扩展 `company_tag` / `frequency` / `recency_bucket` 维度。
  - 只存**事实性元数据 + 指向 LeetCode 的外链**；实际做题跳转 LeetCode（与「判对错交给 LeetCode」一致）。
- **涉及代码**：新增导入 worker 模块、`problem` 相关 schema 扩展（公司/频率标签）、推荐与题单查询接入该维度。
- **成功信号**：公司高频题单覆盖度、冲刺/模拟面试用到该数据后的可信度与使用率。

**B. 攻略 RAG 知识库（中价值、中成本，稍后做）**
- **目标**：对热门刷题攻略做 RAG，作为**内部 grounding**，让计划阶段划分、知识点顺序、讲解结构更合理；不照搬内容，用其作参考结构并生成我们自己的原创讲解，注明出处。
- **数据来源（参考）**：`youngyangyang04/leetcode-master`（代码随想录，中文系统学习攻略）等高星题解/攻略仓库。
- **关键动作**：新增 `向量索引` worker，构建攻略/知识点向量库；计划生成与知识点卡（4.3）检索该库作为 grounding 上下文。
- **涉及代码**：向量索引 worker、知识库 schema、`LearningPlanAgentService` / 知识点卡生成接入 RAG 上下文。
- **成功信号**：计划推荐合理性（可调研/对比）、讲解质量、知识点卡采纳率。

> **合规红线（必须遵守）**：LeetCode Premium **题面**受 LeetCode 版权保护，攻略仓库（如代码随想录）各有 License 且多数限制商用。**可用**：公司/频率/标签/题目列表等事实性元数据、作为内部检索 grounding 的引用；**不可**：对外分发受版权保护的题面或他人题解原文。RAG 输出须为我方原创并注明来源。选题引用 Premium 题目时只给标签与外链，不复制题面。

### 4.1 冲刺模式入口（结构性缺口，性价比最高）
- **目标**：面向社招②与冲刺①，提供「高频考点题单 / 按主题速练 / 按薄弱补练」，跳过长计划配置直接开练。
- **关键动作**：内置若干高频题单（如「大厂高频 100」「按主题速通」「按目标公司」）；入口与系统学习模式并列；复用现有题库、推荐、讲解、Review。
- **依赖**：题单质量依赖 **4.0-A 公司维度题目元数据**（用公司/频率信号选题排序）；建议 4.0-A 与本项一并或稍前推进。
- **涉及代码**：题单数据（可先人工整理 seed）+ 题库/推荐复用、前端新增冲刺入口与题单页。
- **成功信号**：冲刺模式使用占比、冲刺用户的做题量与留存。

### 4.2 计划 / 练习随能力动态调整（查漏补缺）
- **目标**：基于能力画像与错题信号，主动「建议卡片」——「这块弱，建议补练」/「该升难度」/「这段可跳过」，一键采纳而非强制改计划。
- **涉及代码**：`AbilityProfileService` + 错题信号接入推荐；前端建议卡片。
- **成功信号**：建议采纳率、采纳后薄弱项能力分提升。

### 4.3 知识点 / 技能维度深化（系统性）
- **目标**：从「计划→题目」深化到「知识点掌握」——能力画像与讲解挂到知识点（二分、DP、图论…），「你在『区间 DP』弱，这是讲解卡 + 3 道针对题」。
- **关键动作**：题库打知识点标签；沉淀轻量知识点卡片（AI 生成 + 人工校）；能力画像按知识点聚合。
- **涉及代码**：题库标签 schema、`ability` 聚合、知识点卡内容。
- **成功信号**：知识点掌握覆盖、按知识点补练使用率。呼应「知识沉淀」目标。

## 5. P2 —— 战略差异化 + 增长 + 数据

### 5.1 面试模拟（战略功能，核心稳固后即启动）
- **目标**：限时模拟面试——出题、追问、复盘表现，直击②社招 + 冲刺①最强痛点，天然的差异化与（未来）付费卖点。**支持「按目标公司」出题**，让模拟更贴近真实面试。
- **关键动作**：复用对话与 Review 能力，先做轻量版（限时出题 + 追问 + 表现复盘报告）；按目标公司出题依赖 **4.0-A 公司维度题目元数据**加权抽题。
- **成功信号**：模拟使用率、完成后继续训练转化。

### 5.2 成长报告 + 可分享物料（增长 + 留存）
- **目标**：每周自动成长报告（练了多少、强了哪些、打卡、下周计划），做成可分享卡片，既强化粘性又低成本获客。
- **成功信号**：报告打开率、分享率、分享带来的新注册。

### 5.3 内容护城河（持续进行）
- **目标**：以 **4.0 知识聚合层**为核心持续经营内容——扩充公司维度元数据的覆盖与新鲜度、丰富攻略/知识点 RAG 库、补高质量原创题解与知识点卡片。内容质量是 AI 推荐与讲解的上限，也是长期壁垒。
- **说明**：4.0 是「把内容资产建起来」，5.3 是「持续维护与加厚」，二者是同一支柱的建设期与运营期。

### 5.4 业务指标可观测（为未来变现备数据）
- **目标**：在 Micrometer 技术指标上补「商业维度」：注册→激活→留存漏斗、打卡分布、**单用户 LLM 成本**。不做支付，但要能回答「谁最活跃、成本几何、谁最可能付费」。

## 6. 明确不做 / 维持不加码

| 项 | 决策 | 说明 |
|---|---|---|
| **真实判题 / 代码运行** | ❌ 不做 | 无完整测试集、工作量大、非定位；判题引导去 LeetCode（界面已有外链），完成门槛用「用户回填 AC + 质量 Review」替代。 |
| 支付 / 计费基础设施 | ⏸ 暂缓 | 起步期不做；治理层配额/审计先当「成本护栏 + 用量计量」，为将来分层付费留底座。 |
| AI 治理（配额/并发/审计）、幂等锁、Admin、i18n、Debug 控制台 | 🟢 维持 | 已完成的资产，本阶段不加新功能，仅维持并顺手对齐未来（如 Admin 补用量视角）。 |
| 学习计划扩展多轮修订 | 🟡 观望 | 先埋点验证使用率再决定去留；免费路径可只留「一键扩展」。 |
| 分发受版权题面/他人题解原文 | ❌ 红线 | 见 4.0 合规红线：Premium 题面与攻略原文不可对外分发；只用事实性元数据 + 内部 grounding + 我方原创 + 注明来源。 |
| 教练风格 5 档 | 🔧 收敛 | 并入 3.1，收敛为「引导/直给」两档且默认引导。 |

## 8. 北极星指标与里程碑

- **北极星指标**：**周活跃学习者中，完成 ≥3 次「达标 Review 或复习」的人数** —— 同时衡量有没有人用、用得深不深、是否真在练。
- **里程碑**：
  - **P0 验收**：新用户激活率、次周留存、每日复习任务打开率达到内部基线；讲解默认引导式已上线。
  - **P1 验收**：冲刺模式上线并被使用；能力驱动的建议可观测、采纳率有数据。
  - **P2 验收**：面试模拟上线；具备成长报告与商业指标漏斗，能用数据判断「是否到了开启付费的时机」。

> 核心原则：**先服务好「有 deadline、要拿 offer」的人——用「冲刺题单 + 引导式教练 + 质量 Review + 模拟面试」直击他们的 ROI，并用错题复盘与成长可视化把他们留住。判对错交给 LeetCode，判好坏和懂没懂由我们来做。这就是值得付费的根基。**
