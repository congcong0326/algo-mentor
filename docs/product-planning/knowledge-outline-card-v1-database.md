## 迁移文件

- `backend/mentor-api/src/main/resources/db/migration/V72__knowledge_outline_card_schema.sql`：建立大纲节点、共享卡片、可选文章、用户调度状态、评价流水共 5 张表，包含外键、唯一约束、CHECK 和读取索引。

V73 seed 脚本已按当前阶段要求删除。V72 接续全局 V71，由应用现有 Flyway 配置执行，执行后五张表均为空，不预建 root、节点、卡片、文章或用户数据。内部 root 由后续数据库内容导入事务建立，应用启动和用户 GET 均不写入初始化数据。

## 具体约定

- 节点 slug 最多 220 字符，节点和文章标题最多 200 字符；问题最多 500 字符，核心回答最多 20000 字符。上述必填文本拒绝空白值。
- 新建内容默认 DRAFT。文章发布必须填写发布时间，文章草稿可以先保存空正文。
- 共享内容外键限制删除；用户删除级联清理个人状态与流水。
- 用户状态的调度值、到期时间和最后评价信息必须显式传入，没有自动入队的默认值。短期学习允许 memory 字段为空。
- 唯一部分索引保证最多一个 ROOT；DDL 不创建 root。创建/移动节点无环及根节点维护限制由受控导入流程负责；祖先发布可见性、流水归属、首次评价原子事务及幂等冲突处理由后续服务层实现；DDL 不代替这些业务校验。
- 本次不涉及配置变更、Java/API 或前端实现。

## 验证与执行边界

此前验证记录（V73 已删除，不作为当前初始化方案）：在独立临时 PostgreSQL 16 实例中通过 `psql -v ON_ERROR_STOP=1` 依次执行现有 V8 认证表迁移、V72 和 V73，全部成功。随后执行事务内断言，验证：

- 单一 root、普通节点必须有父节点、同级 slug 唯一及父节点删除限制；
- 空白问题、超长回答、非法发布状态被拒绝；
- 用户卡片唯一、必填最近评价、非法 FSRS 状态/评级和负计数被拒绝；
- 同一用户的评价幂等键唯一，不同用户可使用相同 UUID；
- 快照只接受 JSON 对象；已有用户状态的卡片不能删除，归档保留历史；
- 删除一个用户清理其状态与流水，不影响其他用户；
- 初始化内容数量正确，未评价时用户状态和流水均为空。
