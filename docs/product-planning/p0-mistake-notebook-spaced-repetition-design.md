## 1. 为什么做（定位锚点回填）

- **命中痛点 P6「学了就忘」**，是留存闭环里当前**完全缺失**的一块，属于 P0 留存核心。
- **北极星贡献**：北极星是「周活跃中完成 ≥3 次达标 Review 或**复习**的人数」，复习任务直接是分子的一半。
- **一票否决原则对齐**：错题复习最容易退化成「重看题解 → 看似会了」的抄答案幻觉。本设计从机制上把复习做成**先自己想通、AI 判是否真懂**，而不是重放答案。

## 2. 竞品借鉴与差异化

| 维度 | leetreviewer 的做法 | 我们借鉴 / 差异化 |
|---|---|---|
| 复习前动作 | **Recall the algorithm before solving**：做题前先回忆算法 | **借鉴（核心）**：复习先「复述思路」，遮住任何提示；这正是我们防抄答案的抓手 |
| 调度 | 自动安排下次复习时间（间隔重复） | 借鉴：SM-2 简化版自动排期 |
| 评级来源 | 偏用户自评 / 自我回忆感受 | **差异化**：间隔由 **AI 判定「是否真懂」** 驱动，而非纯自评——避免「自我感觉良好」的信度问题，呼应「判懂没懂由我们做」 |
| 复习卡片 | 可滑动的 recall / review 卡片（含移动端） | 借鉴：卡片式复习流；移动端滑动作为二期 |
| 导入 | 贴一个链接自动填充题目 | 我们已有题库 catalog，无需导入；错题来自练习过程自动入库 |
| 完成对错 | —— | 沿用产品定位：**判对错交给 LeetCode**，我们判「懂没懂 + 好不好」 |

**一句话差异化**：leetreviewer 帮你「记得住」，我们在「记得住」之上多做一层「**证明你真的懂**」——每次复习都要过 AI 这关，间隔才会拉长。

## 3. 核心产品理念（四条）

1. **Recall-first（先复述，后揭示）**：复习卡默认遮住题解/提示，用户先讲思路（算法选择、关键步骤、复杂度、边界），再由 AI 判定。杜绝一眼扫过答案骗自己。
2. **AI 判定驱动调度**：下次复习间隔由 AI 对「复述/重做」的判定等级决定，用户自评仅作辅助信号，不作权威。
3. **分层复习、控成本**：默认走轻量「思路复述」（judge 一次 LLM）；复述不过关或代码型题目才升级到「重做 + 代码 Review」。既保信度又控 LLM 成本。
4. **卡片可个性化生成（分层能力）**：复习卡不是一刀切的「请复述思路」，而是可以**结合用户在该题的提交历史（上次 Review 分数/错点、代码、题目难度、掌握度阶段、lapses）动态决定问什么、给多少支架**。简单题只问关键实现点（回算式），难题/顽固错题给结构化模板引导用户少写多想。这一层做成分档实现，天然是会员/免费的切面。

## 4. 错题来源（入库规则）

| 来源 | 触发 | 是否自动 | MVP |
|---|---|---|---|
| **Review 未达标** | `practice_code_review.passed = false` | 自动入库 | ✅ |
| **用户主动标记** | 题目/工作台「加入错题本 / 我还没掌握」 | 手动 | ✅ |
| **AI 判定薄弱** | 讲解/对话中 AI 判断该题理解薄弱 | 自动（建议+可确认） | 二期 |
| 反复卡住 / 超时（可选） | 单题做题时长或提示次数超阈值 | 自动候选 | 二期观察 |

规则：
- 一个 `(user, problem)` 只维护**一条**错题记录（聚合掌握度），重复触发只更新来源与「重新学习」状态。
- **Review 未达标即入库，即使已 AC**：因为我们的达标门槛是「AC 回填 AND 质量 Review 达标」，代码质量/理解不到位同样算没掌握（呼应 3.2）。
- 用户可手动**移除/归档**错题（尊重「我确实会了」）。

## 5. 复习调度（SM-2 简化版）

每条错题记录维护：`repetitions`（连续通过次数）、`ease_factor`（默认 2.5，下限 1.3）、`interval_days`、`due_at`、`mastery_state`。

### 5.1 评级（4 档，映射 SM-2 q 值）

评级由 **AI 判定为主**产出（见 §6），映射到调度：

| 用户可见档位 | q | 语义 | 调度效果 |
|---|---|---|---|
| 忘了 / 不会 | 2 | 关键思路答不出或错 | `repetitions=0`，`interval=1 天`，`lapses+1`，进入 LAPSED |
| 勉强想起 | 3 | 大方向对但漏关键点 | 间隔增长慢，EF 下调 |
| 掌握 | 4 | 思路完整、复杂度/边界基本到位 | 间隔正常增长 |
| 秒懂 / 熟练 | 5 | 干脆利落、无遗漏 | 间隔增长快，EF 上调 |

### 5.2 间隔计算

```
若 q < 3（忘了）:        repetitions = 0; interval = 1 天
否则:
  repetitions == 0 →     interval = 1 天
  repetitions == 1 →     interval = 3 天
  repetitions >= 2 →     interval = round(interval_prev × ease_factor)
EF' = EF + (0.1 - (5-q) × (0.08 + (5-q) × 0.02))，clamp 到 [1.3, +)
due_at = now + interval 天
```

- **毕业（MASTERED）**：`interval_days ≥ 30` 且 `repetitions ≥ 3` → 标记已掌握，转低频巡检（如 60/120 天）或从待复习队列淡出，仍保留在错题本「已掌握」分组。
- **首个间隔梯度**参考大纲的 1/3/7/15：由 EF 自然逼近（1 → 3 → ~7 → ~17…），不写死。

> 冷启动实现可先用固定梯度 `1/3/7/15/30`，跑通后再切到带 EF 的 SM-2 精细版，两者数据结构兼容。

## 6. 复习形态与交互流程

### 6.1 两种复习模式（分层）

1. **思路复述（Recall）— 默认，低成本**
   - 卡片先只给题面摘要 + 知识点标签，**遮住上次代码与题解**。
   - 用户用文字/语音复述：用什么算法、为什么、关键步骤、时间/空间复杂度、边界与坑。
   - AI 判定：命中点、遗漏点、误区 → 产出评级（§5.1）+ 一句「差在哪」。
   - 复述过关即完成本次复习；不过关 → 引导升级到「重做」或给最小提示后再复述一次。

2. **重做（Re-solve）— 兜底 / 代码型题**
   - 回到题目训练工作台（复用 `PracticeChatWorkbench` + 代码 Review）重做。
   - 评级来源 = 本次 `practice_code_review` 的达标与否 + 分数，而非 recall 判定。
   - 适用：复述不过关、用户主动选、或以代码实现为主的题。

### 6.2 复习卡的「问什么」—— AI 生成卡片（C 档全量 + 异步预生成）

一次复习，LLM 调用有两处：**卡片生成**（问什么、给多少支架）与 **judge**（判复述是否真懂）。

**决策：C 档（AI 生成卡片）作为全量默认**——每张卡都结合用户在该题的提交历史（上次 Review 分数/扣分点、代码、难度、掌握度、lapses）由 LLM 生成，而不是查表模板。理由：卡片精准贴合薄弱点是这个功能「证明你真懂」的价值核心，规则模板拿不到「就你上次漏的那个边界追问你」这种精度。

**唯一的代价是延迟与成本，用「后台异步预生成」解决**（见 §6.2.1）：待复习队列的 `due_at` 是**提前已知**的，所以卡片不必等用户打开才生成——可以提前算好、缓存，用户打开即读缓存，零等待。这恰好绕开了 N-API 唯一站得住的反对理由（首屏等待）。

**A/B 档不废弃，降级为「兜底档」：**

| 档位 | 卡片生成 | 何时用 |
|---|---|---|
| **C · AI 生成卡片** | 1 次 LLM（异步预生成 + 缓存） | **全量默认** |
| **B · 规则化个性** | 无 LLM，`(难度 × 掌握度 × lapses × 上次分)` 查表变形模板 | 预生成未命中/超时/失败/预算超限时**即时兜底** |
| **A · 静态模板** | 无 LLM，固定四问 | LLM 全线不可用时的最终兜底 |
| **D · 自适应对话式复习** | 多轮追问，融入对话 | 高阶会员 / 二期 |

judge 仍是用户提交复述后 1 次 LLM（无法预生成，依赖用户输入）。所以稳态下**每张卡 = 预生成 1 次 + judge 1 次**；成本约 2×，但生成那次是离线的、可用更便宜/快的模型档，也可**命中缓存复用**（见下）。

**技术形态：卡片是一等公民的结构化 JSON（§6.4）。** C/B/A 产出同构 JSON，前端渲染同一套 UI，只是「谁来填」不同（LLM / 规则引擎）。档位切换与降级对前端零成本，也便于按 `card_variant` 埋点对比效果与成本。

#### 6.2.1 异步预生成流水线

- **触发时机（三选一或叠加）**：
  1. **入队即生成**：一次复习结束、算出新 `due_at` 落库时，顺带排一个「到期前生成下一张卡」的异步任务（把生成成本摊到每次复习之后，最贴合最新提交历史）。
  2. **每日批处理**：低峰期一个 worker 扫「今日/明日到期」队列，批量预生成（可用批量/廉价模型档，成本最优）。
  3. **会话内预取（prefetch）**：用户开始复习会话时，后台并行生成**队列后续几张**卡；用户在答第 k 张时，第 k+1、k+2 张已就绪。作为前两者的补充，覆盖「临时手动加入/立即复习」的题。
- **缓存与失效**：生成结果存 `mistake_note.pending_card_json`（或独立 `review_card` 表），带 `generated_at` 与 `source_signature`（提交历史的指纹）。**若打开时提交历史未变（signature 命中）直接复用，不重生成**——这是省成本的关键杠杆，尤其「已掌握、低频巡检」的题几乎不变。
- **打开时的取卡逻辑**：
  ```
  取 pending_card（未过期且 signature 命中）
    命中 → 直接用（C 档，零等待）
    未命中 → 即时兜底 B 档模板（零等待） + 后台补生成，供下次复习用
  ```
  用户**任何时候都不空等 LLM**：要么读到预生成的 C 卡，要么秒回 B 卡。
- **不阻塞、可观测**：预生成是后台任务，超时/失败只是这张卡这次走 B 档，绝不影响复习主流程或持有事务（呼应 AGENTS.md「不要让模型调用阻塞关键事务」）；生成任务的成功率/延迟/成本按 `card_variant` 出 Micrometer 指标。
- **落地**：契合 AGENTS.md 既定的**独立 worker** 形态（如 `复习卡预生成` worker），也可先用应用内异步执行 + 后续抽 worker。

#### 6.2.2 单用户预生成配额（按卡片数）

- **规则：每用户每自然日 C 档预生成上限 = 20 张**（可配置，`algo-mentor.review.card-gen.daily-limit=20`）。
- **超限行为**：当日第 21 张起**不再调 LLM 预生成**，该卡直接展示兜底档（B 档规则模板，B 不可用再退 A）。用户复习流照常，只是卡片个性化程度降级，**judge 不受影响**（judge 是用户提交后必走的，不算在此配额内）。
- **为什么按卡片数而非 token**：直观、可对用户解释（「今天智能卡片额度用完了」）、便于将来做会员分层（会员抬高/取消上限）。token 维度的硬护栏仍由治理层兜底。
- **计数口径**：只计**实际发起 LLM 生成**的次数；signature 命中缓存复用**不计数**（鼓励缓存、不惩罚未变题）。降级到 B/A 的卡也不计数。
- **落地**：走治理层已有配额/审计（大纲 §6），key 形如 `review_card_gen:{userId}:{yyyy-MM-dd}`，日切归零；额度耗尽发一次可观测事件，供成本分析与会员转化埋点。
- **正常用户几乎碰不到**：20 张/天 ≈ 每天复习 20 道错题，已是相当重的复习量；上限主要防刷/防异常成本，而非限制真实使用。

### 6.3 会员/免费切面（先埋接口，不上支付）

按大纲 §0「起步期不做支付」，本期**不上收费**，但**接口按档位设计**，将来一开关即分层：

**测试阶段（当前）：单一模型、全功能放开，不设会员墙。** 本节的分层只是**为后期预留的接口切面**，测试期一律走「全量开放」这一档；模型选型与会员分层作为后期优化，不在本期实现。

后期可分层的候选能力（仅预留，先埋接口、不启用）：

| 能力 | 说明 |
|---|---|
| AI 生成卡片（C 档）配额 | 测试期统一每天 20 张（§6.2.2）；后期按会员抬高/取消 |
| 生成模型档 | 测试期单模型；后期可分快/廉价档 vs 更强档 |
| 复述不过关时 AI 最小提示 | 测试期放开；后期可加每日配额 |
| D 档自适应对话式复习（多轮追问） | 后期能力 |
| 备注富文本 / 附图 | 测试期纯文本；后期可加富文本 |

治理层已有的**配额/审计**（大纲 §6「AI 治理维持」）承接生成/judge 的用量计量与成本护栏，为后期一开关即分层留底座。

### 6.4 复习卡结构化 Schema（前端与规则/LLM 共契约）

```jsonc
{
  "card_variant": "STATIC | RULE_BASED | AI_GENERATED",
  "problem_ref": { "slug": "two-sum", "title_cn": "两数之和", "difficulty": "EASY" },
  "context_summary": "上次 Review：8.5/10，扣分点=边界处理",   // 用户可读，来自历史信号
  "prompts": [                                                // 有序问题清单，1..N 条
    { "key": "algo_choice",  "label": "你会用什么算法？为什么？" },
    { "key": "key_step",     "label": "关键实现点（一两句即可）", "hint": "别写完整代码" },
    { "key": "complexity",   "label": "时间/空间复杂度" },
    { "key": "edge_case",    "label": "上次你漏了边界 X，这次怎么处理？" }
  ],
  "scaffold": {                                               // 可选，B/C 档才给
    "template_markdown": "1. 我的思路是……\n2. 关键点：\n3. 复杂度：\n4. 边界：",
    "max_input_chars": 400                                    // 硬约束「少写多想」
  },
  "reveal_policy": "HIDE_PREVIOUS_CODE_AND_SOLUTION",         // 遮蔽策略
  "expected_effort": "LIGHT | MEDIUM | HEAVY"                 // 供 judge 参考 rubric 严格度
}
```

- 该 schema 同时是**规则模板输出**与**LLM 结构化输出**的目标；前端只认 schema，不区分来源。
- `prompts[]` 按题难度/掌握度截取：简单已掌握 → 只留 `key_step + complexity`；难题/顽固 → 全量 + `scaffold`。
- **硬约束「用户少写」**：`max_input_chars` 从产品层强制引导「多想少写」，避免用户把复述写成小作文（也顺便控 judge 上下文成本）。

### 6.5 复习会话流程（卡片流）

```
首页/学习台「今日待复习 N 道」
        │  一键开始
        ▼
┌─────────────────────────────────────────┐
│  复习卡 (第 k / N)                          │
│  题面摘要 · 知识点标签 · 来源标签              │  ← 遮住上次代码/题解
│  上次表现：Review 8.5/10，边界处理扣分         │  ← 仅 B/C 档展示
│  ▸ 你会用什么算法？                          │
│  ▸ 关键实现点（一两句）                       │
│  ▸ 时间/空间复杂度                            │
│  ▸ 边界 X 这次怎么处理？                      │
│  [模板]（可选支架，B/C 档才给）                │
│  ─────────────────────────────────────    │
│  你的备注（我看过就懂 / 二次思考）：___________ │  ← 见 §6.6
│  [ 我讲完了 ]   [ 我想直接重做 ]  [ 跳过 ]     │
└─────────────────────────────────────────┘
        │ 提交复述
        ▼
   AI Judge → 评级 + 命中/遗漏点 + 「下次复习：X 天后」
        │
        ├─ 过关 → 下一张卡
        └─ 不过关 → 最小提示再来一次 / 升级重做
   （全部完成 → 复习小结：今日通过 x/N，掌握度变化，连续打卡+1）
```

- **不主动展示题解全文**；只在复述后给「差距点评」，需要更多可跳 LeetCode 或发起讲解（走引导式教练 3.1）。
- 卡片可**滑动 / 快捷键**推进（桌面先做键盘流，移动端 swipe 二期）。

### 6.6 用户备注（每卡片可留痕）

- **两类备注，同一入口**：
  1. **卡片备注（本次一次性）**：只跟随本次 `review_log`，记录当次的想法、错点自省。
  2. **题目备注（长期，跟随 mistake_note）**：跨复习保留，未来每次打开该题的卡片顶部都显示（灰底、可折叠）。用户点「置顶到题目备注」把当次备注升级为长期。
- **富文本渐进**：MVP 纯文本 + 换行 + `code` 反引号；富文本/附图作为会员权益（§6.3）。
- **长度限制**：单条 ≤ 2000 字符，避免变成日记。
- **不作为 judge 输入**（默认）：备注是给用户自己的，不喂给 judge 影响评级——避免用户把「答案」写进备注反向欺骗调度。可提供开关「让 AI 参考我的备注一起判」（会员）。
- **搜索/回顾**：错题本页支持按备注关键字检索；成长报告（5.2）可挑出用户「反复留言」的痛点题。

## 7. 页面与信息架构

- **首页 / 每日学习台（3.3）**：「今天有 N 道待复习」卡片 + 一键进入复习会话（与 streak、今日计划并列）。这是主入口。
- **错题本页（新增，如 `/mistakes` 或「复习中心」）**：
  - 顶部：今日待复习队列入口 + 掌握度概览（NEW / 复习中 / 已掌握 / 已遗忘 计数）。
  - 列表：题目、来源标签、知识点标签、难度、掌握度、下次复习时间、最近评级。
  - 筛选/排序：按知识点、掌握度、来源、所属计划、到期时间。
  - 操作：手动加入、移除、归档、立即复习。
- **题目训练工作台内**：错题状态角标 +「加入错题本 / 移出」按钮；Review 未达标后提示「已加入错题本，X 天后复习」。
- **（呼应 4.2/4.3）** 错题按知识点聚合，作为「薄弱信号」喂给能力画像与动态建议：「你在『区间 DP』错题最多，建议补练」。

## 8. 掌握度状态机

```
        入库/收藏
NEW ───────────────► LEARNING ──(interval≥30 & reps≥3)──► MASTERED
                        ▲  │                                   │
                 忘了(q<3)│  │忘了(q<3)                          │忘了(q<3)
                        │  ▼                                   ▼
                     LAPSED ◄──────────────────────────── (曾掌握又忘)
```

- `NEW`：刚入库，待首次复习。
- `LEARNING`：复习中，间隔未稳定。
- `MASTERED`：达毕业阈值，低频巡检 / 淡出队列。
- `LAPSED`：曾进展/掌握后又忘，重置间隔重新学习（`lapses` 计数用于识别「顽固错题」，可提示重点补）。

## 10. 埋点与成功指标

- **复习任务打开率**：首页「待复习 N 道」→ 进入复习会话的转化。
- **复习完成率 / 单次复习题数**。
- **Recall 一次通过率**、**评级分布**（忘/勉强/掌握/熟练）。
- **复习后同类题表现提升**（复习过的知识点，后续练习/Review 分数变化）。
- **错题毕业率**（LEARNING→MASTERED）、**顽固错题占比**（lapses≥N）。
- **次周留存**（有复习行为 vs 无 的留存差）。
- **单用户复习 LLM 成本**（并入 5.4 商业指标）；**按 `card_variant` 拆分成本 vs 通过率/留存**，量化 C 档 AI 卡片是否值这一倍成本，作为放量与会员定价依据。

## 11. MVP 范围与分期

**MVP（P0 内交付）**
- 来源：Review 未达标自动入库 + 用户主动标记（两个最确定来源）。
- 调度：SM-2 简化版（可先固定梯度 1/3/7/15/30），AI 判定评级驱动。
- 复习形态：思路复述（recall）为主 + 重做兜底。
- **卡片：C 档 AI 生成为全量默认 + 异步预生成缓存；B 档规则模板作即时兜底、A 档最终兜底**。卡片 schema §6.4 一步到位。
- **预生成流水线（§6.2.1）**：MVP 先做「入队即生成 + 会话内 prefetch」两条触发 + signature 缓存复用；每日批处理与独立 worker 可稍后抽。
- Judge：用户提交复述后 1 次 LLM。
- 备注：卡片一次性备注 + 题目长期备注（纯文本）。
- 页面：错题本页 + 首页「待复习 N 道」入口 + 卡片式复习会话。

**二期**
- 每日批处理预生成 + 独立 `复习卡预生成` worker、复述不过关的 AI 最小提示配额、D 档自适应对话式复习。
- AI 判定薄弱自动入库、反复卡住候选。
- 知识点聚合看板、按知识点批量复习（呼应 4.3）；错题信号接入能力画像与动态建议（4.2）。
- 移动端滑动卡片、语音复述、备注富文本、成长报告接入复习数据（5.2）。

## 12. 风险与开放问题

- **无官方题解作 ground truth**：我们不存题解原文、不判对错，AI 判定「思路对不对」靠题面 + 标签 + 通用算法知识，可能有误判。缓解：judge 用结构化 rubric（算法/复杂度/边界分项）、给「不确定」出口、允许用户申诉重判。这与定位一致（教练判懂没懂，不当对错权威）。
- **LLM 成本与延迟**：每次 recall 判定一次模型调用，须走配置化超时/重试/降级，不阻塞事务；纳入单用户成本监控。
- **评级信度/一致性**：同一复述多次判定应稳定 —— 需 prompt/rubric 设计与后续 eval（可挂到 `pyproject` 的 eval runner）。
- **合规红线**：错题只存事实性元数据 + 用户自己的复述/代码，**不缓存受版权保护的题面或他人题解原文**（遵循 4.0 合规红线）。
- **已定决策（本文拍板，可推翻）**：
  1. 评级权威 = **AI 判定为主**，自评为辅助信号，冲突时显式提示差距。
  2. 默认复习形态 = **思路复述（recall）**，重做兜底。
  3. 毕业阈值 = `interval≥30 & reps≥3`；冷启动先用固定梯度 `1/3/7/15/30`，再切 EF。
  4. LLM 颗粒度 = **C 档 AI 生成卡片全量默认**，靠**后台异步预生成 + signature 缓存**消除首屏延迟（§6.2.1）；B/A 档降级为预生成未命中/失败/超配额时的即时兜底。卡片 schema §6.4 一步到位。
  5. **预生成触发** = MVP 先上「**入队即生成**」（+ 会话内 prefetch 覆盖临时加入的题）；每日批处理 worker 二期。
  6. **单用户预生成配额** = **每天 20 张 C 卡**（可配置）；超限当日后续卡自动展示兜底档，judge 不受影响，缓存命中不计数（§6.2.2）。
  7. 备注 = 一次性卡片备注 + 题目长期备注两级，MVP 纯文本，默认不入 judge。
  8. **测试阶段单一模型、全功能放开、不设会员墙**；模型选型与会员分层作为后期优化，本期只按 §6.3 预留接口切面。
