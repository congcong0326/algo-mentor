# 训练方案：从「周课表」到「活的契约」——闭环产品设计

编写日期：2026-07-07

> 本文只回答一件事：**闭环合上之后，用户拿到的产品是什么样子、他每一步能感知到什么。**
> 不涉及数据库、服务拆分和代码实现。实现层承接文档见
> [`learning-plan-load-and-weekly-loop-design.md`](./learning-plan-load-and-weekly-loop-design.md)。

## 一句话结论

训练方案不应该是一张「按日历自动往前翻的课表」，而应该是一份**活的契约**：用户每完成、跳过、拖延或超额一次，计划都要当场回应他——重新排题、更新「预计学完日」、给出下一步。用户要始终能看见一件事：**我的努力，正在改变这份计划。**

## 我们已经做了什么，缺口在哪

上一版「负载与周执行闭环」已经落地了三件事：创建时算强度、生成周桶、详情页显示「当前第几周 / 落后还是超前」。但它在设计时**主动放弃**了闭环的后半段（原文非目标）：

- 不实时重排，不因题目状态变化重排整份计划；
- 「当前周」按**日历**推进（`创建到现在过了几周`），跟用户做没做题无关；
- 周进度只是「反馈和建议」，不回流改变计划本身。

于是今天的产品是这样的：**传送带按时间走，人按努力走，两条线永不交汇。** 具体断在三处——

| 场景 | 用户实际经历 | 感受 |
| --- | --- | --- |
| **没做完** | 时间照走，第 3 周照常到来；第 2 周没做的题不补、不排、不回流，只变成一个「落后 4 点」的标签 | 被扣分，但没人帮我补 |
| **提前冲完** | 3 天刷完两周的量，但「当前周」还卡在日历第 1 周，没有下一包可领 | 我最积极的时候，产品让我停下来 |
| **走到终点** | 日历到第 N 周，计划静默结束，不管路线学没学完；无完成率、无沉淀、无续期 | 它就……没了？ |

**根本矛盾**：结构是「日历盒」，价值是「完成量」，两者互相打架。这一版要把主轴切过来。

## 产品主张：计划是一份「活的契约」，不是一张课表

一句话定义我们要做出来的东西：

> 用户和产品之间有一份约定——**「我要学完这条路线」**。
> 计划的职责是：始终维护这份约定当前的**真实状态**（还剩多少、按现在的节奏预计哪天学完、下一步做什么），
> 并且**每一次用户行为都让这份约定当场更新一次**。

三个产品级承诺，任何时刻都要成立：

1. **不丢题**：没做完的题不会消失、不会「过期作废」，它会滚到后面，约定的终点不变、只是完成日顺延。
2. **不设墙**：想快就能一直往前领，产品不会因为「还没到那一周」拦住你。
3. **有回声**：每完成 / 跳过一次，都能立刻看到计划因此变化了什么（预计学完日前移 / 顺延 / 本周清空）。

## 心智模型转变：把「第几周」换成「进度 + 预计学完日」

这是整份设计的支点。

**旧模型（日历传送带）**：核心指标是「当前第 2 周 / 共 6 周」。周由时钟推动，用户是乘客。

**新模型（活的契约）**：核心指标是**两个**——

```
路线进度：42 / 120 题（35%）
按你最近的节奏，预计 8 月 18 日学完
```

- **进度**由「完成」驱动，不由日历驱动。完成一包，进度条前进，指针前移。
- **日历退居为「预测」**：不再是推着你走的传送带，而是一句「照这样，你大概哪天到终点」。快了就提前，慢了就顺延。日历从「裁判」变成「后视镜」。
- **预计学完日取「最近真实节奏」的平滑外推**（最近约 3 个题包 / 7 天的移动平均），避免单日暴增暴减让日期乱跳；计划刚开始、真实数据不足时先用创建时选的每日配额兜底，够了再自动切换。对用户一律以「预计 / 大约」呈现，不制造虚假精确。

用户看的不再是「我在第几周、落后几题」（一个只会让人有负担的相对位置），而是「我走到哪、还要多久到」（一个由自己掌控的绝对进度）。

## 四个关键时刻：用户到底看到什么

下面用界面文案草稿描述**体验**，不是最终视觉，重点是「每个动作后计划怎么回应」。

### 时刻一：完成一个题包 ✅

用户做完当前题包最后一题的瞬间，不是简单打个勾，而是一次**结算**：

```
本包完成 · 数组与哈希（5/5）
  正确率 4/5 · 用时约 70 分钟
─────────────────────────────
路线进度  27 → 32 题（+5）
预计学完  8月20日 → 8月18日  ↑ 提前 2 天
下一包已解锁：二分与区间（4 题）
                              [ 继续下一包 ]  [ 今天到这 ]
```

要点：完成 = **进度前移 + 预计日刷新 + 下一包解锁**，三件事一起当场发生。用户第一次直观感到「我做题 → 计划动了」。这是整个闭环的情绪核心。

### 时刻二：没做完 / 断更几天 🟡

用户拖了几天没碰，回来时**不是**一张「你落后 4 题」的罚单，而是一次**温和的重排**：

```
欢迎回来 · 你有 3 天没训练
本周没做完的 4 题，已帮你顺延到接下来的安排里（没有丢）
─────────────────────────────
路线进度  32 / 120 题（27%）
预计学完  8月18日 → 8月25日  ↓ 顺延 7 天
现在的节奏对你偏紧了，要不要调一档？
     [ 保持不变 ]  [ 降到舒缓 · 每天少 1 题 ]
```

要点：
- **未完成的题被「顺延」而不是「作废」**——直接兑现「不丢题」承诺。
- 后果落在**「预计学完日」这个用户真正关心的数字**上，而不是抽象的「落后 X 点负载」。
- 连续欠账触发**再平衡邀请**（把已有的 `suggestions` 真正用起来），且是**建议不是强制**——契约可以重新协商，主动权在用户。

### 时刻三：提前冲完 🚀

用户状态好，想一口气多做。产品**不设墙**：

```
本包完成 · 你今天已经连过 2 包了 🔥
路线进度  32 → 41 题（34%）
预计学完  8月18日 → 8月11日  ↑ 提前 7 天
─────────────────────────────
还想继续吗？下一包：图与搜索（5 题）
     [ 再来一包 ]  [ 见好就收，去复盘今天的题 ]
```

要点：
- 领下一包是**主动的、随时可点**的，不是「等到下周才开」。
- 「去复盘 / 加练」是一个**并列的正向选择**，而不是「你超前了，系统没内容给你了」的兜底话术。
- 提前带来的奖励是**看得见的**：预计学完日大幅前移。让高投入立刻变成成就感。

### 时刻四：走到终点 🏁

路线学完，或用户主动收尾，进入**结算态**——这是当前完全缺失的一环：

```
🎉 路线完成 · 数据结构与算法基础（120/120）
共 34 天 · 平均每天 42 分钟 · 首刷正确率 78%
你最稳的：数组、哈希、二分
还偏弱的：动态规划、图（错题各 3 道未清）
─────────────────────────────
接下来想怎么走？
  [ 针对薄弱项开专项计划 ]   ← 用本次沉淀的错题/弱项直接起草
  [ 二刷高频错题 ]
  [ 换一条更进阶的路线 ]
```

要点：计划**有明确的终点仪式**，把一次学习**结算成资产**（完成率、掌握/薄弱专题、错题沉淀），并把资产直接导流到下一个计划。契约完成 → 履约凭证 → 续约入口，闭环真正合上。

> 补充：如果用户走的是「时间盒」型（有明确 deadline，比如两周后面试），终点也可能是**时间到但路线没走完**。这时结算态展示的是「你在有限时间里覆盖了 X，最该临阵磨枪的是 Y」，而不是一句冷冰冰的「计划已过期」。

## 用户能感知到的「计划状态」

用户不需要理解后台枚举，但他应该能在详情页一眼读懂计划**此刻处于哪种状态**。我们对外只暴露四种，用人话表达：

| 用户看到的状态 | 含义 | 计划正在做什么 |
| --- | --- | --- |
| **进行中 · 节奏不错** | 完成节奏跟得上或超过预期 | 正常解锁下一包，预计日稳定或前移 |
| **进行中 · 有点跟不上** | 连续欠账，预计日在顺延 | 顺延题目 + 发出「要不要降档」的再平衡邀请 |
| **暂停** | 用户主动挂起，或连续 7 天无任何完成自动转入 | 冻结预计日、停止一切催促，回来时不清算历史压力，只做一次温和重排 |
| **已完成 / 已收尾** | 走完路线或到期收尾 | 进入结算态，产出履约凭证 + 续约入口 |

关键原则：**没有「失败 / 过期」这种终结性负面状态。** 一份学习契约永远可以被重新协商——降档、延期、暂停、重开，但不会被判死刑。这是学习产品和「打卡 App」的根本区别。

## 节奏（舒缓 / 标准 / 冲刺）在闭环里的真正含义

建方案页选的节奏，今天只影响「初始题数」，选完就变成装饰。在活契约里，节奏应该是**这份契约的松紧系数**，持续生效：

| 节奏 | 契约松紧 | 欠账时的默认反应 | 适合 |
| --- | --- | --- | --- |
| **舒缓** | 每日配额小，顺延容忍高 | 断更不催，安静顺延预计日 | 时间碎、想长期稳住 |
| **标准** | 默认配额，正常复盘 | 温和提醒 + 顺延 | 大多数人 |
| **冲刺** | 每日配额大，顺延容忍低 | 更早、更强的「你要掉出 deadline 了」预警 | 有明确面试日期 |

也就是说：节奏不是初始的一次性参数，而是**贯穿整个执行期、决定计划如何回应你**的性格设定。用户可以在时刻二那样的再平衡邀请里随时切换——契约的松紧，本身也是可协商的。

## 这一版产品不承诺什么（边界）

为了不让范围失控，明确划掉：

- **不做每日精确排程**：闭环的最小单位是「题包」，不是「几点做哪道题」。
- **不做分钟级耗时预测**：「预计学完日」是基于最近节奏的**估算**，措辞一律用「预计 / 大约」，不制造虚假精确。
- **不做全自动难度调参**：再平衡是「邀请用户切档」，不是系统偷偷改计划。用户始终握有主动权。
- **不做社交 / 排行榜施压**：进度是给自己看的绝对值，不是和别人比的相对位置。

## 已决策（本版定稿）

以下五项此前为评审待定，现已拍板，作为本版设计的确定输入：

1. **主轴取向 → 默认进度盒，deadline 型作为可显式开启的变体。**
   计划默认由「完成」驱动，对外只讲「路线进度 + 预计学完日」。用户在创建时若勾选「我有明确 deadline（如面试日期）」，则叠加「时间盒」语义：终点变成固定日期，产品在临近时用倒计时和「最该临阵磨枪的部分」帮他取舍，而不是顺延。**两种都不判失败**，区别只在「终点是路线还是日期」。

2. **顺延的可见度 → 只在用户回归时汇总一次，训练中不打断。**
   同一次训练过程中的正常流转（做完一包解锁下一包）安静发生，不弹「已顺延」。只有当用户**隔天首次进入**、且期间有欠账时，才在入口处汇总一次「这几天没做的 N 题已顺延，预计学完日 → X」。宁可少说，不制造啰嗦的负罪感。

3. **预计学完日的口径 → 最近真实节奏的平滑外推；冷启动用计划配额兜底。**
   以「最近 3 个已完成题包 / 最近 7 天」的移动平均推算日速度，避免单日暴涨暴跌导致预计日乱跳。数据不足（计划刚开始、完成不足 3 包）时，先用创建时选定的每日配额估算,积累够真实数据后自动切换。口径对用户始终以「预计 / 大约」措辞呈现。

4. **暂停的触发 → 连续 7 天无任何完成，自动转「暂停」。**
   1–6 天欠账仍属「有点跟不上」，只顺延 + 邀请降档；满 7 天无完成自动转「暂停」，冻结预计学完日、停止一切催促。回归时不清算历史压力，只做一次温和重排（时刻二）。用户也可随时主动暂停。

5. **终点结算的沉淀去向 → 复用现有 AI 创建 / 计划扩展能力，不另造机制。**
   结算产出的「薄弱专题 + 未清错题」作为**预填输入**直接喂给现有的 AI 创建入口（或计划扩展），一键起草下一个针对性计划。用户看到的是「基于你这次的表现，已经帮你把下一步的草案填好了」，而不是从空白表单重新开始。

## 推荐决策

把训练方案重新定义为**活的契约**，主轴从「日历推进」切换到「完成推进」，对外只讲两个数字：**路线进度**和**预计学完日**。四个关键时刻（完成 / 欠账 / 提前 / 终点）都必须让用户看到计划当场回应他。守住三条承诺——**不丢题、不设墙、有回声**——其余（每日排程、精确预测、自动调参）本版一律不做。

这样，用户拿到的不再是一张会自己过期的课表，而是一个「你越用它越懂你、你的每一次努力它都记得」的学习伙伴。
