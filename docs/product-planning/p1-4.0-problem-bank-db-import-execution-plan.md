# P1-4.0 题库数据最终入库执行计划

## 背景

当前 `algo-mentor` 已完成题库基座的本地数据准备：

- 官方 LeetCode API 原始缓存已落到本地。
- `complete` 题目已通过阶段一/二画像和只读校验。
- 公司维度题目元数据已生成本地 seed，并能与本地题库索引做匹配校验。
- 公司数据已增加 `companyMarket`，先将国内重点公司标记为 `CHINA`，其余标记为 `OTHER`。

本计划的目标是把题目主数据、`cn_only` 题目和公司题频元数据最终转换为数据库可导入数据，并通过后端 importer 幂等写入 PostgreSQL。

## 目标

- 生成最终题目主 seed，覆盖：
  - `BILINGUAL`：中英文题面完整题目。
  - `CN_ONLY`：中文站独有或只有中文题面的题目。
- 扩展数据库模型，使 `CN_ONLY` 能被准确表达，不把中文题面伪装成英文题面。
- 生成最终公司题频 seed，只保留能匹配最终题目主 seed 的信号。
- 后端导入流程幂等：重复导入同一批 seed 不产生重复数据，不破坏已存在主键关系。
- 记录导入审计信息，包括来源、commit、匹配数、跳过数、错误数和 manifest 路径。
- 支持小批导入验收，再全量导入。

## 非目标

- 不导入 Premium 受锁题面。
- 不抓取或分发题解、测试用例全集或第三方长文本内容。
- 不对无链接公司题频行做自动题号猜测。
- 不在本阶段实现定时同步 worker。
- 不在本阶段实现在线判题。

## 数据模型调整

### `problem`

为支持 `CN_ONLY`，需要调整题目表：

```sql
ALTER TABLE problem
  ADD COLUMN frontend_display_id VARCHAR(80),
  ADD COLUMN content_status VARCHAR(30) NOT NULL DEFAULT 'BILINGUAL',
  ADD COLUMN source_site VARCHAR(30) NOT NULL DEFAULT 'LEETCODE_COM_CN';
```

字段含义：

| 字段 | 说明 |
|---|---|
| `frontend_id` | 普通数字题号，保留 `INTEGER`，仅普通 LeetCode 题使用 |
| `frontend_display_id` | 展示题号，支持 `LCP 46`、`LCR 075`、`面试题 03.04` |
| `content_status` | 内容状态：`BILINGUAL` / `CN_ONLY` |
| `source_site` | 主内容来源：`LEETCODE_COM_CN` / `LEETCODE_CN` |

同时放宽英文字段约束：

```sql
ALTER TABLE problem
  ALTER COLUMN title_en DROP NOT NULL,
  ALTER COLUMN content_markdown_en DROP NOT NULL;
```

中文字段继续非空：

```sql
title_zh VARCHAR(300) NOT NULL
content_markdown_zh TEXT NOT NULL
```

建议新增约束：

```sql
ALTER TABLE problem
  ADD CONSTRAINT ck_problem_content_status
  CHECK (content_status IN ('BILINGUAL', 'CN_ONLY'));

ALTER TABLE problem
  ADD CONSTRAINT ck_problem_required_content
  CHECK (
    (
      content_status = 'BILINGUAL'
      AND title_en IS NOT NULL
      AND content_markdown_en IS NOT NULL
      AND title_zh IS NOT NULL
      AND content_markdown_zh IS NOT NULL
    )
    OR (
      content_status = 'CN_ONLY'
      AND title_zh IS NOT NULL
      AND content_markdown_zh IS NOT NULL
    )
  );
```

唯一键建议：

```sql
CREATE UNIQUE INDEX uk_problem_frontend_display_id
  ON problem(frontend_display_id)
  WHERE frontend_display_id IS NOT NULL;
```

保留现有 `uk_problem_slug`。

`frontend_id` 的唯一约束需要复核：

- 如果当前 PostgreSQL 唯一约束允许多个 `NULL`，则可以保留。
- 若迁移中需要重建，建议改为部分唯一索引：

```sql
CREATE UNIQUE INDEX uk_problem_frontend_id_not_null
  ON problem(frontend_id)
  WHERE frontend_id IS NOT NULL;
```

### `company`

新增公司市场字段：

```sql
ALTER TABLE company
  ADD COLUMN company_market VARCHAR(30) NOT NULL DEFAULT 'OTHER';
```

约束：

```sql
ALTER TABLE company
  ADD CONSTRAINT ck_company_market
  CHECK (company_market IN ('CHINA', 'OTHER'));
```

`company.slug` 继续作为幂等 upsert 键。

### `problem_company_signal`

继续使用唯一键保证幂等：

```sql
UNIQUE (problem_id, company_id, role, recency_bucket, source_name)
```

导入同一 seed 时，对该唯一键执行 upsert。

### `problem_company_import_run`

保留导入审计表，用于记录每次导入。

建议额外在 `metadata_json` 中保存：

- `seedChecksum`
- `problemSeedManifestPath`
- `companySeedManifestPath`
- `matchedSignalCount`
- `skippedSignalCount`
- `unmatchedProblems`
- `errorsByRule`
- `companyMarkets`

## 执行阶段

### 阶段 1：生成最终题目 seed

- 读取：
  - `data/index/problem_index.jsonl`
  - `data/sources/leetcode-api/{slug}.com.json`
  - `data/sources/leetcode-api/{slug}.cn.json`
- 输出：
  - `data/seed/problems.jsonl`
  - `data/seed/problem_categories.jsonl`
  - `data/seed/problem_category_items.jsonl`
  - `data/seed/manifest.json`

分类处理：

| 分类 | 入题目 seed | 说明 |
|---|---|---|
| `complete` | 是 | 生成 `BILINGUAL` |
| `cn_only` | 是 | 生成 `CN_ONLY` |
| `premium_locked` | 否 | 不导入默认题库 |

### 阶段 2：校验最终题目 seed

扩展或新增 `validate_seed.py` 校验：

- `slug` 唯一。
- `frontend_display_id` 唯一。
- `frontend_id` 非空时唯一。
- `content_status` 合法。
- `BILINGUAL` 中英题面都非空。
- `CN_ONLY` 中文题面非空，英文题面允许为空。
- tag 三数组等长。
- `leetcodeUrl` 中 slug 与记录一致。
- `frontend_display_id` 对普通数字题与 `frontend_id` 一致。

输出：

- `data/reports/problem_seed_validation_report.json`

### 阶段 3：生成最终公司 seed

基于当前 `tools/problem_company_seed/prepare_company_seed.py`：

- 输入公司源不变。

输出：

## 幂等导入语义

### 题目导入幂等

题目以 `slug` 为稳定业务键：

```sql
ON CONFLICT (slug) DO UPDATE
```

更新字段：

- `frontend_id`
- `frontend_display_id`
- `title_en`
- `title_zh`
- `difficulty`
- `tag_values`
- `tag_labels_en`
- `tag_labels_zh`
- `content_markdown_en`
- `content_markdown_zh`
- `content_status`
- `source_site`
- `leetcode_url`
- `sample_test_case`
- `python3_template`
- `source_commit`
- `updated_at`

不更新字段：

- `id`
- `created_at`

### 公司导入幂等

公司以 `company.slug` 为业务键：

```sql
ON CONFLICT (slug) DO UPDATE
```

更新：

- `display_name`
- `company_market`
- `last_imported_at`

### 公司信号导入幂等

信号以以下唯一键为业务键：

```sql
(problem_id, company_id, role, recency_bucket, source_name)
```

重复导入同一 seed 时：

- 不新增重复行。
- 更新 `frequency_score`、`rank`、`acceptance_rate`、`source_url`、`source_commit`、`source_problem_url`、`import_run_id`、`updated_at`。

### 删除与下线策略

第一版不做硬删除。

如果新 seed 不再包含旧信号：

- 暂不删除历史行。
- 后续如需要严格同步，可增加 `is_active` 或 `last_seen_import_run_id`。

第一版推荐新增：

```sql
is_active BOOLEAN NOT NULL DEFAULT TRUE
```

导入语义：

- 当前 seed 中出现的信号置为 `is_active = TRUE`。
- 是否将同 source 不再出现的旧信号置为 `FALSE`，第一版可以不做，避免误伤。

### import run 幂等

每次执行导入都创建新的 `problem_company_import_run`，因为这是一次执行审计。

业务数据幂等不等于审计记录幂等：

- `problem` 幂等。
- `company` 幂等。
- `problem_company_signal` 幂等。
- `problem_company_import_run` 允许每次新增。

验收 SQL 示例：

```sql
SELECT content_status, COUNT(*)
FROM problem
GROUP BY content_status;

SELECT company_market, COUNT(*)
FROM company
GROUP BY company_market;

SELECT COUNT(*)
FROM problem_company_signal;

SELECT p.content_status, COUNT(*)
FROM problem_company_signal pcs
JOIN problem p ON p.id = pcs.problem_id
GROUP BY p.content_status;
```

幂等验收：

```sql
SELECT COUNT(*) FROM problem;
SELECT COUNT(*) FROM company;
SELECT COUNT(*) FROM problem_company_signal;
```

## 风险与处理

| 风险 | 处理 |
|---|---|
| `CN_ONLY` 英文字段为空影响前端 | API 返回 `contentStatus`，英文 locale 回退中文 |
| 非数字题号破坏 `frontend_id INTEGER` | 新增 `frontend_display_id`，普通数字题继续保留 `frontend_id` |
| 公司信号引用未导入题目 | 最终公司 seed 按最终 `problems.jsonl` 过滤 |
| 重复导入产生重复信号 | 使用唯一键 upsert |
| 外部源无 LICENSE | 只保存事实元数据和来源，不保存题面/题解 |
| 旧 seed 中不存在的新字段 | importer 给默认值，或要求 manifest schemaVersion |
