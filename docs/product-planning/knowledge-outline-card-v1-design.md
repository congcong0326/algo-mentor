# 知识大纲与知识卡片第一阶段研发设计

设计日期：2026-09-15  
状态：产品方向已确认，作为首期实现基线

本次修订：知识卡从首期起对齐现有 FSRS 四档评价；首次评价才入队。新增独立知识库页面和独立八股文复习中心页面。

当前阶段调整（2026-09-15）：保留数据库 DDL，不执行初始化数据导入；优先建设用户侧知识库浏览、卡片与文章阅读、四档评价及八股文复习中心的完整 API。接口契约见 [用户侧接口设计](knowledge-outline-card-v1-api-design.md)。共享内容由维护者后续直接执行数据库导入，不建设管理员 CRUD；原管理员接口方案已撤回。第 7 节的 seed 导入不在当前交付范围，测试数据仅用于隔离测试。当前交付为设计，尚未实现 API。

## 1. 目标与边界

第一阶段验证一条最小学习闭环：

```text
知识库首页 → 选择技术节点 → 浏览展开的大纲 → 进入卡片列表
→ 先回答问题 → 查看答案 → 可选的四档评价 → 八股文复习中心 → 到期复习
```

内容面向多个用户共享。大纲节点、卡片和文章是平台内容；用户只产生自己的学习状态、复习记录和后续个人数据，不复制一套用户专属内容。

本阶段只做：

- 一棵以虚拟 root 为根的可递归知识树；
- 技术节点及其下级节点的浏览、展开和收起；
- 独立知识库页面中的卡片列表、卡片详情、显示答案和四档评价；
- 独立八股文复习中心页面、用户 FSRS 调度状态和复习流水；
- 节点可选文章入口和文章列表/详情阅读。

本阶段不做：

- 每个节点强制生成文章；
- 用户编辑或复制平台卡片；
- 复杂关系图、推荐路径和多套知识树；
- AI 自动发布或自动覆盖已批准文章；
- 内容编辑后台。内容可先通过 seed 或受控管理方式导入。

## 2. 核心概念

### 2.1 一棵共享知识树

数据库只有一棵树，根节点是技术上的虚拟 root，产品界面不展示它。root 的直接子节点是用户进入知识库后看到的第一层，例如 `Java`、`MySQL`、`PostgreSQL`、`Redis`。

```text
虚拟 root
├── Java
│   ├── 基础
│   │   └── 对象与引用
│   └── 并发
├── MySQL
│   ├── SQL 基础
│   └── 事务
└── Redis
    └── 数据结构
```

树在数据模型上不设置业务最大深度，使用 `parent_id` 表达父子关系。产品和编辑约定避免无意义的过度拆分；大多数内容应在技术节点下经过两到三层到达主题，必要时可以继续挂载。

大纲节点是共享的单一身份。它不保存某个用户的完成状态，节点进度由当前用户关联卡片的状态聚合得到。

### 2.2 卡片是共享学习内容

一张卡片只有一份平台内容，有一个主要归属大纲节点。一个节点可以有零到多张卡片。卡片正文至少有问题和核心回答，解释、示例、误区和来源按需要提供。

卡片不是用户副本。用户 A 和用户 B 看到同一份已发布内容，但各自拥有独立的学习状态和复习记录。卡片与其他卡片的前置、追问、对比关系第一阶段可以暂不落库；需要时再增加独立关系表，不把关系硬编码进正文。

### 2.3 文章是节点的可选附属内容

文章是技术风格、偏博客的主题导读，不是大纲存在的前提。一个节点可以没有文章，也可以有多篇文章；只有存在已发布文章时，用户界面才显示文章入口。

文章草稿由人工发起生成并审核后发布。首期只需保存文章状态和正文，不做自动更新；大纲或卡片变化不会静默覆盖已发布文章。

## 3. 数据库设计

迁移使用当前 `mentor-api` 的下一可用 Flyway 版本，以下表名和字段为首期契约。所有时间字段使用 `TIMESTAMPTZ`，主键使用 `BIGSERIAL`（或项目统一的 bigint identity 写法）。

### 3.1 `knowledge_outline_node`

保存共享大纲树。root 也作为一行保存，便于所有节点统一通过 `parent_id` 挂载；root 的 `node_kind` 为 `ROOT`，产品查询时过滤掉该行。

| 字段 | 说明 |
| --- | --- |
| `id` | 节点 ID，主键 |
| `parent_id` | 父节点；root 为 `NULL`，普通节点引用本表 |
| `node_kind` | `ROOT` 或 `NODE` |
| `slug` | 节点稳定标识，建议在同一父节点下唯一 |
| `title` | 展示名称 |
| `summary` | 节点的一句话说明，可为空 |
| `sort_order` | 同级展示顺序 |
| `status` | `DRAFT`、`PUBLISHED`、`ARCHIVED` |
| `created_at` / `updated_at` | 审计时间 |

约束和索引：

- 通过唯一部分索引保证全表只有一个 `ROOT`；root 不允许有父节点，普通节点必须有父节点；
- `UNIQUE (parent_id, slug)` 保证同一父节点下的稳定标识不重复；
- `INDEX (parent_id, status, sort_order, id)` 支持按父节点读取子节点；
- 删除节点前由应用校验没有已发布后代、卡片或文章；首期不做级联删除；
- 创建或移动节点时由服务层拒绝自引用和形成环，查询使用递归 CTE，不引入 closure table、物化路径等额外结构。

`slug` 只用于稳定定位和路由辅助，展示名称可以修改。第一阶段不要求全局 slug 唯一。

### 3.2 `knowledge_card`

保存共享卡片的当前已编辑内容。

| 字段 | 说明 |
| --- | --- |
| `id` | 卡片 ID，主键 |
| `outline_node_id` | 主要归属节点，外键到 `knowledge_outline_node` |
| `question` | 问题标题，必填 |
| `answer_markdown` | 核心回答，必填 |
| `explanation_markdown` | 详细解释，可为空 |
| `example_markdown` | 示例或流程，可为空 |
| `source_markdown` | 来源说明，可为空 |
| `sort_order` | 节点内卡片顺序 |
| `status` | `DRAFT`、`PUBLISHED`、`ARCHIVED` |
| `created_at` / `updated_at` | 审计时间 |

约束和索引：

- `question` 和 `answer_markdown` 不能为空，并设置合理的字符长度上限；
- `INDEX (outline_node_id, status, sort_order, id)` 支持主题卡片列表；
- 用户端只读取 `PUBLISHED` 卡片；归档卡片不删除历史用户状态，但不再出现在新列表中；
- 首期不实现卡片版本表。需要审核历史或草稿并行编辑时，再增加版本化设计，不影响当前共享身份。

### 3.3 `knowledge_article`

保存节点的可选技术文章。

| 字段 | 说明 |
| --- | --- |
| `id` | 文章 ID，主键 |
| `outline_node_id` | 所属大纲节点 |
| `title` | 文章标题 |
| `body_markdown` | 正文 |
| `status` | `DRAFT`、`PUBLISHED`、`ARCHIVED` |
| `published_at` | 审核发布时写入 |
| `created_at` / `updated_at` | 审计时间 |

使用 `INDEX (outline_node_id, status, published_at DESC, id)` 查询节点文章。允许一个节点有多篇已发布文章，文章列表按发布时间倒序；没有已发布文章时 API 返回空列表，前端不渲染文章按钮。

首期不保存模型调用明细或大纲/卡片版本快照。若后续需要判断文章是否过时，再增加生成元数据和审核记录。

### 3.4 `knowledge_card_user_state`

保存当前用户已加入复习的知识卡及其调度状态，每个 `(user_id, card_id)` 只有一行。保留表名，字段与现有 `problem_review_card` 的调度字段对齐，不另建 `NEW/MASTERED/LAPSED` 掌握状态机。

**存在记录即表示已加入复习中心。只有首次评价事务成功后才创建记录。** 浏览大纲、打开卡片、显示答案、获取按钮间隔预览均不建记录，不入队；无需再增加 `enrolled` 字段。

| 字段 | 类型与说明 |
| --- | --- |
| `id` | `BIGSERIAL` 主键 |
| `user_id` | `BIGINT NOT NULL`，引用 `auth_users(id)` |
| `card_id` | `BIGINT NOT NULL`，引用共享 `knowledge_card(id)` |
| `repetitions` | `INT NOT NULL`，连续成功计数，沿用调度器定义，不等于总评价次数 |
| `interval_days` | `INT NOT NULL`，调度间隔天数 |
| `lapses` | `INT NOT NULL`，遗忘次数 |
| `fsrs_state` | `VARCHAR(16) NOT NULL`，`LEARNING/REVIEW/RELEARNING` |
| `fsrs_step` | `INT NULL`，短期学习步骤 |
| `fsrs_stability` | `NUMERIC(12,6) NULL`，稳定度 |
| `fsrs_difficulty` | `NUMERIC(12,6) NULL`，记忆难度 |
| `due_at` | `TIMESTAMPTZ NOT NULL`，本次评价计算出的下次到期时间 |
| `last_rating` | `VARCHAR(16) NOT NULL`，`AGAIN/HARD/GOOD/EASY` |
| `last_reviewed_at` | `TIMESTAMPTZ NOT NULL`，最近一次评价时间 |
| `created_at` / `updated_at` | `TIMESTAMPTZ NOT NULL`，首次入队及更新时间 |

约束和索引：

- `UNIQUE (user_id, card_id)` 保证同一用户只入队一次；
- `INDEX (user_id, due_at, id)` 支持当前用户的全部已加入卡片和到期队列；
- CHECK 校验四档评价、三个 FSRS 状态，以及计数/间隔非负；学习阶段允许 memory 字段为空，毕业后由既有调度器填充；
- 删除用户时级联清理其状态。共享卡片已有复习记录后采用归档，不物理删除历史；卡片外键使用限制删除；
- 未评价没有行；首次评价从 `SchedulingState.initial()` 在内存中计算，并持久化**评价后的状态**，不是仅插入初始卡；
- 卡片未到期仍展示在中心的“全部已加入”列表，只有 `due_at <= 当前时间` 才属于“待复习”；
- 首期不增加手动移出、暂停和重新入队功能，因此不预加用户归档字段。

`fsrs_state=REVIEW` 表示进入长期复习阶段，不代表已经永久掌握。界面采用“未加入复习 / 学习中 / 复习中 / 重学中”，到期时额外标记“待复习”。未加入也不等于用户从未读过。

### 3.5 `knowledge_card_review_attempt`

保存每次评价流水与调度快照，对齐现有 `problem_review_attempt`。卡片内容保持共享，不在流水中复制正文。

| 字段 | 类型与说明 |
| --- | --- |
| `id` | `BIGSERIAL` 主键 |
| `user_state_id` | `BIGINT NOT NULL`，对应用户知识卡调度记录 |
| `user_id` | `BIGINT NOT NULL`，当前用户 |
| `client_attempt_id` | `UUID NOT NULL`，单次评价幂等键 |
| `rating` | `VARCHAR(16) NOT NULL`，`AGAIN/HARD/GOOD/EASY` |
| `scheduling_before_json` | `JSONB NOT NULL`，评价前调度快照 |
| `scheduling_after_json` | `JSONB NOT NULL`，评价后调度快照，包括到期时间 |
| `reviewed_at` | `TIMESTAMPTZ NOT NULL`，服务端评价时间 |

设置 `UNIQUE (user_id, client_attempt_id)`，建立 `(user_state_id, reviewed_at DESC)` 和 `(user_id, reviewed_at DESC)` 索引；CHECK 校验四档 rating、快照为 JSON 对象。用户外键和状态外键在用户清理时级联删除，应用校验状态确属当前用户。快照复用现有 `ReviewSchedulingSnapshot` 语义，首次评价的前态是内存初始状态。

入队和评价是同一个事务：

1. 由认证信息获取用户 ID；检查同一幂等键是否已处理，重复请求返回原流水及其调度结果。相同键用于不同卡片或不同评级时拒绝。
2. 校验卡片及祖先均已发布；已有记录则加行锁读取最新状态。首次评价先在内存计算评价后状态，再尝试插入；并发插入冲突则读取并锁定已有状态，重新检查幂等并重新计算，避免建立两张用户复习卡。
3. 使用统一调度器应用本次四档评价，原子写入状态和流水；任何失败回滚，不能留下没有评价记录的入队状态。
4. 客户端重复提交或网络超时重试沿用同一 UUID，不重复计数或推进调度；幂等冲突路径必须回滚本次创建的临时状态。

第一阶段不保存用户自由回答正文，不因点击“显示答案”产生流水。

### 3.6 复用既有 FSRS 能力

首期直接采用现有的“Anki 式短期学习 + FSRS 长期复习”，以 [复习调度设计](../review-scheduling-anki-alignment-design.md) 及当前实现为准。四档按钮为：

| 界面文案 | 统一枚举 | 新卡第一个学习步骤的默认预览 |
| --- | --- | --- |
| 重来 | `AGAIN` | 1 分钟 |
| 困难 | `HARD` | 5 分 30 秒，界面显示 6 分钟 |
| 良好 | `GOOD` | 10 分钟 |
| 简单 | `EASY` | 4 天，直接进入长期复习 |

以上是现有默认配置示例；前端不硬编码间隔。知识卡的四档评价不是题目的静态难度，更不能把“简单”解释为无需入队。

复用 `ReviewRating`、`SchedulingState`、`FsrsReviewSchedulerService`、`AnkiLearningPolicy`、`ReviewDayBoundary` 及现有用户复习偏好。分钟级学习步骤、毕业间隔、FSRS memory、用户时区与间隔预览均采用同一实现。

当前调度器参数依赖 `ProblemReviewCard`。实施时仅将其需要的调度状态、到期时间、最近评价时间提取成轻量输入，给现有题目调用保留适配入口；知识卡调用相同的 `preview/apply`。不伪造题目 slug，不复制 FSRS 算法，不将知识卡插入带 `problem_slug` 外键的题目复习表。

知识卡的用户状态、流水、列表查询和入队服务独立实现。`ReviewSeedPolicy` 的 Code Review 自动入队策略不用于知识卡；首次用户评价就是第一条真实学习记录。沿用用户偏好中的调度参数，首期知识复习队列仅按已入队且到期查询，不扩展每日新卡配额或跨中心联合任务池。

预览不写数据库；无用户状态时使用内存初始状态。相同输入、时间、偏好及随机配置下预览和应用应一致；实际提交以服务端当前时间和最新状态计算，返回真实到期时间。

## 4. API 与读取边界

API 只返回已发布的共享内容，并根据当前认证用户左连接学习状态。首期可以提供以下只读和写入能力，具体 URL 遵循项目现有 API 命名约定：

- 获取 root 的直接子节点；
- 获取某技术节点下的递归大纲树（返回节点、卡片数量、文章数量和当前用户进度）；
- 获取节点的已发布卡片列表；
- 获取卡片详情；
- 获取节点的已发布文章列表和文章详情；
- 获取卡片四档间隔预览，不触发入队；
- 提交卡片评价，携带 `clientAttemptId`、四档 `rating` 和用户时区；用户 ID 从认证上下文取得；
- 获取八股文复习中心的当前用户汇总、全部已加入卡片列表和到期列表。

递归树接口只读取当前技术分支，不在知识库首页加载所有技术节点的后代。返回结构使用嵌套 `children`，前端不需要自己拼树。卡片和文章正文不随大纲树批量返回，避免首页响应过大。

节点进度只作展示聚合，例如“已加入复习 7 / 20 张”；它不是独立存储的事实。全部列表、待复习列表、详情及计数均校验卡片和祖先发布状态；隐藏或归档内容保留历史调度但不参与当前可见数量和队列。不得只检查卡片自身状态而泄露隐藏分支。

## 5. 首期界面交互

### 5.1 两个独立页面入口

在现有应用外壳中新建两个页面，各自有固定导航入口，不与算法题页面混排：

| 入口 | 建议路由 | 用途 |
| --- | --- | --- |
| 知识库 | `/knowledge` | 技术入口、大纲、卡片浏览和可选文章 |
| 八股文复习中心 | `/knowledge/review` | 当前用户已评价的知识卡及到期复习 |

原有算法题复习中心继续承载算法题。两个复习中心复用底层调度和可复用展示组件，数据查询及卡片列表分别维护。知识卡详情和知识复习会话共用问题、答案、评价按钮组件，按进入来源提供返回入口。

### 5.2 知识库首页

入口名称为“知识库”。首页展示虚拟 root 的直接子节点，默认不展开下级：

```text
Java          32 张卡片    已加入复习 12 张
MySQL         24 张卡片    已加入复习  6 张
PostgreSQL    18 张卡片    已加入复习  4 张
Redis         21 张卡片    已加入复习  9 张
```

用户点击技术节点进入该节点的大纲页。页面顶部提供“八股文复习中心”入口，点击后进入独立复习中心；不在第一阶段增加复杂仪表盘。

### 5.3 技术大纲页

页面显示面包屑和当前技术名称，例如 `知识库 / MySQL`。进入后加载该分支的完整大纲，节点默认展开；用户可以逐节点收起，也可以使用“全部展开/全部收起”。收起状态只保存在浏览器本地，不写入平台内容或用户学习事实。

每行节点显示：

- 展开/收起控制（有子节点时）；
- 节点标题和一句话说明；
- 下属已发布卡片数量及当前用户进度；
- 有已发布文章时显示“查看文章”；
- 有卡片时显示“查看卡片”。

卡片列表默认收起，不在大纲页直接铺开卡片正文或全部问题。点击叶子节点标题或“查看卡片”进入该节点的卡片列表。叶子节点没有卡片时显示简短的“暂无已发布卡片”，不创建空的学习流程。

节点标题和箭头的职责要清楚：箭头只展开/收起；标题进入节点内容。对有子节点且自身也有卡片的节点，标题进入节点详情，使用“查看卡片”进入本节点卡片列表，不要求用户猜测点击行为。

### 5.4 卡片列表页

页面显示 `MySQL / 事务 / 卡片` 等面包屑和列表。每行只展示问题标题和当前用户状态：

```text
○ ACID 分别解决什么问题？                 未加入复习
○ 数据库隔离级别如何影响并发读取？          待复习
○ MVCC 为什么能减少读写阻塞？               复习中
```

点击问题进入卡片详情；列表不自动打开答案。第一阶段可按节点 `sort_order` 排列，并提供“开始学习”按钮从第一张开始浏览。不评价也可以查看下一张或离开；只有明确评价才计入复习。

### 5.5 卡片详情与评价

进入卡片后先展示问题和“显示答案”按钮，防止用户只滚动阅读：

```text
数据库隔离级别如何影响并发读取？

[显示答案]
```

点击后展开核心回答、解释、示例和来源（存在什么展示什么）。页面底部显示与现有复习中心一致的四档评价及服务端返回的间隔预览：

```text
[重来 · 1 分钟]  [困难 · 6 分钟]  [良好 · 10 分钟]  [简单 · 4 天]
```

上述间隔仅为新卡默认示例，后续按真实调度状态更新。按钮下方说明：“选择任一评价后加入八股文复习中心；仅浏览不会加入。”

点击任一按钮后提交一次评价。首次成功显示“已加入八股文复习中心，下次复习：……”；已有卡成功显示“评价已记录，下次复习：……”。知识库和复习中心使用同一 `(user_id, card_id)` 调度状态，从知识库再次评价也会更新既有调度，不另建副本。

提供“下一张”“返回卡片列表”和“前往八股文复习中心”。下一张仍在当前浏览列表中；不评价也能继续浏览。请求进行中禁用四个按钮，成功后本轮不再允许重复评价；失败保留当前页面并使用同一幂等键重试，网络结果不确定时不提前显示已入队。

### 5.6 八股文复习中心

独立页面顶部显示“已加入 N 张”“待复习 M 张”和“开始复习”。列表有“全部已加入”和“待复习”两个筛选，首次进入默认展示全部已加入，保证用户刚评价的卡片即使未到期也能找到。

列表展示问题标题、所属技术/主题、学习阶段和下次复习时间，按 `due_at, id` 排序并分页。它只查询当前用户已有调度记录的知识卡：

- 从未评价的卡片不展示，即使已经浏览过或看过答案；
- 四种首次评价都加入，包括“简单”；未到期显示预计时间，到期标记“待复习”；
- “开始复习”只选到期卡片，未到期不会为凑数量提前加入；没有到期卡片时禁用按钮并提示下次到期时间；
- 尚未加入任何卡片时显示“在知识库查看卡片并选择评价后，会出现在这里”，提供“去知识库”入口。

点击列表卡片可以查看详情；点击“开始复习”进入知识卡复习会话，先看问题、点击显示答案，再选择四档评价。服务端记录后推进到下一张到期卡；也可以退出而不评价，退出不改变调度。会话不混入算法题。

每次成功评价后重新取到期候选，优先短期学习/重学卡，其余按到期时间排序。“重来”后的卡片在新到期时间前不重复出现，到期后可再次参与本轮复习。当前无到期卡时展示“本轮已完成”和“返回复习中心”，提示下一次到期时间；不自动等待，也不把未到期卡标成已完成。页面恢复后重新查询，后端不为本阶段新增会话表或永久队列表。

从详情返回时回到原来的知识库列表或复习中心并刷新相应状态；不能固定跳回原有算法题复习中心。

### 5.7 文章列表与详情

只有节点存在已发布文章时，大纲行才显示“查看文章”。点击后统一进入文章列表，再点击文章进入详情。

文章详情是普通 Markdown 阅读页，提供标题、更新时间和返回所属节点。文章不是卡片学习流程的必经步骤，不显示“完成文章”门槛，也不因为没有文章而改变卡片入口。

## 6. 内容发布与权限

- 普通用户只能读取已发布节点、卡片和文章，并写入自己的自评与学习状态；
- 内容维护者通过受控 seed/管理流程创建和发布共享内容；
- 节点、卡片和文章的草稿/归档状态不出现在普通用户树中；
- 共享内容更新后，所有用户看到新版本，但历史学习状态仍按 `(user_id, card_id)` 保留；
- 首期不提供用户修改平台正文、复制卡片或创建私有分支的功能。

## 7. 实施顺序与验收

按以下顺序实现，任何一步都不要求先完成文章：

1. 建立 root、节点和卡片表，导入一小段 Java/MySQL seed；
2. 实现 root 子节点和技术分支递归读取；
3. 实现大纲页默认展开、收起和卡片入口；
4. 适配现有调度器输入，实现卡片详情、答案和四档预览/评价；
5. 实现首次评价原子入队、调度快照流水，以及独立八股文复习中心和到期复习会话；
6. 增加文章表和有文章才显示的列表/详情入口。

首期验收以用户能否完成下面的动作作为标准：

```text
进入知识库 → 点击 MySQL → 找到事务下的叶子主题
→ 打开一张卡片 → 先看问题 → 显示答案
→ 不评价直接返回：复习中心仍为空
→ 再次打开并选择“困难”：加入八股文复习中心，显示约 6 分钟后复习
→ 到期后进入待复习列表 → 开始复习 → 四档评价更新下次时间
```

同时确认多个用户看到相同的大纲和卡片正文，而各自的状态、待复习时间和复习流水互不影响。文章不存在时，页面仍能完整完成上述流程；文章存在时，入口仅作为额外阅读选项出现。

### 7.1 必须验证的行为

- 只浏览、显示答案或读取预览：用户状态和流水均无新增；已入队卡浏览时也不改变调度。
- 新卡分别点击 `AGAIN/HARD/GOOD/EASY`：只创建一条当前用户状态和一条首次流水，四种情况均在中心可见。
- 对齐现有两步学习、毕业及成熟卡重学策略；固定时钟/时区/随机配置验证预览与提交及落库 memory 一致。
- 首次点击“简单”立即在全部列表出现，按默认配置四天后到期；当前待复习列表不能提前出现。
- 同一评价重复提交只调度一次；并发首次评价不生成重复状态，失败事务不留下孤立入队记录。
- 不同用户的入队、评价和到期数据互不影响；知识库与八股文复习中心共享当前用户同一张知识复习卡。
- 新旧复习中心分别查询知识卡和算法题，原有算法题调度回归通过；共享内容或祖先归档后从知识复习列表隐藏，历史保留。
- 页面覆盖四档显示、无评价退出、首次入队成功/失败、中心空态、全部/到期筛选、复习后再次到期和原路返回。

实现阶段运行最小相关后端测试及前端交互测试，通过根 Makefile 入口验证；本次仅更新设计，不执行迁移、初始化导入或新增运行页面；实现阶段以用户侧接口设计为准。
