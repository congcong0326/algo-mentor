# 知识大纲与知识卡片第一阶段研发设计

修订日期：2026-09-16。当前基线为目录维护与全量导入方案；旧节点稳定键、固定字段章节和仅 DDL 阶段约定已被替代。

## 产品闭环

共享知识库首页 → 选择技术大纲 → 浏览子节点、卡片或文章 → 先回忆再显示答案 → 可选 FSRS 四档评价 → 独立复习中心。

大纲、卡片、文章为共享内容；用户各自保存复习状态和评价流水。浏览、显示答案和间隔预览均不入队，首次评价成功才入队。不复制用户专属内容。

## 维护与身份

正式内容在 `knowledge-base/`，仅 `.node` 目录构成树。目录可改名和移动，无需稳定外部键。ROOT 是导入时生成的虚拟根，不展示。

一张卡片一个 `.card.md` 文件。问题来自文件名；slug 由维护者生成并长期保持，是所有持久引用和复习关联的身份。

卡片正文是 YAML 元数据、核心回答、详细 Markdown 三部分。详细内容以第一个顶层二级标题开始，完整自由渲染。元数据支持 slug、tags、status、order、relations；关系包括 prerequisites/followups/contrasts/related，按 slug 引用。

文章为 `.article.md`，正文不要求固定结构或元数据，不参与复习。一节点可以零到多篇文章，目录不依赖文章存在。

完整约束与示例以 [维护手册](../../knowledge-base/README.md) 为准，工程设计见 [目录导入设计](knowledge-directory-import-v1-design.md)。

## 更新和删除

导入事务全量重建共享大纲、卡片、文章和关系。数据库内容主键可变化；用户状态按 `(user_id, card_slug)` 保存，流水按用户状态关联，不随日常导入删除。内容修订与移动保留 slug；改成不同问题使用新 slug。

删除源文件使当前卡片退出知识库和复习队列，保留历史；恢复同 slug 后重新关联。草稿可导入但不对用户显示。开发期 V76 允许一次性重建旧知识表，后续导入必须保留复习事实。

## 复习

复用已有 FSRS/Anki 学习步骤调度服务与用户偏好。四档为 AGAIN/HARD/GOOD/EASY，用户评价事务同时更新状态与流水。

同用户的 clientAttemptId 幂等；相同请求重试返回已记录结果，不重复调度。若请求标识被用于不同 slug 或评级，返回 409。不同用户的状态、统计和请求标识互相隔离。

卡片列表、详情、关系和复习队列只展示已发布且位于有效发布树中的内容；文章独立阅读，不评价。

## 首期范围

实现目录导入、知识库浏览、卡片关系、文章阅读和个人复习闭环，不实现管理员 CRUD、AI 自动生成发布、复杂关系图和多来源同步。

详细数据库与 API 契约分别见 [数据库说明](knowledge-outline-card-v1-database.md)、[用户 API](knowledge-outline-card-v1-api-design.md)。
