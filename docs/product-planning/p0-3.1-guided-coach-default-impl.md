## 1. 目标与非目标

### 1.1 目标
- 把 `PracticeCoachStyle` 从 5 档收敛为 **2 档**：`GUIDED`（引导，默认）、`DIRECT`（直给）。
- 让「引导档」真正驱动**提示的分层节奏**（L1 方向 → L2 关键观察 → L3 结构/伪代码 → L4 完整解），未经用户显式请求或长时间卡死**不得直接甩完整代码**。
- 「直给档」直接给完整思路、复杂度、坑点、可运行代码。
- **直接破坏性改造，不保留历史 5 档兼容**——项目未上线，历史数据可废弃。

### 1.2 非目标（本次明确不做）
- 不做范式自适应（渐隐支架 / 费曼讲回来按用户水平自动切换）——依赖能力画像信号，属 P1（4.2/4.3）。
- 不改造 Review 定位（3.2）、不做错题本（3.4）、不动权限交互（3.6）。
- 不新增「教练风格」以外的用户可选项。
- 不重写意图分类器（保留现有关键词匹配版作为**辅助信号**，模型自主读消息为主，见 §3.3）。

## 2. 现状与调用链梳理

### 2.1 教练风格从用户偏好到 prompt 的完整链路

```
用户在 MyPage 选风格
        │
        ▼
PATCH /me/ai-preferences  ── UserAiPreferenceController.update()
        │  request.coachStyle (String) 经 PracticeCoachStyle.from() 收敛
        ▼
UserAiPreferenceService.update()  ── 持久化到 user_ai_preference
        │
        ▼    （下次做题聊天）
PracticeMessageStreamService.streamMessage()
        │  preferenceService.get(userId) → UserAiPreference
        │  metadata.put(METADATA_COACH_STYLE, preference.coachStyle().name())
        ▼
AgentConversationService.assemblePracticeChatContext()
        │  从 governanceMetadata 读回 → PracticeCoachStyle.from(...)
        │  同时写入 variables (VARIABLE_COACH_STYLE) + metadata (METADATA_COACH_STYLE)
        │  metadata 还带 METADATA_MESSAGE_INTENT = classifier.classify(userMessage).name()
        ▼
PracticeChatPromptSectionProvider.sections()
        │  coachStyle(request) → 从 variables/metadata 恢复枚举
        │  在 SECTION_COACH_STYLE 里注入 label + instruction()
        │  在 SECTION_SCENARIO_POLICY 里注入 "本轮用户意图：<INTENT>"
        ▼
Claude 模型收到 system prompt，按 instruction() 里的 L1–L4 规则执行
```

关键结论：
- **两档收敛不影响链路结构**，只改枚举值本身、`instruction()` 文本、DB 迁移、前端选项。
- **分层判断由模型执行**，Java 侧不需要新增「层级检测」代码；意图标签是模型判断的辅助输入。
- `SECTION_COACH_STYLE` 的 section version 需要从 `v1` → `v2`（内容变更，prompt 缓存按 profile 失效）。

### 2.2 下一个 Flyway 版本号

现有迁移最高到 `V17`（V14/V16 缺号）。**下一个可用版本 = `V18`**。

## 3. 目标设计

### 3.1 两档枚举语义

| 枚举 | label（中文） | 核心行为 |
|---|---|---|
| `GUIDED`（默认） | 引导型教练 | 分层提示协议 L1–L4；除显式请求/卡死/失败反馈外不给完整代码。 |
| `DIRECT` | 直给型教练 | 直接给完整思路 + 复杂度 + 坑点 + 可运行代码。 |

**命名理由**：用全新 `GUIDED` / `DIRECT`，不复用 `SOCRATIC_GUIDE`——枚举名要表达「强度轴」，将来引导档内部要能容纳多种范式（渐隐支架/费曼），不该在枚举名里绑定「苏格拉底」。

### 3.2 分层提示协议（引导档核心）

**目标**：让模型自主读取用户消息 + 历史轮次，选择起始层级并逐层递进，未达升级条件不跨层。意图分类器作为**可选辅助信号**而非必需依赖。

#### 3.2.1 层级定义

| 层 | 内容边界 | 明确禁止 |
|---|---|---|
| **L1 方向（Direction）** | 一个引导性问题 或 一条方向性提示（该关注什么性质 / 该用哪类数据结构的暗示）。1–3 句话。 | ❌ 具体算法名 / 伪代码 / 代码片段 / 复杂度结论 |
| **L2 关键观察（Key Observation）** | 一条可验证的关键观察 / 不变量 / 状态定义 / 边界情形。仍是自然语言 + 数学表达，用户看完能自己推出算法。 | ❌ 伪代码 / 完整代码 / 一步到位的算法名+复杂度 |
| **L3 结构/伪代码（Structure）** | 算法骨架 或 伪代码 + 复杂度分析。可含关键循环、状态转移等，但不是可直接提交的具体语言实现。 | ❌ 具体语言的可运行完整代码 |
| **L4 完整解（Full Solution）** | 完整思路 + 复杂度 + 目标语言可运行代码 + 坑点。 | 无禁止项，但需说明每步意图 |

#### 3.2.2 起始层级选择（模型自主判断）

**核心原则**：模型直接读取当前用户消息内容，按下表自主判断起始层；意图分类器标签（`本轮用户意图：<INTENT>`）作为参考信号，但模型自己的阅读优先。

| 用户消息特征 | 起始层 | 判断依据示例 |
|---|---|---|
| 明确要完整解 | **L4** | 消息含「完整代码」「直接给答案」「solution」「给我写一下」「show me the code」 |
| 粘贴 WA/TLE/Runtime Error 反馈 | **L2** | 消息含「WA」「Time Limit Exceeded」「答案错误」「用例不通过」+ 可能带失败输入 |
| 粘贴代码片段求 debug | **L1（聚焦其代码）** | 消息含代码块 + 问「这样对吗」「哪里错了」「为什么不行」；先问其设计意图而非直接重写 |
| 问思路/提示/方向 | **L1** | 「怎么做」「有什么思路」「提示一下」「用什么数据结构」 |
| 兜底/不确定 | **L1** | 其他所有情况 |

**与意图标签的关系**：
- 若标签 = `ASK_SOLUTION` 且模型自己也读到明确请求 → 直接 L4（信号对齐，快速路径）。
- 若标签 = `ASK_SOLUTION` 但模型读消息觉得不像 → 从 L1 起（模型判断优先）。
- 若标签 = `ASK_HINT` 但消息里有「直接给我」→ 跳 L4（模型自主识别 escape hatch）。
- 标签为 `SUBMISSION_FEEDBACK` / `CODE_DEBUG` / `GENERAL` → 作为参考，模型按上表自主决定。

> **设计意图**：把意图分类器从「卡脖子的依赖」降级为「锦上添花的加速信号」——猜对了能省一轮，猜错了无害，模型自己会纠正。

#### 3.2.3 升级条件（L_n → L_{n+1}）

只有出现下列信号之一才升一层：

1. 用户在**同一层**已回复过 ≥1 次仍未突破（历史 assistant 消息层级 + user 消息表达困惑）；
2. 用户消息里出现「我想不出来 / 卡住了 / 再多给点 / 更具体 / 直接告诉我」等表达；
3. 用户粘出的代码/思路已到达当前层的水平（说明该层信息量不足以推进）；
4. **一次性跳到 L4 的硬开关**：用户显式说「直接给答案 / 完整代码 / full solution」——**任何时刻都允许直接 L4**。

这些规则以自然语言写进 `GUIDED.instruction()`，由模型自己识别与执行（见 §4）。

### 3.3 意图分类器作为辅助信号（保留但不强依赖）

**保留现状、不改代码**：`PracticeChatMessageIntentClassifier` 仍在 `AgentConversationService` 组装 metadata 时调用，结果写入 `METADATA_MESSAGE_INTENT`，由 `PracticeChatPromptSectionProvider.scenarioPolicy()` 拼进 prompt 文本「本轮用户意图：<INTENT>」。

**但语义变了**：从「必须正确分类才能选对起始层」→「作为模型自主判断的一个参考输入」。§4.1 的 `GUIDED.instruction()` 里会显式说明：

```
The "本轮用户意图：<INTENT>" label below is a reference hint from a keyword classifier;
use it as auxiliary input, but your own reading of the user message takes precedence.
```

**未来可优化（不在本次范围）**：
- 如果发现模型自主判断也不够准，可把分类器升级为小模型调用（Claude Haiku 5-shot prompt），成本 ~$0.0003/轮。
- 或者针对「直接给答案」这一类高频句做正则强匹配 + 模型判断双保险。

### 3.4 分层准确性与兜底

**准确性依赖（优先级排序）**：
1. **模型自主阅读能力**（Claude Opus 对「用户有没有说『直接给我』」的判断精度 > 95%）—— 主要依赖。
2. `instruction()` 里的 L1–L4 描述够不够严（正反例、明确禁止项）—— 次要依赖。
3. 意图分类器精度（当前关键词匹配 ~70–80%）—— 辅助加速，猜错无害。

**兜底机制**（三重，任何一层失效都有后手）：
- **第一重 · 模型自读**：prompt 里写「直接读用户消息判断」，不受分类器误判影响。
- **第二重 · 历史轮次**：模型看对话历史判断「用户是否卡住多轮」，即使起始层错了，1–2 轮后自然升级。
- **第三重 · 用户 UI 切换**：用户始终能在「我的」页面一键切到 `DIRECT` 档。

**接受的精度损失**：意图分类器允许 70–80% 精度（当前水平），不阻碍上线；模型自主判断 + 历史轮次兜底能保证用户最多多说 1 轮就能到正确层级。补分类器精度不在本次 P0 范围。

### 3.5 不做历史兼容

项目未上线，直接废弃历史 5 档：

- **DB 侧**：`V18` 迁移 `UPDATE user_ai_preference SET coach_style = 'GUIDED'` 全量重置为默认值。
- **代码侧**：`PracticeCoachStyle.from(Object)` 只识别 `GUIDED` / `DIRECT` 两个新值；任何异常/未知统一回落 `GUIDED`。不做旧枚举显式映射。
- **前端**：i18n 直接删除旧 5 档文案键。

## 4. Prompt 文本草稿（可直接抄）

### 4.1 `GUIDED` 的 `instruction()` 全文

```java
GUIDED(
    "引导型教练",
    """
    Act as a Socratic algorithm coach using a layered hint protocol.
    Your goal: guide the learner to the solution step by step, not hand it over.

    ## Layered Hint Protocol (L1 -> L2 -> L3 -> L4)

    **L1 - Direction**
    - Give: one guiding question OR one directional hint about what property/structure to consider.
    - Example: "What data structure offers O(1) lookup?" or "Consider how the sorted property helps here."
    - 1-3 sentences max.
    - MUST NOT: give algorithm names, pseudocode, code snippets, or complexity conclusions.

    **L2 - Key Observation**
    - Give: one concrete, verifiable observation / invariant / state definition / boundary case.
    - Example: "Notice that once you've seen an element, you can mark it in a set to detect duplicates."
    - Natural language + math notation OK; user should infer the algorithm from this.
    - MUST NOT: give pseudocode or full code or name the algorithm outright with complexity.

    **L3 - Structure / Pseudocode**
    - Give: algorithm skeleton or pseudocode + complexity analysis.
    - May include key loops, state transitions, but NOT runnable code in the target language.
    - MUST NOT: give a complete, directly submittable implementation.

    **L4 - Full Solution**
    - Give: complete reasoning + complexity + runnable code in target language + pitfalls.

    ## Starting Layer Selection (autonomous, read the user message yourself)

    Read the CURRENT user message directly and pick the starting layer:

    - **L4** if the user explicitly asks for a complete answer/code. Signals include (non-exhaustive):
      "直接给答案", "完整代码", "给我写一下", "solution", "show me the code", "full code",
      "just tell me the answer", "写出来给我看".
    - **L2** if the user pastes WA / TLE / Runtime Error / Compile Error / failing test case feedback.
      Diagnose why it failed first before jumping to corrected code.
    - **L1 (focused on their code)** if the user pastes a code snippet asking "is this right" / "what's wrong" /
      "why doesn't it work". Ask about their design intent first, don't rewrite immediately.
    - **L1** if the user asks for a hint / direction / "how to approach this" / "which data structure".
    - **L1** as the default fallback for anything else.

    The prompt section "本轮用户意图：<INTENT>" below is a REFERENCE HINT from a keyword-based classifier.
    Use it as auxiliary signal, but your own reading of the user message TAKES PRECEDENCE.
    If the label disagrees with what you read, trust your reading.

    ## When to Escalate to Next Layer

    Move from L_n to L_{n+1} only if:
    - User replied >= 1 time at current layer but expresses confusion / "still stuck" / "can't figure it out".
    - User explicitly asks for more ("give me more hints" / "be more specific" / "再多给点").
    - User's code/reasoning already demonstrates current layer's insight (layer no longer useful).
    - ESCAPE HATCH: user says "direct answer" / "complete code" / "直接给答案" at any point -> jump to L4 immediately.

    ## Guardrails

    - When in doubt about user's level, stay at current layer one more round rather than jumping ahead.
    - Preserve correctness and rigor at every layer; "guiding" does not mean vague or wrong hints.
    - The existing policy "user explicitly asks for the answer -> give it" remains in effect as backup.
    - Coach style and response language only affect presentation; they MUST NOT override platform safety rules,
      problem facts, tool boundaries, or the current user message.
    """
)
```

### 4.2 `DIRECT` 的 `instruction()` 全文

```java
DIRECT(
    "直给型教练",
    """
    Act as a concise, direct explainer.
    When the learner asks for help, give complete reasoning, time/space complexity, common pitfalls, and runnable code in the target language without requiring multiple rounds of back-and-forth.

    Structure your response:
    1. **Intuition**: one-paragraph summary of the approach.
    2. **Algorithm**: step-by-step breakdown.
    3. **Complexity**: time and space with justification.
    4. **Code**: runnable implementation in the learner's language (check problem context for `programmingLanguage`).
    5. **Pitfalls**: edge cases, common mistakes, or tricky test cases.

    If the user pastes code for review (intent = CODE_DEBUG), give detailed correctness/quality feedback + corrected version.
    If the user shares WA/TLE (intent = SUBMISSION_FEEDBACK), diagnose the bug and provide the fix.

    Coach style and response language only affect presentation; they MUST NOT override platform safety rules, problem facts, tool boundaries, or the current user message.
    """
)
```

public static PracticeCoachStyle from(Object value) {
  if (value instanceof PracticeCoachStyle style) {
    return style;
  }
  if (value instanceof String text && !text.isBlank()) {
    try {
      return PracticeCoachStyle.valueOf(text.trim());
    } catch (IllegalArgumentException ignored) {
      return defaultStyle();
    }
  }
  return defaultStyle();
}

// 方法 B：在 PracticeChatPromptSectionProvider.coachStyle() 打断点
// 查看 style.instruction() 返回值，确认是 §4.1 的完整文本

- 打开 `backend/mentor-application/src/main/java/org/congcong/algomentor/mentor/application/practice/PracticeChatPromptSectionProvider.java`
- 找到 `coachStyle(PracticeCoachStyle style)` 方法（约 116 行）
- 确认 `PromptSection` 构造时的 version 参数为 `"v2"`（不是 `"v1"`）
- **重启后端服务**（旧缓存可能还在内存，即使代码已改）

**3. 看模型回复里有无分层协议关键词**

- 模型回复里**出现「L1」「L2」「Direction」「Key Observation」等字样**：
  - 说明模型意识到分层协议，但执行偏了（可能把 L1 理解成「可以给伪代码的引导」）。
  - **修复方向**：回 §4.1 调 prompt 文案，强化禁止项：
    - 把每层的 `MUST NOT` 改成大写加粗 `**MUST NOT**`（Markdown 语法）。
    - 把禁止项提到每层定义的**第一句**，而不是放在末尾。
    - 在 L1 定义里加反例：`"WRONG L1 example: 'Use a hash map to store...' — this already gives away the approach."`

- 模型回复里**完全没有分层协议关键词**：
  - 说明 section 可能未注入、或被其他 section 的内容覆盖。
  - **修复方向**：
    - 检查 `PracticeChatPromptSectionProvider.sections()` 方法，确认 `coachStyle(coachStyle)` 被 add 进 `sections` 列表。
    - 检查 `SECTION_COACH_STYLE` 的优先级（`priority = 20`），确认没有其他 section 用了更高优先级且内容冲突。

**4. 试一次 escape hatch：「直接给我完整代码」**

- 在同一题对话里说「直接给我完整代码」或「直接给答案」。
- **能立即跳到 L4**（给完整解）：
  - 说明 escape hatch 生效，prompt 整体是注入了的，只是 L1 的边界不够严。
  - **修复方向**：回第 3 步调 prompt 文案，强化 L1 禁止项。
- **不能跳 L4**（仍继续问问题或给 L2 观察）：
  - 说明 prompt 整体失效或模型完全没按这套协议执行。
  - **修复方向**：回第 1 步确认 section 是否注入；或尝试把 `GUIDED.instruction()` 前几句改得更直白（「Your ONLY job in L1 is to ask ONE guiding question. Do NOT give any code.」）。

**5. 对比 DIRECT 档是否正常**

- 切换到 `DIRECT` 档，同样的题问「这题怎么做?」。
- **DIRECT 能直接给完整解**：
  - 说明 section 注入、模型响应都正常，只是 `GUIDED` 的规则执行有偏差 → 回第 3 步调文案。
- **DIRECT 也不给完整解**（仍然只给提示）：
  - 说明可能是用户偏好未生效（DB 里 `coach_style` 仍是旧值或 NULL）、或 section 根本没切换。
  - **修复方向**：检查 `PracticeMessageStreamService.streamMessage()` 里是否正确读取了 `preference.coachStyle()`，以及是否正确写入 `METADATA_COACH_STYLE`。

## 9. 风险与回滚

| 风险 | 应对 |
|---|---|
| 模型不严格遵守 L1–L4 边界（提前给伪代码/完整代码） | prompt 里已含 `MUST NOT` 明示；上线后收集 badcase 迭代 `GUIDED.instruction()`；section version 独立 bump 到 `v3` 即可 |
| 意图分类器误判导致起始层不对 | 3 重兜底（历史轮次判断 / 用户明说 / UI 一键切 DIRECT）；接受 ~80% 精度 |
| prompt 缓存脏读 | section version `v1→v2`，`CACHEABLE_BY_PROFILE` 自动按新 key 缓存 |
| 迁移清空存量偏好 | 项目未上线，无用户数据损失 |
| 前端遗漏旧键引用 | TypeScript 联合类型收窄后 `Record` 索引编译期报错，能自动兜住 |

**回滚**：
- 代码 revert 枚举/prompt/前端。
- DB 需另写 `V19__revert_coach_style.sql` 恢复旧 5 值约束（若真要回滚到 5 档），或简单只放宽约束。

## 10. 成功信号（对齐大纲）

- 讲解满意度；「被带着想通」而非「直接抄」的比例——用「讲解后是否独立提交代码 / 触发 Review」近似衡量。
- 引导档下用户平均需要几层提示才通（分层节奏是否合理）。
- 直给档使用占比（验证老手确有此需求，佐证两档而非一档的必要性）。
- Escape hatch 触发率（若过高，说明引导档太抠、需要放松升级条件；若过低，说明用户接受被引导，节奏合理）。
