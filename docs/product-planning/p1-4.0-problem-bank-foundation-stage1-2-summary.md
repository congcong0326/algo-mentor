# P1-4.0 题库基座阶段一/二总结与后续建议

## 背景

本文件记录 `algo-mentor` 题库基座阶段一（官方 API 原始抓取入本地）和阶段二（数据画像与只读校验）的当前结果，并给出阶段三之前的产品与工程建议。

本轮工作只完成抓取、缓存、画像和校验；尚未进入数据加工、AI 翻译、seed 生成或入库。

## 当前产物

已新增阶段一/二工具：

- `tools/problem_seed/fetch_problem_index.py`：抓取 `leetcode.com` 与 `leetcode.cn` 全量清单，生成 union 索引。
- `tools/problem_seed/fetch_problem_details.py`：按 union 索引抓取两站 GraphQL 单题原始 JSON，支持限速、重试和断点续抓。
- `tools/problem_seed/profile_problems.py`：基于本地缓存做五类画像。
- `tools/problem_seed/validate_seed.py`：对可归一题做只读校验。
- `tools/problem_seed/leetcode_api.py`：LeetCode API、GraphQL 查询、JSON/JSONL、缓存路径等共享工具。
- 对应 `*_test.py` 单测覆盖清单解析、union 合并、详情缓存、断点跳过、五类分类、frontendId 差异和校验规则。

本地产物位于：

- `data/index/problem_index.jsonl`
- `data/index/manifest.json`
- `data/sources/leetcode-api/{slug}.com.json`
- `data/sources/leetcode-api/{slug}.cn.json`
- `data/reports/profile_report.json`
- `data/reports/validation_report.json`

这些 `data/` 产物是本地抓取数据，不应提交仓库；`.gitignore` 已补充 `data/index/` 和 `data/reports/`。

## 关键结论

1. `complete` 题质量足够作为第一批主题库底座。
   - 3202 题中英文题面齐全。
   - 可归一校验 0 问题。
   - `.com/.cn frontendId` 无不一致。

2. 当前不需要优先建设 AI 翻译链路。
   - `zh_missing=0`，没有“英文有、中文缺”的问题集。
   - 先引入 AI 翻译会增加成本、质量评审和回滚复杂度，但短期收益不明显。

3. `cn_only` 有产品价值，但需要单独策略。
   - 共 389 题，主要包括 LCP、LCR、剑指 Offer、面试题以及中文站独有题。
   - 当前 `problem` 表要求 `title_en`、`content_markdown_en`、`title_zh`、`content_markdown_zh` 非空。
   - 若直接导入，需要决定英文侧如何处理，并保留内容来源状态，避免把中文内容误当英文内容。

4. `premium_locked` 不适合进入默认练习题库。
   - 共 774 题。
   - Premium 题通常拿不到题面，只能拿到题号、slug、难度、是否付费等索引元数据。
   - 不应绕过受锁题面，也不应在系统内展示不可验证的题面。

5. `roman-to-integer` 需要单独复核。
   - 这是免费核心题，但本轮 `.com` GraphQL 返回 404。
   - 不建议仅凭本次异常把它长期按 CN-only 处理；阶段三前应重试或人工核对接口状态。

## 导入建议

### 第一批：导入 `complete`

建议阶段三第一版只导入 `complete` 3202 题。

理由：

- 满足当前 `problem` 表中英文字段和 tag 数组约束。
- 不需要 schema 变更即可进入现有 `ProblemSeedImporter` 链路。
- 覆盖当前免费主站题的绝大多数可用内容。
- 风险集中在 HTML 转 Markdown、代码模板读取、样例字段口径等可测试逻辑上。

### 第二批：评审后导入 `cn_only`

建议先生成 `cn_only` 审核清单，再决定是否导入。

可选策略：

| 策略 | 说明 | 建议 |
|---|---|---|
| 暂不导入 | `cn_only` 只保留在报告中 | 最保守，适合先快速上线主题库 |
| 导入但标记 `CN_ONLY` | 英文侧临时回填中文，并显式记录内容状态 | 实用，但需要新增状态字段或元数据 |
| 调整 schema 后导入 | 允许英文题面为空或增加内容覆盖状态 | 长期更干净，但阶段三工作量更大 |

推荐做法：

- 第一版先不混入默认题库。
- 单独输出 `cn_only` 清单，按 LCP、LCR、剑指 Offer、面试题、其他中文站题分组评审。
- 若确定面向中文用户收录价值高，再增加内容状态字段后导入。

### 不导入默认题库：`premium_locked`

建议 `premium_locked` 不进入默认练习题库。

可以保留为：

- 外链索引
- 覆盖率统计项
- 后续官方差异追踪项
- 用户看到的“需跳转 LeetCode Premium”占位项

但不建议在系统内作为可练习题展示。

### 暂无动作：`zh_missing`

当前 `zh_missing=0`，暂不需要：

- AI 翻译流水线
- 英文题面回退中文展示策略
- 翻译质量评审流程

这些能力可作为未来增量抓取后出现缺口时再启动。

## 阶段三建议待办

### 1. 复核异常题

- 对 `roman-to-integer` 的 `.com` GraphQL 重新小批请求。
- 若仍 404，记录为官方接口异常，并决定是否从 `.cn` 题面临时收录。
- 对 `maximum-frequency-score-of-a-subarray` 按 Premium 受锁处理即可。

### 2. 改造 `prepare_seed.py`

输入源从旧的 `fishjar/leetcode-problemset` 改为本地官方 API 缓存：

- 读取 `data/index/problem_index.jsonl`
- 读取 `data/sources/leetcode-api/{slug}.com.json`
- 读取 `data/sources/leetcode-api/{slug}.cn.json`
- 第一版仅处理 `complete`
- 复用现有纯函数：
  - `html_to_markdown`
  - `read_tags`
  - `read_difficulty`
  - `normalize_slug`
  - `first_non_empty`
  - `nested`

### 3. 明确字段映射

第一版 `complete` 固定映射：

| `problem` 列 | 来源 |
|---|---|
| `slug` | `.com titleSlug` |
| `frontend_id` | `.com questionFrontendId` |
| `title_en` | `.com title` |
| `title_zh` | `.cn translatedTitle` |
| `difficulty` | `.com difficulty` |
| `tag_values` | `.com topicTags[].slug` |
| `tag_labels_en` | `.com topicTags[].name` |
| `tag_labels_zh` | `.cn topicTags[].translatedName`，缺失回退英文 |
| `content_markdown_en` | `.com content` 经 `html_to_markdown` |
| `content_markdown_zh` | `.cn translatedContent` 经 `html_to_markdown` |
| `leetcode_url` | `https://leetcode.com/problems/{slug}/` |
| `sample_test_case` | `sampleTestCase` / `exampleTestcases` |
| `python3_template` | `codeSnippets[langSlug=python3].code` |
| `source_commit` | 抓取快照标识，如 `leetcode-api@2026-07-02` |

### 4. 生成 seed 并跑校验

- 输出 `data/seed/problems.jsonl`
- 继续输出空的分类 seed 文件，保持现有 importer 兼容：
  - `problem_categories.jsonl`
  - `problem_category_items.jsonl`
- 跑 `validate_seed.py` 或扩展后的 seed 校验，保证：
  - `slug` 唯一
  - `frontendId` 唯一
  - `title_zh` / `content_markdown_zh` 非空
  - tag 三数组等长
  - URL slug 一致

### 5. 小批入库验收

建议先导入 50 到 100 题做人工抽样：

- 标题中英是否对应
- 题面 Markdown 是否可读
- 示例与代码模板是否正常
- tag 中英文标签是否对齐
- 后端列表、详情、搜索和练习入口是否正常

小批通过后再全量导入 3202 题。

### 6. 再决策 `cn_only`

`complete` 全量稳定后，再单独开一个小决策：

- 是否收录 LCP / LCR / 剑指 Offer / 面试题
- 是否新增 `content_status`、`source_site`、`is_premium` 等字段
- 英文侧缺失时是允许为空、回填中文，还是后续再做翻译

## 风险与注意事项

- 官方 API 行为可能变化，后续增量抓取需要保留 manifest 和报告。
- Premium 题不应抓取或展示受锁题面。
- CN-only 题存在非数字 `frontendId`，例如 `LCP 82`、`LCR 075`，当前 `problem.frontend_id INTEGER` 不兼容，若要导入需先定 schema 策略。
- 中文站独有 slug 可能包含大小写，抓取阶段已保留官方原始 slug；入库前若规范化需评估是否会影响 URL。
- 当前 `source_commit` 字段被建议复用为抓取快照标识，后续可考虑迁移为 `source_snapshot`。

## 当前推荐路线

1. 阶段三第一版：只加工并导入 `complete` 3202 题。
2. 导入前：单独复核 `roman-to-integer` 的 `.com` 404。
3. 导入后：用后端功能做 50 到 100 题抽样验收。
4. 第二轮：评审 `cn_only` 389 题的产品价值和 schema 方案。
5. 暂不建设 AI 翻译；等未来出现 `zh_missing` 或确定收录 CN-only 后再设计。
6. `premium_locked` 仅保留外链索引和覆盖率统计，不进入默认练习题库。
