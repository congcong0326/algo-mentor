# 用户分层痛点分析与路线图校准

> 视角：产品经理，从「不同能力/不同目标的真实用户」出发，回答三个问题：
> 1. 刷题过程中，各类用户的真实痛点是什么？
> 2. 本产品当前形态与路线图，能否解决这些痛点？
> 3. 从用户角度看，`product-roadmap.md` 的规划是否合理？需要怎么校准？
>
> 结论先行：**产品的能力方向大体对，但优先级和产品形态存在一个结构性偏差——路线图默认「用户 = 有充裕时间、愿意跟长计划的人」，而真正大基数且强付费的群体（求职冲刺者）要的往往不是「计划」，而是「高频题单 + 查漏补缺 + 模拟面试 + 可信反馈」。** 下文给出校准建议。

---

## 一、先分人群：谁在刷题、谁会付费

刷题人群高度异质，**决定付费意愿的不是能力高低，而是「目标是否明确 + ROI 是否清晰 + 是否焦虑」**。按此拆分：

| 人群 | 基数 | 付费意愿 | 特征与心态 |
|---|---|---|---|
| **① 校招求职学生** | 🔴 大 | 🔴 强 | 有明确 deadline 和 ROI（拿 offer），焦虑，愿为「提高上岸概率」付费。刷题产品的历史核心付费盘（LeetCode 会员、代码随想录、labuladong 的主力用户）。 |
| **② 社招跳槽工程师** | 🟡 中 | 🔴 极强 | 时间极少、钱不敏感、目标精准（大厂面试）。ARPU 最高，最愿为「省时间、直击考点」买单。 |
| **③ 转码/非科班/训练营** | 🟡 中 | 🟠 强 | 焦虑最重、基础最弱，愿意付费但需要更多手把手扶持，服务成本高、易流失。 |
| **④ 在校非毕业班 / 兴趣提升** | 🔴 大 | 🟢 弱 | 没有紧迫 ROI，免费资源即可满足，付费转化低。 |
| **⑤ 竞赛选手（OI/ACM）** | 🟢 小 | 🟢 弱 | 能力强、不需要教练、有成熟免费生态，几乎不是目标客户。 |
| **⑥ 在职维持手感** | 🟡 中 | 🟠 中 | 低频、佛系，付费看性价比。 |

**优先级结论**：**主攻 ① 校招求职（要基数）+ ② 社招跳槽（要 ARPU）**，这两类是「大基数 × 强付费」的交集，也是所有算法学习产品验证过的付费盘。③ 转码作为第二梯队。④⑤⑥ 不作为付费设计的主要对象（可作为免费流量池/口碑层）。

> **这条结论是校准路线图的标尺**：凡是服务 ①②，尤其能缩短「刷题→拿 offer」路径的功能，优先级应上调。

## 二、按能力分层：刷题过程中的真实痛点

同一个「求职」目标下，不同能力的人卡在不同环节。把痛点拆细，才能判断产品是否真的对症。

### 新手 / 转码（不会写、看题没思路）
- **P1 不知道从哪开始、按什么顺序**：面对上千道题无从下手。
- **P2 看题解看不懂**：题解跳步骤、默认你会前置知识。
- **P3 卡住没人问、容易放弃**：孤独感强，坚持不下去是最大杀手。
- **P4 抄完答案的错觉**：看懂 ≠ 会写，下次还是不会。

### 初级（会基础，一到中等题就卡）
- **P5 有思路写不出 / 写出来不知道对不对好不好**：缺即时、针对性的反馈。
- **P6 学了就忘、错题重复错**：没有系统复习，遗忘曲线赢了。
- **P7 不知道自己薄弱在哪**：盲目刷，盲区一直是盲区。

### 中级（能做中等题，冲刺面试/难题）
- **P8 缺系统性、查漏补缺低效**：会的反复做，不会的绕着走。
- **P9 代码能过但质量差 / 复杂度不优**：面试会被追问，自己看不出。
- **P10 面试临场紧张、缺实战演练**：会做题 ≠ 面得好。
- **P11 时间紧、要高频考点而非大而全**：社招尤其没时间上长课程。

## 三、产品能否解决这些痛点？逐条对账

| 痛点 | 当前/规划中的对应能力 | 解决程度 | 说明 |
|---|---|---|---|
| P1 不知从哪开始 | AI 学习计划 + 分阶段推荐 | 🟢 解决 | 核心钩子，尤其打中新手/转码。 |
| P2 题解看不懂 | AI 流式讲解（可追问） | 🟢 解决 | 「随手问、讲到懂」是相对静态题解的核心增量。 |
| P3 卡住没人问、坚持不下去 | AI 讲解 + 进度看板 + streak + 成长报告 | 🟠 部分 | 讲解解决「没人问」；但「坚持」还依赖 P0 的复习提醒/每日任务落地。 |
| P4 抄答案的错觉 | 教练风格「引导式」+ 完成门槛 | 🟠 有风险 | **这是产品的成败点**：若 AI 默认直接给答案，会亲手制造「抄答案幻觉」，反而害人。必须默认引导式（见校准建议）。 |
| P5 写不出/不知好坏 | 结构化代码 Review + 真实判题 | 🟠 部分 | Review 方向对；但「正确性」靠 LLM 判断，对求职群体**可信度不足**（真实判题目前仍是缺口）。 |
| P6 学了就忘 | 错题本 + 间隔重复（P0，规划中未实现） | 🔴 未实现 | 留存核心机制，当前空白，已列 P0。 |
| P7 不知薄弱在哪 | 能力画像 + 知识点维度（P1） | 🟠 部分 | 能力画像已有；知识点维度尚未落地。 |
| P8 查漏补缺低效 | 计划随能力动态调整（P1） | 🔴 未实现 | 计划目前偏静态。 |
| P9 代码质量/复杂度 | 代码 Review 多维评分 | 🟢 解决 | 已是差异化强项。 |
| P10 面试临场 | 面试模拟（P2） | 🔴 未实现且排序偏后 | **对最高付费群体②是杀手锏，却被放到 P2**（见校准）。 |
| P11 要高频考点、没时间上长课 | —— | 🔴 缺形态 | **当前产品过度 plan-centric，缺「冲刺/高频题单」入口**（见校准，最关键的一条）。 |

**总体**：产品的**能力方向覆盖了绝大多数痛点**，尤其 P1/P2/P9 已是强项，P3/P6/P7 的规划也对。但有 **4 个从用户视角看必须修正的地方**，见下一节。

## 四、从用户角度，路线图需要的 4 处校准

### 校准 1（最重要）：产品形态要有「双入口」，不能只有长计划
- **问题**：`product-roadmap.md` 的核心旅程是「生成一份多周计划 → 按计划走」。这**非常适合新手/在校学生（③④和部分①）**，但**严重不匹配社招②和临近面试的求职①**——他们没时间上多周课程，要的是「大厂高频题单 / 按公司按考点 / 我哪块弱就补哪块」。逼他们先配置一个长计划，是**劝退式摩擦**。
- **校准**：产品应支持**两种入口并存**：
  - **系统学习模式**（现有长计划）：面向时间充裕的新手/学生。
  - **冲刺模式（新增，建议 P0/P1）**：直接给「高频考点题单 / 按主题速练 / 查漏补缺」，跳过长计划配置，几分钟内开练。这是抓住**最高付费群体②**的关键形态，且技术上可复用现有题库+推荐+Review，成本不高。
- **一句话**：**别让所有人都先「上课」，冲刺者要的是「直接练 + 帮我押题」。**

### 校准 2：真实判题应从 P1 前移（对付费群体是信任门槛，不是加分项）
- **问题**：路线图把真实判题放 P1。但对核心付费群体①②，「AI 说我对」远不如「跑通了 N/M 用例」有说服力——**没有真实判题，严肃求职者不会把它当主力工具**，会退回 LeetCode。这是**信任门槛**，不是锦上添花。
- **校准**：至少把「样例用例的真实运行」作为 **P0 尾/P1 头** 的 MVP 先上（哪怕只支持 Python/Java、只跑题目自带样例），让 Review 的「正确性」有客观支撑。全量判题可后续完善。

### 校准 3：面试模拟应提到「战略功能」位置（不是 P2 边角）
- **问题**：面试模拟被放在 P2。但它直击**付费意愿最强的②社招 + 冲刺期①**的核心痛点 P10，且是天然的差异化与（未来）付费卖点。
- **校准**：在核心闭环（P0）稳固后**尽快启动**，标记为「面向最高付费群体的战略功能」，不必等所有 P1 做完。可先做轻量版（限时出题 + 追问 + 表现复盘）。

### 校准 4：把「防抄答案」升为核心设计原则（关乎「是否真有帮助」）
- **问题**：AI 讲解若默认直接给答案，会制造 P4「抄答案幻觉」——用户以为学会了，面试原形毕露。这会**摧毁产品的口碑与真实价值**（「用了没进步」= 不会付费）。
- **校准**：把**引导式（苏格拉底、分层提示、卡太久才逐步加提示）设为默认**，「直给」只作为用户显式选择或长时间卡死后的兜底。教练风格不只是「措辞差异」，而是「是否真的让人学会」的产品底线。

## 六、结论

1. **路线图的能力方向基本合理**，对痛点覆盖度高，P0 的错题本/看板/Onboarding 判断正确。
2. **最大的用户视角偏差是「过度 plan-centric」**：只服务了有时间上长计划的人，漏掉了付费意愿最强的社招/冲刺群体。**补一个「冲刺模式」入口是当前性价比最高的动作。**
3. **真实判题**对目标付费群体是**信任门槛**，应前移；**面试模拟**是最强付费点，应提前到战略位置。
4. **防抄答案（引导式默认）**必须作为核心原则——它决定「用户是否真的变强」，而这正是这个产品区别于「一个会写代码的聊天机器人」、最终值得付费的根本。

> 一句话：**先服务好「有 deadline、要拿 offer」的人，用「冲刺题单 + 可信判题 + 引导式教练 + 模拟面试」直击他们的 ROI，产品的付费根基就立住了。长计划是给新手的入口，不该是所有人的必经之路。**
