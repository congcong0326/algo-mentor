# Java 基础总览

学 Java，通常从变量、循环和方法开始。再往后，会接触对象、集合、异常、泛型，以及越来越多的标准库。刚开始看，这些内容有些零散；写过一些程序后，会发现它们经常一起影响同一件事。

比如，把一个对象传给方法，涉及参数传递；方法修改了对象，涉及引用和可变性；这个对象恰好又是 Map 的键，就可能影响后面的查找。理解这些联系，能帮助我们看懂代码为什么这样运行，也更容易判断一种写法是否合适。

Java 基础主要讨论语言规则和常用标准库。这里以 Java 17 为背景，先了解几部分知识各自解决什么问题，以及哪些认识值得优先建立。

## 类型与数据

类型决定一个值能表示什么、可以怎样使用。Java 会在编译时检查许多类型约束，这让一部分错误在程序运行前就能被发现。但具体选什么类型，仍然需要理解数据本身。

例如，价格可以用浮点数表示，也可以用 BigDecimal 表示，两者处理精度的方式不同。日期时间也有区别：记录一次操作发生的时刻，与安排某个地区明天上午九点的活动，需要的信息并不一样。标准库提供多种类型，是因为这些需求确实存在差别。

因此，这部分除了熟悉基本类型、运算和转换，还要了解数值范围、精度、空值和文本编码。它们直接影响数据是否被正确表达。很多看似细小的问题，到了实际业务里就会成为重要的边界。

## 对象与程序组织

对象把相关的数据和行为放在一起。程序通过引用访问对象，也可以让多个位置共享同一个对象。共享很方便，但意味着修改可能影响其他使用者，所以对象与引用的区别值得尽早弄清楚。

在此基础上，封装、接口、继承和组合帮助我们组织较大的程序。封装让对象有机会维护自己的状态约束，接口让使用方知道可以依赖哪些行为，继承与组合则提供不同的复用方式。

这些概念在简单例子里有时显得多余。代码多起来之后，它们的作用会更明显：一个实现发生变化，是否需要连带修改很多调用者；一份数据被改动，能否找到负责维护它的地方。理解这些问题，再看面向对象的各种写法，会更容易知道为什么这样设计。

这一部分应先掌握对象如何被创建、传递、共享和修改，再理解类型之间怎样协作。相等性、不可变性和对象拷贝，都与这些日常操作有关。

## 常用数据结构与数据处理

数组和集合用于管理一组数据。List 保留元素的位置和顺序，Set 表达去重后的元素集合，Map 建立键与值的对应关系。先想清楚需要表达哪种关系，通常就能缩小选择范围。

这里有一个容易忽略的地方：去重依赖“什么算相同”。同一道题的两次练习，在统计做过多少道题时可以合并，在查看练习历史时却应该保留。因此，对象的比较规则和数据的组织方式，需要一起考虑。

泛型让容器和通用方法能够复用，同时对使用的类型施加约束。Lambda 可以把一段处理行为传给方法，Stream 则适合表达筛选、转换和汇总。这些能力经常配合使用，但各自解决的问题不同：类型是否合适、行为如何传递、数据怎样处理。

入门时，先熟悉常见容器的用途和操作约束，再了解具体实现的性能特点。能够根据需求解释自己的选择，比一开始就记住所有内部细节更有帮助。

## 异常、I/O 与资源管理

程序读写文件或调用外部服务时，需要同时处理正常结果和失败情况。文件可能不存在，数据格式可能不正确，连接也可能中断。异常机制用来表达和传递这类失败，调用者再根据自己的职责决定怎样处理。

例如，查询没有找到记录和查询执行失败，通常不应该都被处理成空列表，否则调用者就无法区分两种情况。理解异常的重点，也包括判断哪些信息需要保留、哪一层有能力处理失败。

I/O 还涉及字符与字节之间的转换、缓冲以及资源释放。Java 有垃圾回收，但文件和连接的使用期限仍然需要明确管理。把异常和资源管理放在一起学习，是因为释放资源既要考虑正常结束，也要考虑操作中途失败。

## 编译、运行与扩展机制

Java 源代码通常先编译成字节码，再由运行环境加载和执行。JDK、包、类路径和依赖，分别参与这段过程。了解它们，可以帮助我们区分编译错误、依赖缺失和运行环境不兼容等问题。

反射、注解、动态代理和 SPI 则提供了更灵活的组织方式。例如，程序可以在运行时读取类型信息，或者根据配置选择具体实现。这些能力在框架中很常见，也会让一部分行为无法只从普通的方法调用中看出来。

学习这部分时，先理解它们的用途，以及相对普通调用增加了哪些能力。等到需要阅读框架或实现扩展功能时，再深入具体机制，会更有针对性。

## 学习时先抓住什么

类型与值、对象与引用、类与接口、异常与资源管理，是最值得优先理解的部分。它们影响的范围很广，后面的集合、并发和框架知识都会反复用到。

常用标准库需要结合实际操作逐渐熟悉，尤其要留意相等规则、可变性、精度和空值等使用约束。至于源码实现、运行时优化和少见的语法边界，可以在遇到具体疑问时继续深入。

熟悉 Java 基础之后，应该逐渐能够解释一段代码的行为：数据有没有被复制，修改会影响哪些地方，选用的类型是否符合需求，失败之后会发生什么。这些判断会直接用在平时的编码和排查问题中。
