# 对象、引用与生命周期总览

<a id="objects"></a>

Java 对象是程序中承载状态和行为的具体实体。例如，一条题目信息可以包含标识、标题和难度，也可以提供检查或更新这些状态的方法。对象让相关信息能够作为一个整体被使用，引用则让程序的不同位置能够访问这个整体。

理解对象，需要同时考虑它是什么、如何被访问、状态如何变化，以及何时不再被需要。这些方面共同决定了一次方法调用会产生什么影响。

## 对象与引用承担不同职责

对象保存状态，引用表达对对象的访问关系。一个对象可以被多个变量引用，变量也可以先后引用不同对象。因此，“把一个对象交给另一段代码”可能只是共享了访问它的方式，并没有创建一份独立数据。

这种共享让程序可以围绕同一份状态协作。例如，两个位置持有同一条题目记录，其中一个位置修改标题，另一个位置随后读取时会看到修改后的标题。与此同时，仅仅改变某个变量的指向，并不会改变其他变量原先引用的对象。

变量赋值、参数传递和对象拷贝都需要放在这个区分下理解。最先建立的认识应当是：哪些操作改变访问关系，哪些操作改变对象本身。

## 对象的使用从建立有效状态开始

创建对象时，初始化和构造过程负责建立它的初始状态。设计一个类型时，需要决定哪些数据必须在创建时提供、哪些条件始终应当成立，以及哪些操作可以改变它。

这也是封装的重要作用。调用者通过明确的方法使用对象，对象内部负责维护状态之间的约束。如果内部可变数据被任意暴露，外部代码就可能绕过这些约束，导致对象虽然存在，却已经不再代表一份有效信息。

对象不再可达后，其内存可以由垃圾回收机制处理；但对象可能同时代表一个文件或连接，这些外部资源仍需要明确的使用期限和释放责任。内存可回收与资源已关闭是两个不同的问题。

## 共享状态为何需要约束

可变对象适合表达会发生变化的信息，共享它们时也需要知道谁能够修改、修改会影响谁。复制可以隔离部分影响，但复制的深度决定内部数据是否仍然共享。

不可变对象提供了另一种选择：创建后保持其对外可见的值稳定，因此更容易被安全地共享和理解。是否不可变取决于类型如何管理自身状态；限制某个变量重新赋值，并不足以固定对象内部的全部内容。

这里最重要的是区分变量、对象和对象内部引用的数据。只有明确修改发生在哪一层，才能判断封装、复制或不可变设计是否真正达到了预期。

## 比较对象需要明确含义

两个对象可以分别创建，却表示同一个题目标识。于是，程序需要区分对象身份与逻辑相等：身份关心是不是同一个对象，逻辑相等关心是否满足类型定义的等价条件。

这种区分会影响对象如何参与查找、去重和数据更新。如果类型作为键使用，相等规则和相关状态的稳定性尤其重要；否则，同一份业务信息可能在不同操作中得到不一致的判断。

在这一层级，应优先理解引用与共享、有效状态、可变性和比较语义。具体初始化顺序、拷贝方式与比较方法的细节建立在这些认识之上；对象内存布局和垃圾回收算法则属于更深的运行机制。
