## 01 程序如何编译与运行

**总览要回答**：一段 Java 源码经过什么过程成为正在运行的程序？

覆盖：JDK/JVM 与运行环境的职责；源文件、包、class、JAR；`javac` 与 `java`；类路径与依赖；编译期、运行期错误；版本与目标字节码的基本关系。JIT/GC 仅作入口介绍。

**总览重点**：先区分源码、字节码与运行环境的职责，以及编译成功和具备运行条件的区别；它们决定错误应在哪一层定位。编译优化策略只需建立用途上的认识。

卡片候选：

- JDK、JVM 和 JRE 概念分别承担什么职责，为什么现代 JDK 不一定单独分发 JRE？
- `.java` 到程序运行之间有哪些步骤？
- 编译成功为什么仍可能出现找不到类或字节码版本不兼容？
- `classpath`、包名和 `import` 分别解决什么问题？

参考：G 基础上篇；B `overview/`；O 第 2、3 章；D Getting Started。项目联系：`backend` 的 Java 17/Maven 构建。

## 02 类型、变量与表达式

**总览要回答**：程序如何表示数据，以及语言如何约束一次计算？

覆盖：基本类型与引用类型、字面量、变量与作用域；默认初始化和明确赋值；数值范围、整数溢出、浮点精度；提升、转换、装箱与拆箱；运算符与短路；分支、循环、方法签名与可变参数。`var` 是局部类型推断，不是动态类型。

**总览重点**：优先理解类型限制、值的范围、引用可空性与隐式转换；这些规则直接影响计算结果和错误表现。少见运算符边界在卡片中深入。

卡片候选：

- 成员变量有默认值，为什么局部变量仍可能报未初始化？
- 自动拆箱为什么会抛出 `NullPointerException`？
- `int` 运算溢出会自动变成 `long` 吗？
- `Integer` 的 `==` 为什么不能当作通用数值比较？
- `&&` 与 `&` 用于布尔表达式时有什么差别？

参考：G 基础上篇；B `basic-grammar/`；O 第 3—5 章；JLS 第 4、5、14、15 章。

## 03 对象、引用与生命周期

**总览要回答**：变量与对象是什么关系，修改、传递和比较对象时发生了什么？

覆盖：对象身份、引用与别名、`null`；值传递；构造与初始化顺序；`static`、`final`；可变性、防御性拷贝、浅拷贝与深拷贝；`Object` 的相等和哈希契约；可达性与资源释放的区别。内存区域和 GC 算法留给 JVM。

**总览重点**：优先理解对象与引用的区别、共享状态的影响以及相等性的含义；它们共同决定修改和比较是否符合预期。初始化顺序与拷贝细节由具体问题展开。

卡片候选：

- 两个变量指向同一个对象意味着什么？（C01）
- Java 为什么只有值传递，方法却可以修改对象？（C02）
- `final` 引用为什么不等于不可变对象？（C03）
- 引用上的 `==` 与 `equals()` 有何区别？（C04）
- `equals()` 应满足哪些约束？（C05）
- 为什么按逻辑相等重写 `equals()` 时要同时保证 `hashCode()` 契约？（C06）
- 用作 Map 键之后，为什么不应修改参与相等与哈希计算的字段？（C07）
- 浅拷贝后修改嵌套对象，原对象为什么也可能发生变化？

参考：G 基础中篇和值传递专题；B `oo/`、`basic-extra-meal/`；O 第 3、6 章和对象传递、相等性附录；JLS 4.3、4.12.4、15.12.4.5 与 Object API。已有[对象介绍](object-overviews.md)和[相等性介绍](equality-overview.md)，两篇正文独立成文。

## 06 数组与批量数据入门

## 编写顺序与边界规则

编辑时可参考的基础学习顺序为 01 → 02 → 03 → 04；随后 05/06 可并行阅读，07 → 11、04/06 → 08 → 09、02/05 → 10、04 → 12 是几条局部学习路径。03 中解释相等性时只需要 Map 的“用键找值”意图；不把 HashMap 源码设成前置，避免与集合分支形成学习循环。

本版先重写基础、对象与相等性三篇介绍，以同一组 8 张卡片检查背景是否有助于理解具体问题；C08 放在字符串主题，通过卡片关系体现跨主题联系。后续可用 07/11 检查失败与资源背景，用 08/09 检查类型与数据处理背景。判断总览是否有效的依据是整体认识，不是文章中是否逐卡讲解或列出链接。

Java 8 的 Lambda/Stream、Java 9 模块、Java 16 record/instanceof 模式匹配、Java 17 sealed 类型按概念归位并标注版本，不另建一棵重复的“新特性知识树”。Java 17 的预览特性不进入基础必修；虚拟线程等更新特性进入后续扩展。历史特性与实现细节不能写成语言永久保证。
