# 知识大纲维护流程优化

## 目标与范围

本轮解决 Java 基础大纲维护中出现的编号混入标题、`I/O` 被拆成目录而漏扫、叶子 README 重复，以及内容校验与导入重复构建的问题。

保留 `.node` 目录作为系统正式大纲来源。主题目录中的 `outline.json` 是编辑清单，用于生成与核对目录，不作为第二套运行时内容模型。标题默认无编号，顺序仍沿用目录名排序。

## 编辑清单与生成

- 清单使用 `version: 1` 与 `children`；每个节点包含 `title` 和可选的 `children`。
- 清单管理所在 `.node` 目录的全部后代节点。路径必须由连续 `.node` 目录组成，标题禁止路径分隔符、控制字符、空白边界与相对路径名称。
- 预览列出缺少、额外节点与结构错误。检查比较完整路径集合，不以节点总数代替。
- 应用前完成全部校验；只补建缺少的目录及空叶子的 `.gitkeep`，不删除、覆盖、自动改名或移动内容。存在额外节点时停止应用，由维护者先明确迁移已有内容。
- 主题级 README 集中记录范围和固定版本的参考来源；叶子不再生成重复的 README。

## 校验与构建

`make knowledge-validate`、`make knowledge-import` 先运行大纲检查，再准备 Java 导入工具。普通目录仍不导入；若正式 `.node` 内的普通目录藏有 `.node`、`.card.md`、`.article.md`，检查直接报出漏扫路径。根级参考目录不扫描，主题下的 `references`、`skills` 是明确允许的维护目录。

构建缓存记录后端源码、资源、POM、Maven 项目配置、构建命令、Java 版本与成品 JAR 的内容摘要。内容清单和 Markdown 变化不触发 Maven；源码新增、修改、删除、成品变化或缺失均重建。强制重建仍可通过 Make 命令执行。缓存保存在已忽略的 `.cache/knowledge-cli/`。

## 本轮边界

目录差异预览不等于数据库导入预览。数据库导入仍为全量替换，按当前会话授权执行，既有 slug 与复习数据语义不变。全库仅有目录而没有卡片或文章时，现有导入器仍拒绝空内容快照；纯大纲支持与数据库差异预览留给独立改动。

## 验证

使用临时目录覆盖非法标题、同数量路径偏差、漏扫目录、维护目录排除、符号链接、重复生成与已有内容保留。构建测试覆盖内容变化复用、源码删除失效、成品变化与构建失败。最后对当前 Java 基础清单执行检查、幂等生成和两次真实 Java 校验，确认第二次复用构建。

本轮验证结果：`make knowledge-tools-test` 的 13 项测试通过；大纲预览、重复生成和完整性检查通过。`make knowledge-validate` 连续两次通过，第二次输出“复用知识库导入工具”，均识别 90 个正式节点、2 张既有卡片和 1 篇既有文章。Java 基础保持 14 章、72 个子主题，原有示例内容逐字节一致。
