# 公开首页与产品演示设计

> 日期：2026-08-20  
> 状态：待实施  
> 范围：未登录访问者的 `/` 首页；不改变登录后学习工作台、既有 API 或学习计划领域契约。

## 1. 背景与目标

当前未登录首页复用了登录后产品的概览组件，无法在首次访问时清楚说明 Leet Mentor 的训练闭环，也缺少适合作为搜索入口的公开产品内容。

本次首页要回答三个问题：

1. 学习者为什么不应从随机题单开始？
2. 一次刷题提交后，系统具体如何帮助其改进？
3. 做过的题如何在合适的时间回到学习者面前？

首页的核心承诺为：

> 把刷题变成一套能记住、会调整的训练系统。

公开首页不是登录后工作台的替代品，也不承诺自动替用户完成题目。它展示的是从路线、练习、代码 Review 到间隔复习的产品闭环。

## 2. 叙事主线

全页使用一个一致的演示学习者和路线，避免不同区块突然切换模板、题目或上下文。

```text
LeetCode 面试经典 150 题计划
  -> 按每周 12 小时生成 10 周阶段计划
  -> 今日练习「买卖股票的最佳时机」
  -> 提交 Java 代码，获得 AI Review
  -> 通过间隔复习重新回忆关键模式
  -> 训练信号进入下一次今日训练建议
```

主模板选用 `leetcode_top_interview_150`，原因是它已在模板库、已生成计划、今日工作台和练习页形成完整的真实产品链路。

| 属性 | 演示材料 |
| --- | --- |
| 模板名称 | LeetCode 面试经典 150 题计划 |
| 分类 | 面试备战 |
| 节奏 | 10 周，每周 12 小时 |
| 来源归因 | LeetCode official Study Plan |
| 阶段示例 | 数组与字符串；双指针、窗口与矩阵；二叉树与搜索树；动态规划综合收尾 |
| 练习题 | 121. 买卖股票的最佳时机 |
| 练习语言 | Java |

模板标题、周期、阶段及题目必须从 seed 或后端公开 DTO 导出；不得在首页复制第三方题解、文章正文或把第三方来源包装成合作关系。

## 3. 页面信息架构

### 3.1 公开导航

顶部保持现有 Leet Mentor 品牌、语言与主题切换，但未登录状态的导航改为页内锚点：

```text
训练路线 | AI Review | 间隔复习 | 登录
```

“登录”跳转现有 `/login`。只有在密码注册真实启用时才显示“创建账号”入口；内测关闭注册时不得使用无法完成的“免费开始”承诺。

### 3.2 首屏：今日训练正在发生

首屏标题和正文：

```text
把刷题变成一套能记住、会调整的训练系统
从训练路线开始，在每道题中获得可追问的 AI 辅导，
再通过间隔复习把解题模式留在长期记忆中。
```

首要操作为“开始制定训练计划”，次要操作为“查看训练闭环”。

右侧或背景主视觉使用 `TodayWorkspaceDemo`，借鉴真实今日工作台的信息层级，但全部由 mock 数据渲染：

```text
今日连练 3 题
今日待复习 10 题
学习节奏：提交次数、活跃日、连续天数
学习诊断：当前优势、下一步突破
本周节奏：当前计划、每日训练、剩余题目
```

动效为完成度、今日题包和待复习入口依次出现。首屏不直接播放带声音视频，也不将关键信息只放在动画中。

### 3.3 模板库：从成熟路线开始

标题：`不从空白题单开始。`

辅助文案：`从已整理的训练路线中选择目标，再把周期、语言和每周投入编译成可执行计划。`

演示展示产品现有一级分类：

```text
推荐 | 系统学习 | 面试备战 | 专题突破 | 语言与岗位
```

只展示三张代表卡，避免首页变成模板目录：

| 卡片 | 分类 | 首页展示信息 |
| --- | --- | --- |
| LeetCode 面试经典 150 题计划 | 面试备战 | 150 道题；推荐 10 周；每周 12 小时 |
| 中文系统刷题入门计划 | 系统学习 | 46 道题；推荐 12 周；每周 6 小时 |
| 动态规划专项突破计划 | 专题突破 | 23 道题；推荐 4 周；每周 8 小时 |

卡片可切换，默认高亮主模板。选中后将 `Java / 10 周 / 每周 12h` 写入旁侧“编译计划”面板，并依次生成阶段：数组与字符串、双指针、树、图、动态规划。模板库的完整数量、来源和内容以模板系统为准；页面中数量不得手写成不随 seed 更新的营销数字。

### 3.4 今日练习：计划落到一道题

标题：`今天练什么，为什么练，都很清楚。`

展示主模板第一阶段的题目上下文：

```text
数组与字符串
121. 买卖股票的最佳时机
难度：简单
训练目标：用一次遍历维护历史最低买入价和最大利润
```

动态演示只展示题名、简短问题摘要、样例数据、Java 函数签名和练习状态，不完整复制第三方题面。状态从“开始练习”进入“代码已提交”，使用户理解练习与后续 Review 是同一条链路。

### 3.5 AI Review：提交后得到可执行反馈

标题：`代码提交后，知道下一步该改什么。`

以 `best-time-to-buy-and-sell-stock` 的一个低效初稿作为演示输入：双重循环枚举买卖日，逻辑正确但时间复杂度为 `O(n^2)`。

演示 Review 固定展示真实产品的五个评审维度，而非泛化聊天气泡：

```text
正确性：部分通过
复杂度：需要改进
边界条件：需要改进
代码质量：表现良好
题目要求符合度：表现优秀
```

下面依次展示三段短文本：

```text
代码评审：当前实现能枚举合法买卖日，但数据规模增大时会超时。
主要问题：双重循环的时间复杂度为 O(n^2)。
优化建议：尝试在一次遍历中维护此前最低价格，再更新当前最大利润。
```

动画最后将“未通过 4.8 / 6 分”转为“已通过本次 Review”，并以代码提交记录的版本历史样式呈现。评分只作演示说明，不暗示 AI 编译或在线评测已真实执行。

### 3.6 间隔复习：把做过的题留住

标题：`不是静态错题本，是会在合适时间出现的复习。`

复用同一道“买卖股票的最佳时机”，保持叙事连续。页面应如实匹配当前复习中心的产品模型：完整题面、题目笔记、教练总结、历史记录和固定评级栏，而不是伪装成传统翻卡。

演示状态：

```text
题目：买卖股票的最佳时机
我的题目笔记：维护最低价格；遍历时更新最大利润
教练总结：将每一天作为卖出日，只需保留此前最优买入条件
评级：AGAIN | HARD | GOOD | EASY
结果：GOOD -> 下次复习约 6 天后
```

“约 6 天后”是示意，不得写成固定调度承诺。真实 FSRS 间隔取决于用户的当前状态和评级。这里的对外称呼使用“间隔复习”或“FSRS 驱动的复习节奏”，不以 Anki 品牌作为主文案。

### 3.7 收尾：训练信号回流

标题：`每一次练习，都让下一次更有方向。`

以学习诊断的小型总结收尾：

```text
当前优势：数组
下一步突破：贪心
今日待复习：10 题
下一次训练：优先补一题「贪心」基础练习
```

文案只能承诺当前已有的“学习诊断、待复习和下一步建议”。在计划尚未支持自动重排前，不得声称 Review 会自动改写用户整个训练计划。

## 4. 动态演示实现

第一版不依赖录屏。所有预览均为无后端写入的 React 组件和本地 mock 数据：

```text
PublicHomePage
  ├─ TodayWorkspaceDemo
  ├─ TemplateCatalogDemo
  ├─ PlanCompilerDemo
  ├─ PracticeReviewDemo
  └─ SpacedReviewDemo
```

演示数据集中在 `frontend/src/marketing/demoData.ts`，由单一对象管理模板名、阶段、题目、Review 结果和复习状态，禁止各组件分别硬编码不同版本的故事。

每个组件包含自动循环和用户可点击的状态切换；状态切换只影响本地展示，不发起 API 请求。动效限制为选中态、列表逐项出现、数值渐进和轻微位移，不使用装饰性光球、重型粒子或持续大幅动画。

需要支持：

- `prefers-reduced-motion: reduce` 时停止自动循环并显示最终静态状态；
- 键盘可操作的模板切换与评级演示；
- 窄屏下按单列排列，主演示不出现横向溢出；
- 首屏之外的演示延迟初始化，避免增加首屏脚本和布局成本。

后续可将稳定的真实产品录屏替换某个演示模块，但截图和录屏只能作为媒体素材，不能替代页面标题、正文和可索引的 HTML 内容。

## 5. 视觉与素材边界

- 延续当前产品的浅色工作台、墨黑文字、金黄训练强调色和绿色进度/成功状态；公开首页可更具叙事感，但不复制 LeetReviewer 的品牌、设备框、颜色或文案。
- `.tmp` 中的产品截图仅供设计对照，含水印和账户信息，禁止原样进入构建产物。
- 首页 mock 不展示真实用户名称、进度、代码、对话或 Review 记录。
- 第三方模板只展示允许的标题、分类、节奏和来源归因；题目演示仅展示必要摘要、标签和自写说明，不复制题解。

## 6. SEO 与路由要求

公开首页必须在首次 HTML 中包含可阅读的标题、正文、区块标题和内部链接；动态 demo 是补充，不是正文唯一载体。

第一版交付至少包括：

```text
title：Leet Mentor - AI 算法训练、代码 Review 与间隔复习
description：从训练路线、每日刷题到 AI Review 和间隔复习，帮助算法学习者建立可持续的训练闭环。
canonical：正式域名的 /
Open Graph 标题、描述与产品预览图
```

后续与公开内容页一起补充 `robots.txt`、`sitemap.xml` 和 Search Console 验证。`/api/`、`/admin/`、个人学习数据和参数化工作台 URL 不应进入公开 sitemap。

## 7. 实施顺序与验收

1. 新建公开首页组件、演示数据和样式，不修改登录后工作台。
2. 先完成模板、计划、Review、复习四段演示的静态最终态，再增加自动循环。
3. 接入无障碍、移动端、深浅主题与 SEO 元数据。
4. 运行前端构建和相关交互测试；用桌面与移动视口截图检查文字截断、滚动和动画降级。

验收标准：

- 未登录访问 `/` 能在不请求受保护 API 的前提下理解完整训练闭环；
- 每一段展示的模板、阶段、题目和 Review 语义均与当前产品契约一致；
- 动画关闭后，首页仍完整、可操作且可读；
- 用户点击“开始制定训练计划”能进入真实登录流程；
- 不包含 `.tmp` 截图、水印、真实账户信息、未经授权的第三方正文或误导性合作背书。
