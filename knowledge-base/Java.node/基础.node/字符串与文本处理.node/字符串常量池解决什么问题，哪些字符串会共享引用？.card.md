字符串常量池为相同内容提供一个可复用的 `String` 对象，让重复出现的字符串常量共享对象，减少重复存储。因为 `String` 不可变，共享同一个对象不会产生“某处修改内容，其他地方也跟着变化”的问题。

内容相同的字符串字面量、字符串类型的编译期常量表达式会共享同一个池中对象；内容相同的字符串调用 `intern()`，其返回值也指向同一个池中对象。但 `new String(...)` 会创建新对象，运行时拼接的结果也不会仅因内容相同就自动复用池中引用。

因此，**内容相同不代表引用相同**。`==` 判断是不是同一个对象，比较文本内容应使用 `equals()`，不能把特定来源的共享规则当作通用的内容比较方式。

## 常量池复用的是按内容确定的代表对象

可以把字符串常量池理解为按内容查找代表对象的机制：对于需要驻留的字符串，内容相同就使用同一个代表对象。“驻留”就是让字符串参与这种统一引用的机制，英文称为 interning。

Java 会对字面量和字符串常量表达式的结果自动驻留。例如，同一个程序中多处使用 `"hello"`，即使出现在不同类中，也会引用同一个字符串对象，不需要为每处使用分别保留一份相同内容的对象。

这种共享依赖 `String` 的不可变性：多个引用都只能读取同一份字符内容，任何一方都不能通过普通字符串操作改写它。常量池并不会把程序中所有内容相同的 `String` 对象都自动合并，独立创建的对象仍然可以同时存在。

## 哪些情况会共享，哪些不会

以下比较均以 `String pooled = "ab";` 为基准：

| 字符串的来源 | 示例 | 与 `pooled` 的 `==` 结果 | 原因 |
| --- | --- | --- | --- |
| 相同内容的字面量 | `"ab"` | `true` | 复用同一个池中对象 |
| 编译期常量拼接 | `"a" + "b"` | `true` | 常量表达式的结果自动驻留 |
| 包含常量变量的拼接 | `final String p = "a";` 后使用 `p + "b"` | `true` | `p` 是常量变量，拼接仍是常量表达式 |
| 包含普通变量的拼接 | `String p = "a";` 后使用 `p + "b"` | `false` | 属于运行时拼接，产生新的结果对象 |
| 显式创建对象 | `new String("ab")` | `false` | `new` 创建的对象与池中对象身份不同 |
| 对相同内容调用 `intern()` | `new String("ab").intern()` | `true` | 返回池中代表 `"ab"` 的对象 |

这里“常量变量”有严格条件：必须是以常量表达式初始化的 `final` 基本类型或 `String` 变量。仅有 `final` 不够，例如 `final String p = new String("a");` 中的初始化不是常量表达式，`p + "b"` 也不会因此成为编译期常量。

方法调用也不能作为常量表达式的一部分，即使它实际返回池中的字符串。普通变量即使始终没有被重新赋值，也不会自动成为常量变量。

Java 17 的文本块也会驻留；比较时看的是处理缩进、转义和换行后得到的实际内容，不能仅凭源码看起来相同来判断。

## new 和 intern 为什么会得到不同的引用结果

```java
String pooled = "ab";
String created = new String("ab");
String canonical = created.intern();

System.out.println(created == pooled);       // false
System.out.println(created.equals(pooled));  // true
System.out.println(canonical == pooled);     // true
System.out.println(created == canonical);    // false
```

`new String("ab")` 中的字面量 `"ab"` 已经对应池中对象，但 `new` 仍会创建另一个 `String` 对象。所以 `created` 与 `pooled` 内容相同，引用不同。

这个例子中池里已有 `"ab"`，`intern()` 返回的就是 `pooled` 指向的对象。它不会把 `created` 自动改为这个引用，也不会让已经存在的两个对象变成同一个对象；取得池中统一引用的是接收返回值的 `canonical`。

如果查找时池中没有内容相等的字符串，`intern()` 会把当前字符串加入池，并返回当前对象的引用。所以 `s == s.intern()` 并不总是 `false`，它取决于池中是否已有另一个内容相等的对象；不能仅凭当前代码没出现对应字面量就推断池中不存在它。

## 比较文本时为什么仍应使用 equals

同一段文本可能来自字面量、文件读取、请求参数或运行时拼接。来源变化后，内容可以保持相同，对象身份却不一定相同，因此不能把字面量上的 `==` 结果推广到一般文本比较。

例如，判断变量是否为 `"ab"`，可以写 `"ab".equals(value)`；即使 `value` 为 `null`，也会得到 `false`。无需为了比较内容先调用 `intern()`。
