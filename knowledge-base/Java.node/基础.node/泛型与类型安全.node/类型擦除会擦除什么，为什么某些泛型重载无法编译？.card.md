**类型擦除把参数化类型映射到其非参数化形式，把类型变量映射到最左上界的擦除结果；没有显式上界的 T 通常擦除为 Object。** 例如 `List<String>` 擦除为 List，`T extends Number` 擦除为 Number，并不是所有泛型相关类型都变成 Object。

若两个同名方法的参数列表在擦除后相同，就可能发生签名冲突，不能用不同泛型实参来区分这组重载。擦除也不等于删除所有泛型信息：类文件可保留声明的泛型签名供反射读取，只是普通实例不携带可直接区分其具体类型实参的运行时类身份。

## 擦除规则落到具体声明

```java
class Box<T> {
    T value;
    T get() { return value; }
}

class NumericBox<T extends Number> {
    T value;
    T get() { return value; }
}
```

Box 的 T 在擦除后的字段和方法描述中对应 Object，NumericBox 的 T 对应 Number。编译器先基于泛型执行类型检查，再生成所需的类型转换；必要时还生成桥接方法维持重写关系。

对于 `T extends Number & Comparable<T>`，最左上界是 Number，所以 T 的擦除是 Number。`List<T>` 本身仍擦除为 List，不能把其中 T 的擦除误套到整个容器类型上。

## 只改 List 的元素类型不能重载

下面的两个方法放在同一个类中会编译失败：

```java
void process(java.util.List<String> values) { }
void process(java.util.List<Integer> values) { }
// 擦除后都是 process(List)，发生名称冲突。
```

根据业务可改用不同方法名，或统一成类型安全的泛型算法；如果操作语义不同，不宜为了保留同名而改为 Object 后到处强转。`process(List<String>)` 与 `process(Set<String>)` 则有不同的擦除参数类型，不属于上述冲突。

## 运行时类身份不区分普通实例的类型实参

```java
java.util.List<String> names = new java.util.ArrayList<>();
java.util.List<Integer> scores = new java.util.ArrayList<>();
System.out.println(names.getClass() == scores.getClass()); // true
```

这说明两个对象都是 ArrayList 类的实例，并不意味着它们在源码里具有相同的参数化类型。运行时保留的元素对象仍有自身真实类型，比如 String 或 Integer；被擦除的是相应泛型类型信息，不是把元素变成“没有类型的值”。

## 声明签名仍可能通过反射读取

```java
class Holder {
    java.util.List<String> names;
}
// 放在声明 throws NoSuchFieldException 的方法中：
java.lang.reflect.Field field = Holder.class.getDeclaredField("names");
System.out.println(field.getType());        // interface java.util.List
System.out.println(field.getGenericType()); // java.util.List<java.lang.String>
```

反射读到的是字段声明中的类型信息，不能据此扫描任意 List 对象就恢复它创建时的类型实参。显式携带 `Class<T>` 或声明类型令牌也是另一种额外提供信息的方式，不代表类型擦除失效。
