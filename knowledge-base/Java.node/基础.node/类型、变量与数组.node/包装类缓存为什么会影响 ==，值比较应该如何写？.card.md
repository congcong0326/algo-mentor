**两个包装类型引用之间的 `==` 比较对象身份；缓存可能让数值相同的装箱结果恰好是同一对象，却不会把 `==` 变成数值比较。** 同一种包装类型的可空值比较通常用 `Objects.equals(a, b)`；已确认非空时可用 `equals`，需要数值排序时使用相应比较方法。

缓存范围要区分规范保证与实现选择：Java 17 语言规范对部分常量表达式的装箱规定身份共享，`Integer.valueOf` API 另有缓存契约。超出保证范围时，不应依赖引用是否相同。

## 先看操作数类型，再判断 ==

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);       // true：在规范保证内
System.out.println(a.equals(b));  // true

Integer x = 1000;
Integer y = 1000;
System.out.println(x == y);       // 不应依赖结果，不能把 false 当成跨实现保证
System.out.println(x.equals(y));  // true
System.out.println(x == 1000);    // true：一侧是 int，x 拆箱后比较数值
```

最后一种写法若 `x == null` 就会抛出 `NullPointerException`。两个 `Integer` 引用比较则不会自动拆箱，两个 null 的 `==` 为 true。

## 哪些是保证，哪些只是常见实现

| 层次 | 能依赖的结论 |
| --- | --- |
| JLS 17 装箱规则 | 常量表达式结果为 `boolean`，或 `byte`、`short`、`int`、`long` 的 -128～127，或 `char` 的 0～127 时，同值的两次相应装箱结果 `==` 为 true |
| `Integer.valueOf(int)` API | -128～127 始终缓存；此范围之外也可能缓存。参数是否来自常量表达式不影响这条 API 契约 |
| OpenJDK 的常见实现 | 多种包装类复用小值对象；Integer 缓存上限可因运行配置变化。这些细节不应成为业务正确性的前提 |

不能把某次实验中“128 得到 false”写成 Java 语言保证，也不能推断“所有相同数字的包装对象必然共享引用”。

## equals 也不替你定义跨类型数值相等

```java
Integer i = 1;
Long l = 1L;
System.out.println(i.equals(l));                 // false：包装类型不同
System.out.println(java.util.Objects.equals(i, l)); // false
System.out.println(i.longValue() == l.longValue()); // true：显式统一为 long
```

上述转换适用于这组整数类型。不要为了统一比较而把所有 Number 都转为 `double`，大整数可能损失精度。`Objects.equals(null, null)` 为 true，也需要符合业务的“相等”定义。

浮点包装类还有特定契约：`Double.equals` 将 NaN 与 NaN 视为相等，将正零与负零视为不相等，而基本类型的 `==` 对这两组值恰好相反。比较金额或测量值时，先确定业务需要的数值语义，再选表示和比较方式。
