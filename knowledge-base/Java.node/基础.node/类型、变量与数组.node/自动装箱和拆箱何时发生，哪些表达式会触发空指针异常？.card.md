**装箱是在需要引用类型的位置把基本值转为对应包装类型；拆箱是在需要基本值的位置取出包装对象的值。拆箱对象为 null 时，会抛出 `NullPointerException`。** 赋值、参数传递、返回值和表达式求值都可能触发转换，不能只检查显式的 `int n = boxed`。

例如 `Integer n = 1` 会装箱；`int value = n`、`n + 1`、`n < 10`、`n == 1` 会拆箱。`Boolean` 用于 `if` 条件，以及部分数值条件表达式，也会隐式拆箱。

## 从语法看到隐含的方法调用

```java
Integer boxed = 10;           // 可理解为 Integer.valueOf(10)
int value = boxed;           // 可理解为 boxed.intValue()
java.util.List<Integer> scores = new java.util.ArrayList<>();
scores.add(95);               // 实参装箱
int first = scores.get(0);    // 返回的 Integer 拆箱
```

这是理解 javac 常见编译结果的方式。装箱不保证每次分配新对象，包装类缓存可能复用实例。

## 容易漏掉的 null 拆箱位置

以下各行是独立反例；依次执行时，第一处异常就会中断后续代码。

```java
Integer count = null;
Boolean enabled = null;

int a = count;          // NPE：赋值拆箱
int b = count + 1;      // NPE：算术运算拆箱
boolean c = count > 0;  // NPE：关系比较拆箱
boolean d = count == 0; // NPE：与基本类型比较
count++;               // NPE：先拆箱，再运算并装箱
if (enabled) { }        // NPE：需要 boolean
```

`count == null` 是引用比较，不拆箱；`count == anotherInteger` 在双方静态类型均为 Integer 时也是引用比较，但通常不是想要的值比较。

## 条件表达式的目标类型不能阻止中间拆箱

```java
static Integer choose(boolean useCount, Integer count) {
    return useCount ? count : 0;
}

// choose(true, null) 抛出 NPE，即使方法返回 Integer。
```

这里两个分支分别是 `Integer` 与 `int`，数值条件表达式的类型为 `int`。选择 `count` 分支时先拆箱，表达式求值结束后才可能为返回值装箱。改成 `Object result = useCount ? count : 0` 也不能绕过这一步。

如果需要保留 null，可显式写成控制流；若缺失应使用默认值，则先做缺失判断：

```java
static Integer chooseNullable(boolean useCount, Integer count) {
    if (useCount) {
        return count;
    }
    return 0;
}

static int countOrZero(Integer count) {
    return count == null ? 0 : count; // 被选中的 count 分支已保证非 null
}
```

不应总结成“所有三元表达式都会拆箱”：分支类型决定条件表达式规则，例如两个分支都为 Integer 时不会仅因条件选择就强制拆箱。

## 把缺失处理放在计算入口

对于可空 DTO 字段，先验证必填、补业务默认值或保留缺失状态，再进入基本类型计算。可空开关需要将 null 解释为关闭时，可写 `Boolean.TRUE.equals(enabled)`；若 null 代表配置错误，则应显式报错。
