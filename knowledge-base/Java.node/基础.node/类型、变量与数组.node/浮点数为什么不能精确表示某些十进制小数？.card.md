**`float` 和 `double` 使用有限位宽的二进制浮点格式；有些有限十进制小数转成二进制后会无限循环，只能保存舍入后的近似值。** 随后的运算也可能发生舍入，所以十进制算式看起来应相等的结果，在浮点计算中可能不同。

不是所有小数都有误差：`0.5`、`0.25` 等能够表示成有限二进制小数，并且在相应类型的精度与范围内，可以精确表示。把 `float` 换成 `double` 能提高精度，但不能让 `0.2` 这样的数变成精确二进制值。

## 0.2 为什么会循环

将小数部分不断乘 2，取每一步的整数位，从上到下排列：

```text
0.2 × 2 = 0.4 → 0
0.4 × 2 = 0.8 → 0
0.8 × 2 = 1.6 → 1
0.6 × 2 = 1.2 → 1
0.2 × 2 = 0.4 → 0（回到开头）
```

因此十进制 `0.2` 的二进制小数是 `0.00110011…`，需要无限位，而浮点格式只能保存有限位。相反，十进制 `0.5` 对应二进制 `0.1`，`0.25` 对应 `0.01`，不需要无限展开。

## 原文的运算反例

以下片段在方法中执行；指定 Locale 只是为了让输出使用小数点：

```java
float a = 2.0f - 1.9f;
float b = 1.8f - 1.7f;
System.out.printf(java.util.Locale.ROOT, "%.9f%n", a); // 0.100000024
System.out.println(b);                             // 0.099999905
System.out.println(a == b);                        // false
```

按十进制精确计算，两次减法都应得到 `0.1`。实际参与运算的却是这些字面量的二进制近似值，再经过浮点减法，得到两个不同结果。

输出时减少小数位只能改变显示形式，不能证明底层值已经精确。需要精确十进制运算的业务，可以选择 BigDecimal 并明确构造方式及舍入规则；它也不是“所有运算永远无需舍入”的类型。
