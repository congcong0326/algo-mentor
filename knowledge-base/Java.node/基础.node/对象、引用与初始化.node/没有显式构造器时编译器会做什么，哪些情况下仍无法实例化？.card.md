**普通类完全没有声明构造器时，编译器才会隐式声明默认构造器；一旦声明任意构造器，就不会再自动补一个无参构造器。** 对普通顶层类，默认构造器具有与类相同的访问级别，并隐式调用 `super()`，Object 本身除外。

默认构造器不保证类能实例化：父类无参构造器可能不存在或不可访问；父类构造调用可能涉及受检异常；类可能是抽象类，或者调用位置没有访问权限。需要先区分“类本身无法编译”和“类能编译，但某处不能 new”。

## 有参构造器会阻止自动补无参版本

```java
class Empty { }                 // 隐式声明 Empty() { super(); }

class Problem {
    final String title;
    Problem(String title) { this.title = title; }
}

// new Empty();   // 在可访问的位置合法
// new Problem(); // 编译错误：没有无参构造器
```

“无参构造器”描述参数列表；“默认构造器”特指编译器隐式声明的构造器。手写 `Problem() { ... }` 是无参构造器，但不是这个规范意义上的默认构造器。

## 父类没有可用的无参构造器

以下是预期不能编译的反例：

```java
class Parent {
    Parent(int value) { }
}
class Child extends Parent { }
// Child 的隐式 super() 找不到 Parent()。
```

应显式建立合法构造链：

```java
class Child extends Parent {
    Child() { super(1); }
}
```

父类无参构造器为 private 且对子类不可访问时，同样不能靠自动生成解决。如果父类无参构造器声明受检异常，子类也可能需要显式构造器声明该异常；默认构造器自身没有 throws 子句。

## 编译通过仍不代表可以随处实例化

- 抽象类可以有默认构造器供子类调用，但 `new 抽象类()` 不合法。
- 包访问级别的类及构造器不能直接从其他包访问。public 类也可以显式声明 private 构造器来限制外部构造。
- 非静态内部类的创建还依赖外围实例，不能直接套用顶层类的创建方式。
- 构造器或初始化代码本身还可能抛出异常，编译成功不等于运行时构造必然成功。

这里讨论普通类；record 的规范构造器、枚举和匿名类有各自规则，不宜把“无构造器就补 public 无参构造器”套到所有类型上。
