**创建子类对象时，先完成必要的类初始化，再完成新对象的实例初始化和构造过程。** 以 Java 17 中普通父子类为例，首次执行 `new Child()`，如果父子类都尚未初始化，先执行父类静态初始化，再执行子类静态初始化。创建对象时，所有实例字段先获得默认值，再完成父类的实例字段初始化与初始化块、构造器剩余代码，之后才轮到子类的这些步骤。

同一个类里，字段初始化表达式和对应的初始化块按源码中的先后顺序执行，不是固定“字段先、块后”。类成功初始化后，再次 `new Child()` 不会重复静态初始化，但新对象仍要完整执行实例初始化和构造过程。

## 三种初始化代码分别负责什么

| 代码形式 | 作用 | 什么时候执行 |
| --- | --- | --- |
| `static int count = ...;`、`static { ... }` | 设置类共享的静态状态 | 类初始化时执行，成功后不因再次创建对象而重跑 |
| `int count = ...;`、`{ ... }` | 设置每个对象自己的初始状态 | 每次创建新对象时执行 |
| `Child(...) { ... }` | 调用其他构造器，并根据构造参数完成初始化 | 创建对象时，沿构造链执行被调用的构造器 |

这里的“字段初始化”指执行源码中的赋值表达式，例如 `int count = 10` 中的 `= 10`。在它执行之前，实例字段已经有默认值：整数是 `0`、布尔值是 `false`、引用是 `null`。

## 第一次与第二次 new，有什么不同

下面的 `mark` 只做两件事：打印标签，然后返回 `1`。把它放进字段初始化表达式，就能观察字段何时被赋值。代码可保存为 `InitDemo.java`：

```java
public class InitDemo {
    static int mark(String text) {
        System.out.println(text);
        return 1;
    }

    static class Parent {
        static int parentShared = mark("父静态字段");
        static { mark("父静态块"); }
        int parentValue = mark("父实例字段");
        { mark("父实例块"); }
        Parent() { mark("父构造器剩余代码"); }
    }

    static class Child extends Parent {
        static int childShared = mark("子静态字段");
        static { mark("子静态块"); }
        int childValue = mark("子实例字段");
        { mark("子实例块"); }
        Child() { mark("子构造器剩余代码"); }
    }

    public static void main(String[] args) {
        new Child();
        System.out.println("再次创建");
        new Child();
    }
}
```

第一次创建的输出分为两段：

```text
父静态字段
父静态块
子静态字段
子静态块

父实例字段
父实例块
父构造器剩余代码
子实例字段
子实例块
子构造器剩余代码
```

空行仅用于区分两个阶段，不是程序输出。在这两个阶段之间，新对象的全部实例字段先获得默认值，只是示例没有打印这个过程。

第二次创建时，父子类已经初始化成功，只重复对象初始化的部分：

```text
父实例字段
父实例块
父构造器剩余代码
子实例字段
子实例块
子构造器剩余代码
```

这里不是先执行所有父子类的实例初始化块，再执行所有构造器。**父类先完成自己的实例初始化和构造器剩余代码，子类才开始执行自己的字段初始化表达式与初始化块。**

## 为什么构造器里的打印在实例初始化块后面

上例没有写出 `super()`，但 Java 17 会在这两个构造器开头隐式补上它。因此，进入 `Child()` 后，先调用 `Parent()`；`Parent()` 又先调用 `Object()`。

`Object()` 返回后，才执行 `Parent` 的实例字段初始化表达式和实例初始化块，然后继续执行 `Parent()` 中的打印。`Parent()` 返回后，轮到 `Child` 的实例字段初始化表达式、实例初始化块，最后才执行 `Child()` 中的打印。

因此，不能把顺序理解为“实例初始化块执行完，才调用构造器”。**构造器已经进入了，只是它要先完成父类构造调用和本类实例初始化，才能执行后面的代码。**

如果通过 `this(...)` 调用同类另一个构造器，本类的实例字段初始化表达式和初始化块也只执行一次，不会随着同类构造器的调用次数重复执行。

## 同一个类里，字段和初始化块按什么顺序执行

静态字段初始化表达式与静态块是一组，实例字段初始化表达式与实例块是另一组；各自在所属阶段按源码顺序执行。例如：

```java
int value = 1;
{ value = 2; }
```

实例字段先被设成 `1`，随后被初始化块改成 `2`。如果构造器剩余代码再执行 `value = 3`，最终值就是 `3`。如果一个类中交错写了多个字段和初始化块，也按它们出现的顺序执行，而不是先集中执行所有字段赋值。

## 父类构造器能否读到子类字段的初始值

在上例的顺序中，父类构造器执行时，子类字段已经有默认值，但还没执行子类的显式赋值。此时如果父类构造器调用了被子类重写的方法，就可能读到这个默认值：

```java
class Base {
    Base() { show(); }
    void show() { }
}
class Derived extends Base {
    int answer = 42;
    @Override void show() { System.out.println(answer); }
}
// new Derived() 打印 0，而不是 42。
```

`Base()` 中的 `show()` 仍然会调用子类实现，但此时 `answer = 42` 尚未执行，所以打印 `0`。等父类构造器返回后，`answer` 才被设为 `42`。因此，构造器中应避免调用依赖子类初始化状态的可重写方法。

## 静态初始化也可能早于第一次 new

`new` 只是类初始化的触发方式之一。调用类声明的静态方法，或者读取、写入它声明的非常量静态字段，也会触发初始化。如果此前已经通过这些操作完成类初始化，第一次 `new` 时就不会再执行静态部分。

读取编译期常量不会因此触发声明类的初始化；通过子类名访问继承来的静态字段，初始化的是实际声明该字段的类，不会仅因此初始化子类。

上面的完整输出以没有其他初始化依赖、所有步骤正常完成为前提。初始化代码如果又触发其他类初始化，会插入相应执行过程；如果抛出异常，后续步骤也不会照常完成。
