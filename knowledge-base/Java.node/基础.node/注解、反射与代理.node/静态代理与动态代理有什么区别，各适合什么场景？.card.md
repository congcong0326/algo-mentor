**两种代理都让调用方先调用代理对象，由代理决定如何处理这次调用。** 静态代理的代理类在运行前就已写好或生成，转发逻辑写在具体方法中；动态代理在运行时根据接口或类创建代理类型，把方法调用交给统一的处理器或拦截器。区别在代理类何时产生、调用逻辑如何复用，不在于代理是否一定持有目标对象。

接口少、每个方法的附加行为不同且希望调用过程直观时，静态代理容易控制；多个类型都要应用相同的日志、权限、事务等规则时，动态代理可减少重复包装代码。选择动态代理还要看代理技术的边界：JDK 动态代理基于接口，基于子类的代理受不可重写方法等限制。

## 静态代理怎样转发调用

```java
interface ProblemService {
    void submit(String problemId);
}

class LoggingProblemService implements ProblemService {
    private final ProblemService target;

    LoggingProblemService(ProblemService target) {
        this.target = target;
    }

    @Override
    public void submit(String problemId) {
        System.out.println("提交题目：" + problemId);
        target.submit(problemId);
    }
}
```

调用方持有 `LoggingProblemService`，它在 `submit` 中增加日志，再显式调用目标对象。新增接口方法时，代理类通常也要补充对应实现；如果不同服务都需要相同日志逻辑，手写代理容易重复。

## 动态代理在框架里做什么

| 场景 | 代理收到调用后做什么 | 是否必须有现成的目标对象 |
| --- | --- | --- |
| Spring AOP 的常见代理模式 | 例如拦截经代理进入的 `@Transactional` 方法，按事务属性处理事务，再调用目标 Bean | 通常有目标 Bean |
| MyBatis Mapper 接口 | 根据被调用的 Mapper 方法找到映射语句，执行 SQL 并转换结果 | 不需要手写 Mapper 实现对象 |

Spring 可根据条件使用 JDK 接口代理或基于类的代理；MyBatis Mapper 常通过 JDK 动态代理提供接口实现。动态代理并不等于每次都用 `Method.invoke` 调目标：处理器可以转发给目标，也可以像 Mapper 那样把方法调用转成另一种操作。

无论哪种代理，附加逻辑通常只作用于**经代理对象进入**的调用。目标对象内部通过 `this` 直接调用自身方法时，不会重新经过外层代理；这也是排查 Spring 常见代理模式下事务未生效时要检查的调用路径。
