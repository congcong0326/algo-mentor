**封装是让对象通过自己提供的操作维护状态约束，并控制外部代码能依赖哪些细节。** 通常把字段和实现用的辅助方法设为 `private`，只公开能够保持对象合法状态的操作；包内协作才考虑包访问权限，确实要给子类扩展时才暴露 `protected` 成员。访问权限应随所需的调用范围扩大，而不是默认全部 `public`。

仅把字段改成 `private` 还不够：如果公开任意赋值的 setter，或把内部可变对象直接返回，调用者仍可破坏对象约束。封装的关键是设计允许发生的状态变化，而非机械地生成 getter、setter。

## 用操作维护跨字段约束

假设练习进度要求目标题数大于零，且已完成题数始终在 `0` 到目标题数之间。如果分别开放 `setTarget` 和 `setSolved`，调用者可以把目标改得小于已完成题数。让对象提供有业务含义的操作，约束就能在每次状态变化时检查：

```java
public final class PracticeProgress {
    private int target;
    private int solved;

    public PracticeProgress(int target) {
        if (target <= 0) {
            throw new IllegalArgumentException("目标题数必须为正");
        }
        this.target = target;
    }

    public void changeTarget(int newTarget) {
        if (newTarget <= 0 || newTarget < solved) {
            throw new IllegalArgumentException("目标题数不能小于已完成题数");
        }
        target = newTarget;
    }

    public void recordSolved() {
        if (solved == target) {
            throw new IllegalStateException("已达到目标题数");
        }
        solved++;
    }

    public int remaining() {
        return target - solved;
    }
}
```

构造器建立初始约束，两个修改方法分别检查各自可能破坏的条件。`remaining()` 提供调用方真正需要的结果，无须暴露可写字段。这里把类设为 `final`，是为了让示例中的状态转换规则不被子类改写；需要扩展点的类型则应明确设计哪些行为允许子类改变。

## 访问级别如何服务接口边界

| 级别 | 主要可访问范围 | 常见选择 |
| --- | --- | --- |
| `private` | 声明类型及 Java 允许的嵌套上下文 | 内部状态、实现细节、辅助方法；优先从这里开始 |
| 不写修饰符（包访问） | 同一个包 | 同包类型之间确有协作需求，但不希望形成公开 API |
| `protected` | 同包代码，以及满足访问规则的跨包子类 | 有意向子类承诺的扩展点；它并非“仅子类可见” |
| `public` | 能访问声明类型的代码；命名模块还受导出规则限制 | 调用者需要依赖的稳定能力 |

访问级别控制的是 **Java 代码从哪里可以使用成员**，不会替对象校验业务输入。`public` 方法也可以严格检查参数；`private` 字段若被宽松的公开方法任意修改，仍无法维持约束。尤其是多个字段必须一起变化时，应提供一次完成并校验整个转换的操作，而不是让调用者按正确顺序调用多个 setter。

返回内部集合、数组等可变对象时，还要考虑调用者通过返回值绕过这些操作。可按需要返回快照；只读视图虽禁止通过视图修改，底层集合若在别处变化，视图仍可能随之变化。若元素本身可变，还需判断是否存在共享修改入口。对象的不可变性与 `final` 的边界见关联卡片。
