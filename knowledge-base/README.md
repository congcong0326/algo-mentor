# 知识库维护手册

本目录是 algo-mentor 共享知识库的唯一正式内容源。维护者编辑目录与 Markdown，再执行导入。一个文件是一张卡片或一篇文章；大纲由目录构成。

## 1. 目录与文件

```text
knowledge-base/
├── AGENTS.md
├── README.md
├── skills/
│   └── card-writing/
│       └── SKILL.md
├── references/
│   └── 原始参考资料.md
└── Java.node/
    ├── AGENTS.md
    ├── 基础.node/
    │   ├── Java为什么只有值传递.card.md
    │   └── 对象与引用.article.md
    └── 集合.node/
        └── HashMap.node/
            └── HashMap如何处理哈希冲突.card.md
```

- 从本目录开始，只递归进入名称以 `.node` 结尾的目录。节点标题为目录名去掉 `.node`。
- `.node` 内的 `.card.md` 是卡片，`.article.md` 是文章；文件名去掉后缀就是问题或文章标题。
- 正式文件路径中的目录必须连续使用 `.node`，不支持穿过普通目录后继续找节点。
- 其他目录整个子树不扫描，其他文件忽略。例如 `skills/示例.node/示例.card.md` 也不会导入。
- 根目录不直接存放卡片或文章；`AGENTS.md`、`README.md` 等维护文件可以放在根目录或节点内。
- 后缀区分大小写，正式内容不支持符号链接。去掉后缀就会退出导入范围。
- 节点、文章按文件名称的确定性顺序显示；卡片先按 `order`，同值按问题标题和 slug 排序。

运行时不需要 `_node.yaml`、节点稳定键或额外标题字段。`outline.json` 是可选编辑清单，帮助生成和检查目录，本身不导入。现有仓库 `knowledge/` 个人笔记不会自动导入。

### 大纲维护流程

标题直接使用主题名称，默认不加编号。每个管理大纲的主题只维护一份 README，集中说明范围与 GitHub 固定版本来源；空叶子用 `.gitkeep` 保留在 Git 中。标题中的 `/`、`\`、控制字符和首尾空白会被工具拒绝，例如 `I/O` 应明确写成 `IO` 后再生成。

在已创建的主题 `.node` 目录内维护 `outline.json`，管理该主题的全部后代节点：

```json
{
  "version": 1,
  "children": [
    {"title": "对象与引用", "children": [{"title": "值传递"}]},
    {"title": "异常与资源管理"}
  ]
}
```

先预览再生成；预览不写文件，生成只补建目录，不生成卡片或文章：

```sh
make knowledge-outline-preview KNOWLEDGE_OUTLINE=knowledge-base/Java.node/基础.node/outline.json
make knowledge-outline-apply KNOWLEDGE_OUTLINE=knowledge-base/Java.node/基础.node/outline.json
make knowledge-outline-check
```

预览显示缺少与清单外的完整节点路径。生成前会拒绝非法标题、重复同级节点、符号链接和清单外节点。改名、移动、删除由维护者结合已有内容显式处理，并保留卡片 slug；不能用自动补建代替内容迁移。清单中的数组顺序不控制页面排序，页面仍按目录名排序。

检查会诊断正式 `.node` 内被普通目录隔断的知识内容；根级普通目录继续忽略，正式节点内的 `references/`、`skills/` 也可用于明确存放不导入的参考资料。普通目录不会因此被自动纳入导入范围。直接调用 Java JAR 不读取编辑清单，日常维护请使用 Make 入口。

## 2. 一张卡片的结构

````markdown
---
slug: java-pass-by-value
tags: [Java基础, 对象与引用]
order: 10
relations:
  related: [hashmap-collision]
---

Java 传递的是实参值的副本。对象参数复制的是引用值。

## 原理解释

这里解释原因……

## 示例

```java
// 示例代码
```

## 容易混淆的地方

正文可以自由组织。
````

解析分为三部分：

1. 文件第一行开始的一对 `---` 包围 YAML 元数据。
2. 元数据后至第一个**顶层二级标题**之前为核心回答，不能为空，最多 20000 字符。
3. 从第一个顶层二级标题至文件结尾是详细解释，可省略；标题、段落、代码、表格等保持 Markdown，不拆更多字段。

建议二级标题写成 `## 标题`；标准 Markdown 的 Setext 二级标题也算分界。代码块、引用、列表内部的标题不算顶层分界。正文保留代码缩进、行尾空格与硬换行，不根据章节名称解析业务字段。

最小卡片仅需：

```markdown
---
slug: unique-card-slug
---

直接回答问题。
```

问题来自文件名，不重复写入元数据或一级标题。一张卡应围绕一个能独立评价“会不会”的问题。

## 3. 元数据

| 字段 | 默认值 | 约定 |
| --- | --- | --- |
| `slug` | 必填 | 全库唯一，含草稿；小写字母、数字以单连字符连接，最长 160 字符 |
| `tags` | 空列表 | 非空字符串列表，不重复，用于标签显示与当前节点内搜索 |
| `status` | `published` | 只支持 `published`、`draft`；草稿进入数据库但不对普通用户展示 |
| `order` | `0` | 非负整数，小值优先；建议 10、20、30 留出插入空间 |
| `relations` | 空对象 | 按下表保存目标卡片 slug 列表 |

目前只接受这些字段，拼错字段或重复 YAML 键会报错。后续增加结构化字段时同步扩展解析器、类型和本手册，不会静默丢弃元数据。

| 关系键 | 含义 |
| --- | --- |
| `prerequisites` | 当前卡片的前置知识 |
| `followups` | 当前卡片之后的追问 |
| `contrasts` | 对比、辨析对象 |
| `related` | 一般关联 |

每种关系可省略；列表顺序决定展示顺序。同一关系内不能重复，不能引用自身，目标必须在完整导入目录中存在。前置关系不能成环；其他关系允许相互引用。不自动生成反向关系，不要求双边文件同步维护。同一目标可以出现在不同关系类型中。

草稿目标可以被引用，但用户界面隐藏指向草稿的关系。引用使用 slug，与文件名和所在目录无关。

## 4. 文章

文章是普通 Markdown，无需 YAML 元数据或稳定 slug。标题取文件名，正文全部保存并渲染。文章可以有任意章节，不进入复习队列。一个节点可以没有文章或有多篇文章。

卡片和文章复用现有 Markdown 阅读组件，支持安全渲染的列表、代码和表格等。使用外部可访问的图片/资料 URL；本地资源上传、相对文档链接转换和 Mermaid 图形渲染不在本次范围，不要依赖本地路径在网页中可访问。维护文档自己的相对链接不受影响。

## 5. 日常操作

从仓库根目录运行：

```sh
make knowledge-validate
make knowledge-import
```

也可以直接在本目录执行一键脚本：

```sh
cd knowledge-base
./import.sh
```

`./import.sh` 会自动定位仓库根目录，并把当前 `knowledge-base` 作为完整快照传给 `make knowledge-import`。只想检查格式而不写数据库时执行 `./import.sh --validate-only`；需要强制重建导入工具时执行 `./import.sh --force-rebuild`。脚本导入成功后会尽量输出卡片状态统计；如果存在 `DRAFT` 卡片，它们已进入数据库，但普通知识库页面默认只展示 `PUBLISHED` 内容。

命令先检查编辑清单与目录，再准备 Java 制品并执行一次性 CLI；不会启动 Vite、Web API 或后台 worker。`knowledge-validate` 只读内容目录，不连接数据库。`knowledge-import` 先完成相同校验，再执行 Flyway 迁移和事务导入，完成后退出。

首次使用或后端源码、资源、POM、Maven 项目配置、构建命令、Java 版本、成品 JAR 变化时重建；仅修改知识库内容时复用已核验的 JAR。缓存位于 `.cache/knowledge-cli/`。需要强制刷新外部依赖或外部 Maven 配置时执行 `make knowledge-cli-rebuild`；不需要手动寻找 JAR 或跳过构建依赖。流程工具的回归检查为 `make knowledge-tools-test`。

`knowledge-outline-preview` 只比较文件目录与编辑清单，不查询数据库。导入仍是全量替换；全库只有目录、没有任何卡片或文章的快照仍会被 Java 导入器拒绝，单个空节点可以随含内容的全库快照导入。

默认路径为 `knowledge-base`，可用 `KNOWLEDGE_DIR=/完整目录` 指定另一份完整快照。此参数不是增量导入范围：指定目录会替换整个共享知识库。

数据库连接沿用根 Makefile 的 `.env` 与 `POSTGRES_HOST/PORT/DB/USER/PASSWORD` 环境配置。不要在内容文件里保存数据库配置。

推荐维护动作：

- 新建卡片：选节点目录，写中文问题文件名，维护者生成新 slug，写核心回答和必要详情。
- 改标题、改正文、移动文件：保留 slug，执行校验和导入。
- 改大纲：直接改名或移动 `.node` 目录，后代文件和 slug 不变。
- 草稿：设置 `status: draft`，写好后改为 `published`。
- 下线：删除正式文件，或移到普通维护目录。还在引用它的关系需一并修正，否则导入失败。
- 恢复：重新放回同 slug 卡片即可恢复历史关联；旧 slug 不得复用于不同问题。

导入结果报告节点、卡片、文章数量及移除的卡片 slug。重复 slug、无效格式、空核心回答、断裂关系、循环前置关系、错误路径或空快照都会在写入前失败。

## 6. 数据与幂等

每次导入在一个事务中删除并重建共享大纲、卡片、文章和关系。失败完整回滚；同一时刻只允许一个导入事务。

卡片数据库自增 ID 可以变化，长期引用统一使用 slug。用户复习状态使用 `(user_id, card_slug)`，复习流水引用用户状态，日常导入不删除它们。内容移除后保留历史但不进入复习队列，同 slug 恢复后重新关联。重复导入保证内容和身份的业务结果一致，不保证自增 ID 或技术导入时间不变。

本次开发期 V76 迁移会一次性重建旧知识表并清除旧测试复习数据，这是当前开发阶段的明确约定；此后普通导入不重置复习记录。

回退内容时恢复旧 Git 版本并重新导入即可；这不会回退用户已经发生的复习行为。大纲与文章的数字 ID 仅在当前快照内有效，不能作为永久外链。

## 7. 示例审查路径

导入后自行执行 `make up`，进入“知识库”：

1. Java → 基础 → 对象、引用与初始化 → 引用、值传递与对象共享：查看值传递卡片，点击“显示答案”，检查核心回答、详情标题、代码和标签。
2. 在同一节点打开“对象与引用”文章，检查独立阅读入口。
3. 在卡片的“相关卡片”中跳到 HashMap 卡片，检查 slug 关系跳转。
4. Java → 集合 → HashMap：检查嵌套节点及“前置知识”“相关卡片”两种关系。
5. 评价一张卡，重复执行导入，再确认复习中心仍保留它。
6. 展开 Java → 基础，检查 14 个章节及其子主题；尚未补充内容的叶子显示“暂无内容”。Java → 集合 → HashMap 保留原有示例，不包含 skills、references、README 或 AGENTS。

当前两张 demo 卡片和一篇文章只用于验证组织和展示机制。Java 基础已建立 14 章大纲，范围与参考来源见 [Java 基础维护说明](Java.node/基础.node/README.md)，后续再补充内容。
